# Принципы продукта и совместимость

## Совместимость разделена по данным

Старая выпущенная версия Tweaker содержит только Skin Changer.
**LegacyDataConverter обязателен**; любое изменение формата скинов должно
сохранять перенос из legacy-формата, который он читает. Новый формат нельзя
обосновывать общим «проект ещё не выпущен, миграций нет». BinaryFormatter
остаётся изолированным в отдельном net481-процессе.

**Скрипты и скайбоксы не выпущены:** breaking changes API и форматов в этих
областях не требуют обратной совместимости. Это не освобождает от обновления
документации, генерации, поставляемых примеров и тестов в одном изменении.

## Lua и устройство игры

- Давай скрипту общие возможности (хранилище, JSON, доступные операции), а не
  функции специально для одного модуля. Состав вкладки, reset-кнопки и значения
  по умолчанию решает сам скрипт. Плагин не навязывает ему UI и автоперсист.
- Система Lua — модуль плагина. Хост получает изменения состояния, а не
  непрерывный покадровый поток внутреннего состояния скриптов.
- Порядок скриптов задаёт только пользователь (`order=` и drag-and-drop).
  Не добавляй авторские `@after`/приоритеты. Зависимые части автор объединяет
  в один проект либо документирует нужный порядок.
- Числа игровых механик проверяй графом/бинарём. Записывай команду, результат,
  адрес/RVA или группу/индекс. Описание поведения — отправная точка для
  исследования; неподтверждённое число не превращается в факт из-за источника.
- Предпочитай возможности каналов Quest3D общим D3D/dinput/Win32-хукам:
  общие точки делятся со Steam/OBS и другими оверлеями. ABI, поколения групп,
  ICF и побочные эффекты getters требуют проверки, не угадывания по имени типа.
- PuzzlePRO HUD — передовой мод: допустимо поднять его `@api` и расширить API
  плагина вместо обходного решения внутри скрипта. Это политика разработки
  плагина, не разрешение обещать пользователю AgentKit ещё несуществующий API.
- Loretta важнее Native AOT: если AOT недоступен, используй предусмотренный
  single-file fallback, а не самописный парсер. Не устанавливай failed bundle.

## UI и данные приложения

Поведение виджета должно быть обычным и предсказуемым. Если особый жест нужен
только ради компенсации дорогой записи/работы backend, исправлять нужно
причину в backend; не усложняй UI вокруг неё. Стилевой дрейф не считать
замыслом. Общие карточки/шаблоны и строительные блоки не копируй по вкладкам.

В Avalonia общие стили/шаблоны находятся в `SharedStyles.axaml` и
`SharedControlTemplates.axaml`; модульные стили задают собственное и модификаторы.
Перед работой с шаблонами, клавиатурой, Bitmap/SKBitmap прочитай профильные
разделы `avalonia-pitfalls` через [карту](documentation-map.md). Коротко:
CrossfadeBrushTransition вместо стандартного BrushTransition; Bitmap освобождается
явно, но после ухода из visual tree; WriteableBitmap вместо лишней копии из
IntPtr; большие JSON/zip не проводить через лишнюю строку/MemoryStream.
Для списка скинов — ReadName, для превью — ReadPreviews; полная Decompile нужна
установке и экспорту, а не отображению списка.

В оверлее используй `ui/widgets` и нижний `ui/kit`: общие метрики темы, anim,
interact и paint. Не создавай вне kit собственные tween, ButtonBehavior или
копии рецептов. Рамки и отступы — из темы. Снимки до/после проверяют результат,
но не заменяют чтение правил и просмотр изменённых областей.

## Документация как проверяемое описание

Журналы реверса хранят первичные доказательства. Публичные `Docs/internals/`
производны от них: находка, меняющая утверждение мануала, обновляет его в том
же изменении. Запускай указанные в мануале команды проверки CgrPy.

Публичные scripting/skyboxes manuals на английском и предназначены авторам
материалов. Их ссылки за пределы публичной поставки — GitHub-ссылки; ссылка
внутрь `Docs/Internal` или `Tools` не должна ломаться в `DevTools/Docs`.
`Docs/AgentWorkflow` относится к разработке репозитория, не к публичной поставке.

Developer Bundle — постоянная сайд-задача обновления AgentKit/CgrPy под знания
об игре и Lua API. Она не создаёт глобальный барьер завершения остальных работ.
Личный KnownBugs не используется как реестр этой задачи.
