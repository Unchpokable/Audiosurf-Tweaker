# Формат `.sky` — сменный пакет неба

Единица распространения и единый источник правды для одного неба: слои, их шейдеры и ассеты, все
параметры и связи между ними.

Заменяет собой схему «конфигурация живёт в комментарии внутри HLSL» (`@sky`, см.
`skybox-procedural.md`). Та схема была правильной ровно до тех пор, пока небо было **одним**
пиксельным шейдером. Как только появился второй слой, стало нужно связывать конфигурацию одного
шейдера с другим — и связывать оказалось нечем, кроме цепочки переходников.

## Почему пришлось менять

Не «стало некрасиво», а два конкретных симптома.

**Две несвязанные системы параметров в одной фиче.** У неба — блок `@sky`, резолв через CTAB,
панель, ключи `param.*` в настройках. У спрайтового слоя — типизированные аксессоры в
`skybox_config`, руками написанные ползунки, руками написанные ключи. Обоснование («спрайтовый
шейдер вшит в DLL, его никто не редактирует») верно ровно до Ф5, где меш с материалом приезжает с
диска.

**«Где солнце» существовало в четырёх представлениях подряд**: комментарий в HLSL → текстовый
парсер → индекс регистра из CTAB → массив констант → направление → пуш в чужой модуль → загрузка в
регистры второго шейдера. Каждое звено защитимо по отдельности; цепочка целиком — костыль.

Побочная выгода, которой не ждали: механизм `version =` существует **только** потому, что
сохранённые значения ключуются номером регистра — это правильно при переименовании и неправильно
при переписывании. Параметры, именованные в манифесте, снимают проблему вместе с механизмом.

## Две формы одного пакета

| форма | что это | для чего |
|---|---|---|
| **каталог** `OurDraftsCollides.sky/` | распакованные файлы | **разработка** |
| **архив** `OurDraftsCollides.sky` | тот же каталог в zip | распространение |

Обе грузятся одним загрузчиком через один манифест. Это не компромисс, а условие, без которого
затея вредна: цикл «сохранил `.hlsl`, альт-табнул, увидел» — причина, по которой шейдерная работа
шла быстро, и перепаковка архива ради одного символа его убивает. В форме каталога загрузчик следит
за временем модификации манифеста и **каждого файла, на который манифест ссылается**.

Каталог реализуется первым, архив вторым.

```
OurDraftsCollides.sky/
├── Config.json      обязателен, всё остальное на усмотрение автора
├── shaders/
│   ├── odc.ps.hlsl
│   └── clouds.ps.hlsl
└── textures/
```

## Config.json

JSON с комментариями и висячими запятыми (флаги чтения yyjson). Комментарии разрешены намеренно:
автор неба обязательно захочет подписать, что означает та или иная ручка.

### Имена, а не регистры

Единственная поправка к первоначальному наброску, и важная. Номера регистров назначает `fxc`, и они
уезжают от любой правки выше по файлу — манифест, ссылающийся на `c7`, тихо разъедется с шейдером
после безобидного редактирования. Это тот же баг, который уже ловили однажды.

Манифест называет **переменные**; загрузчик резолвит их через таблицу констант скомпилированного
шейдера (`sky_bytecode`), как это уже делает аннотация. Регистры принадлежат компилятору, имена —
автору.

### Общие значения

Самая ценная часть формата. Небо объявляет свои источники света — один раз, на верхнем уровне, — а
слои к ним привязываются. Это разом заменяет три разных механизма: соглашение c0-c5 в
`sky_common.hlsli`, привязку `sun =` и ручные ползунки света у спрайтов.

**Свет, а не солнце.** Обобщение до произвольного источника — не запас на будущее, а условие
правдоподобия. Два солнца никогда не были интересным числом: у неба есть солнце, луна, полярное
сияние, зарево у горизонта, планета на треть обзора, — и геометрия, освещённая одним из них, это
геометрия, которая видимо не принадлежит небу за ней. Согласованный свет через несколько слоёв
получается ровно из того, что все слои отвечают одному и тому же списку. Ничего специфически
звёздного в `light` нет: это направление, цвет и яркость, и любого из трёх может не быть.

```jsonc
"shared": {
  "lights": [
    {
      "id": "primary",
      "bearing":   { "label": "Bearing (deg)",   "default": -14.48, "min": -180, "max": 180 },
      "elevation": { "label": "Elevation (deg)", "default": 29.0,   "min": -20,  "max": 70 },
      "color":     { "label": "Sun colour",      "default": [1.0, 0.96, 0.86] },
      "intensity": { "label": "Sun strength",    "default": 1.0, "min": 0.0, "max": 2.0 }
    },
    {
      "id": "twin",
      // Второй источник почти всегда авторится ОТНОСИТЕЛЬНО первого, а не собственным азимутом.
      "bearing":   { "relative_to": "primary", "label": "Twin offset (deg)", "default": 180.0 },
      "elevation": { "same_as": "primary" },
      "intensity": { "label": "Twin strength", "default": 1.0, "min": 0.0, "max": 2.0 }
    },
    {
      // Направления нет вовсе — свет, который само небо бросает на всё, что в нём висит. Без него
      // неосвещённая сторона облака абсолютно чёрная и читается как дырка, а не как облако.
      "id": "ambient",
      "kind": "ambient",
      "color":     { "label": "Ambient colour", "default": [0.55, 0.62, 0.78] },
      "intensity": { "label": "Ambient level",  "default": 0.25, "min": 0.0, "max": 1.0 }
    }
  ],

  // Всё прочее, о чём больше одного слоя обязаны договориться и что не является светом.
  "values": [
    { "id": "haze", "label": "Haze", "default": 0.4, "min": 0.0, "max": 1.0 }
  ]
}
```

`suns` принимается как написание `lights`, а `strength` — как написание `intensity`: так написаны
первые пакеты, и для неба с парой солнц это просто лучшие слова. Это написания, не понятия —
загрузчик в обоих случаях строит один и тот же `light`.

### Пути привязки

Источник привязки называется путём. Резолвится вот это:

| путь | что это |
|---|---|
| `lights.<id>.bearing` | градусы, как их напечатал автор (для относительного света — смещение) |
| `lights.<id>.elevation` | градусы; свет с `same_as` отдаёт значение того, на кого ссылается |
| `lights.<id>.color` | rgb; белый, если цвет не объявлен |
| `lights.<id>.intensity` | скаляр; единица, если не объявлена |
| `lights.<id>.direction` | **производное**: единичный вектор из **абсолютного** азимута и высоты |
| `lights.<id>.radiance` | **производное**: цвет × яркость — то, что на самом деле нужно шейдеру освещения |
| `values.<id>` | свободное общее значение |

Авторские и производные формы привязываются одинаково, и именно это убирает переходник. Шейдер неба
привязывает `g_sun.x` к азимуту, потому что градусы — то, что печатает его автор; шейдер облаков
привязывает `g_light.xyz` к направлению, потому что вектор — то, что нужно его математике. Ни один
не знает, как другой предпочитает это записывать.

Неполный ответ — тоже ответ: у `ambient`-света нет `direction`, и привязка к нему не резолвится, а
не отдаёт нули. Цель остаётся с тем, что в ней было, вместо нуля, который выглядел бы как авторское
значение.

### Слои

Список с порядком отрисовки. `kind` определяет, чем слой рисуется, `bind` — что попадает в его
uniform-переменные.

```jsonc
"layers": [
  {
    "id": "sky",
    "kind": "fullsky",              // пиксельный шейдер, красящий весь куб
    "shader": "shaders/odc.ps.hlsl",
    "bind": {
      "g_sun.x": "suns.primary.bearing",
      "g_sun.y": "suns.primary.elevation",
      "g_sun.z": "suns.twin.bearing",     // как авторено: смещение
      "g_sun.w": "suns.twin.strength"
    },
    "params": [
      {
        "group": "Eclipse",
        "params": [
          { "var": "g_eclipse.x", "label": "Size (deg)", "default": 5.32, "min": 0.2, "max": 20.0 },
          { "var": "g_sun_tint",  "label": "Core colour", "default": [1.0, 0.96, 0.82] }
        ]
      }
    ]
  },
  {
    "id": "clouds",
    "kind": "sprites",
    // Своего шейдера нет — рисуется вшитым в плагин. Слой, который хочет рисовать облака иначе,
    // называет здесь пару .vs/.ps, и всё остальное работает без изменений.
    "bind": {
      "g_light.xyz":  "lights.primary.direction",   // производная форма
      "g_light.w":    "lights.ambient.intensity",
      "g_light2.xyz": "lights.twin.direction",
      "g_light2.w":   "lights.twin.intensity"
    },
    "params": [
      {
        "group": "Clouds",
        "params": [
          // "prop", а не "var": это решает, что лежит В вершинном буфере, а не как это затеняется,
          // и никакая шейдерная константа этого выразить не может.
          { "prop": "count", "label": "Sprites", "default": 120, "min": 0, "max": 600 },
          { "var": "g_tint", "label": "Body colour", "default": [0.92, 0.94, 1.0] }
        ]
      }
    ]
  }
]
```

### `var` или `prop`

Ручка указывает ровно на одно из двух, и говорит, на что, самим ключом:

- **`var`** — переменная шейдера этого слоя. Не регистр: номера назначает fxc, и они уезжают.
- **`prop`** — свойство **вида** слоя, а не его шейдера. Количество спрайтов пересобирает вершинный
  буфер; ни одна шейдерная константа этого не выражает, а притвориться, что выражает, значило бы
  завести вторую систему параметров ровно для тех ручек, которым она нужна меньше всего.

Слой `sprites` понимает `count`, `size` (угловой полуразмер в градусах), `clumps`, `spread`.

Общее значение (свет или запись из `shared.values`) не использует ни того, ни другого: оно
принадлежит небу, а в слои попадает их привязками, — и потому не называет ничего своего.

### Группы — структура, а не атрибут

Параметры лежат **группами**: список групп, у каждой заголовок и свой список. Первый вариант нёс
`"group"` ключом на некоторых записях, и это был прямой след строчного формата, где `group =`
работал переключателем режима.

Так делать не следует: смысл записи начинает зависеть от того, что стоит **выше** неё, то есть
разбор оказывается stateful, только притворяется данными. Вложенность говорит то же самое
структурой — и заодно даёт будущему редактору узел, к которому можно привязать группу, вместо
соглашения, которое надо не сломать.

Группа может не иметь имени — тогда её параметры рисуются без заголовка. Одно правило вместо
второго списка для «негруппированных».

## Настройки — по файлу на небо

`<папка плагина>/Skies/OurDraftsCollides.json`. Заменяет ключи `param.*` в общем `.cfg`, и не только
потому, что те были нечитаемы.

Общий файл **накапливает настройки несуществующих небес навсегда**: нераспознанные `param.*` он
обязан сохранять и писать обратно, потому что изнутри невозможно отличить «небо сейчас не
загружено» от «неба больше нет». Пофайлово это решается построением — удалил небо, удалились
настройки, — и заодно настройка становится тем, что можно **переслать**.

Лежит **рядом с плагином, а не внутри пакета**. Пакет может быть zip-архивом, то есть физически
недоступным для записи, и вообще принадлежит **автору неба**, тогда как значения принадлежат
играющему. Писать свои числа в чужой шипнутый пакет неправильно даже там, где технически можно.

Имя файла — по имени **пакета**, а не по `name` внутри манифеста: имя пакета уникально в папке по
построению и под контролем пользователя, а `name` может совпасть у двух небес и может смениться с
обновлением — и настройки осиротеют без всякого сообщения. Имя санируется: небо, назвавшееся
`../../autoexec`, не должно решать, куда ляжет файл.

Запись опознаётся слоем и `id` параметра (`id` по умолчанию равен имени переменной и существует
затем, чтобы пережить её переименование). **Не группой**: группа — факт представления, и ключ по ней
означал бы, что перенос ручки в другую группу молча теряет её значение. Группы всё же пишутся —
комментариями, для того, кто откроет файл:

```jsonc
{
  "sky": "Our Drafts Collides v2",
  "layers": {
    "sky": {
      // Stars
      "g_star.x": 0.075,

      // Aurora
      "g_aurora.x": 0.6
    },
    // not in the sky's manifest right now; kept so it is not lost
    "clouds": { "count": 140 }
  }
}
```

Записи для слоя, которого сейчас в манифесте нет, **сохраняются** — выключенный на вечер слой не
должен терять настройку. Это единственное, в чём старый плоский файл был прав.

Старые `param.*` остаются **только на чтение и на одну сборку**: значения из них уже попадают в
память при старте, так что первое сохранение переносит их в новый вид само. Писать старый ключ
движок перестаёт сразу.

## Где живут пакеты

`skybox_dir` остаётся тем, чем был: папкой со скайбоксами. Вид каждой записи движок определяет сам,
по содержимому:

| запись | как трактуется |
|---|---|
| каталог с `Config.json` | пакет `.sky` |
| каталог из шести квадратных картинок | cube map по граням (как сейчас) |
| архив `*.sky` | пакет |
| одиночный `*.hlsl` | небо из одного слоя `fullsky` (старый путь) |
| одиночная картинка | cube map: крест или панорама (как сейчас) |

Каталог теперь означает две разные вещи, поэтому порядок проверок важен и он фиксирован:
**сначала `Config.json`**, и только если его нет — шесть граней.

## Совместимость

Старый путь с одиночным `.hlsl` и блоком `@sky` **остаётся**. Такой файл грузится как небо из
одного слоя вида `fullsky`. Это немного кода, оно уже работает, и переход перестаёт быть днём
разрыва.

## Что это открывает

- **Ассетам появляется место.** Меш с материалом — это файл меша, текстура и шейдер; в общей папке
  loose-файлов они бы сталкивались именами.
- **Слой становится сущностью первого класса**, а не «шейдер неба плюс приколоченный сбоку второй
  проход». Оболочки и меши (Ф4/Ф5 в `skybox-geometry.md`) получают, куда объявляться.
- **GUI-редактор становится возможен.** Над «конфигурация в комментариях HLSL» редактор пришлось бы
  строить через round-trip чужого исходника; над JSON это обычная работа.

## Зависимость

`src/libyyjson` — [yyjson](https://github.com/ibireme/yyjson) 0.12.0, MIT, вендорено (два файла, без
сети на configure). Выбран за то, что это **ANSI C**: нет исключений, которые надо выключать, и нет
чужого C++-стиля обработки ошибок, который надо мирить с проектным, — только коды возврата и
`yyjson_read_err`. Комментарии и висячие запятые включаются флагами `YYJSON_READ_ALLOW_COMMENTS` и
`_TRAILING_COMMAS`.
