# UI оверлея: виджеты и слой под ними (`TweakerPlugin`)

Руководство по тому, как в `TweakerPlugin` рисуется интерфейс оверлея: меню, плеер, вкладки Scripts и Skybox,
панель параметров неба, тосты и пины. Что из чего собрано, какие правила у нового кода и как проверить правку
без игры. История решений, почему всё устроено именно так, и находки ревью с номерами `R1–R17`/`U1–U9`, на
которые ссылаются комментарии в коде, — `overlay-widgets-history.md`.

## Что это и зачем

UI оверлея — **ImGui**, но стоковые контролы ImGui по виду и поведению не совпадают с визуальным языком
TweakerUI (акценты, мягкие поверхности, анимированные состояния). Поэтому поверх ImGui лежат два своих слоя:

- **`ui/widgets/`** — контролы со своим состоянием: кнопка, переключатель, список, вкладки, ползунок, попап,
  выбор цвета. Один объект — один контрол, живёт между кадрами.
- **`ui/kit/`** — то, из чего виджеты сделаны: анимация как значение (`anim`), один источник ввода
  (`interact`), рецепты отрисовки без состояния (`paint`). Им пользуются и виджеты, и места, которые рисуют
  себя сами: строки треков плеера, строки скриптов, хром окон, бейджи, кружки цвета.

Слой `kit` существует потому, что виджет целиком подходит не везде — список треков на тысячу строк, строка
скрипта с живыми контролами внутри, разовые фигуры вроде крестика закрытия. Раньше каждое такое место заново
писало свой hover, свою заливку строки, свою рамку области с прокруткой, и они разъезжались: скругления 5/6/8,
мгновенное наведение рядом с плавным, разный фон одной и той же панели. Теперь стиль живёт в одном месте, и
самописная строка выглядит и ведёт себя ровно как виджетная.

```
ui/theme          цвета (редактируемые) + метрики: отступы, скругления, движение, disabled
ui/kit/anim       channel, focus_pair, dt_ms - анимация как тип-значение
ui/kit/interact   interact(), hovering(), fade_disabled() - единственный источник ввода
ui/kit/paint      рецепты без состояния: строка, область с прокруткой, хром окна, пилюля, иконка, ...
ui/widgets/*      контролы = interact + anim + paint + владение значением
ui/form           страница контролов, описанная данными: узел -> виджет, значение у владельца, события
ui/plugins/*,     потребители: собирают экран из виджетов, а где виджет не подходит - из kit
lua_ui, sky_*
```

Код:

| Путь | Назначение |

регистрируются через `menu::add_extra_tab`.

## Правила для нового кода

Короткий список того, что ревью проверяет в первую очередь. Почему каждое правило появилось — в истории.

1. **Виджет — объект с временем жизни.** Не создавать на стеке каждый кадр: внутри анимации, флаги нажатия,
   кэши. `static`, член класса или глобал файла.
2. **`id` стабилен и уникален** в своей ветке ImGui ID stack. Не менять между кадрами, не давать два живых
   виджета с одним `id` в одном окне. `BeginChild`, `PushID`, страницы `tab_view` — отдельные ветки.
3. **Числа — из темы.** Скругления — `theme::radius`, отступы — `theme::space`, длительности —
   `theme::motion`, приглушение выключенного — `theme::disabled_alpha`. Литерал вместо метрики допустим только
   для внутренней раскладки одного виджета, которая больше нигде не встречается.
4. **Вложенные скругления концентричны:** внутреннее = внешнее − зазор между ними. Рамки в теме так и записаны
   («что внутри + отступ»), поэтому новое скругление выражается через существующее, а не подбирается на глаз.
5. **Цвета — из `theme::` каждый кадр**, никогда не кэшировать `ImU32`. Тема меняется на ходу (редактор темы,
   загрузка конфига).
6. **Альфа стиля применяется ровно один раз.** `ImVec4` — цвет темы, рецепт `paint` сам применяет
   `Style.Alpha`; `ImU32` — готовый цвет, через `paint::to_u32` уже прошёл. Голый `ColorConvertFloat4ToU32`
   или повторный `to_u32` — элемент гаснет как alpha² и отстаёт при переходах вкладок и fade попапа.
7. **Всё, на что нажимают, — через `kit::interact`.** Фон, на котором лежат другие элементы, — через
   `kit::hovering`. Вне `kit` не писать `ButtonBehavior`, `InvisibleButton`, `IsItemClicked`,
   `IsMouseHoveringRect`: голая геометрия не знает про окна поверх и про `NoInputs` уходящей страницы.
8. **Всё, что анимируется, — `kit::anim::channel` или `focus_pair`.** Своих tween'ов вне `kit` нет.
9. **Рисовать рецептом, а не копией рецепта.** Строка-карточка, область с прокруткой, хром окна, пилюля,
   «подпись + контрол», иконка, кружок цвета, свечение — есть в `paint`. Если потребителю приходится писать
   голые `AddRect`/`AddText` с цветами темы, рецепта не хватает: его добавляют в `paint`.
10. **Строка «подпись + контрол»** — `paint::label_row` (подпись слева, контрол у правого края по его
    настоящему размеру); подпись-предложение — `paint::label_block`.
11. **Свечению нужно место внутри отсечения:** `paint::glow_reach` (6.75 px). Страница `tab_view` даёт его
    своим отступом (`static_assert`), попап расширяет своё отсечение на эту величину.
12. **Выключенное — выключено, а не «клик ничего не делает».** `set_enabled(false)` у `button`, `toggle`,
    `segmented`, `number_input`, `slider`, `color_field`, `list_view`; приглушение — `theme::disabled_alpha`, а
    внутри `BeginDisabled()` контрол сам не гаснет (`kit::fade_disabled`), иначе альфа выходит в квадрате.
    Целое поддерево — `ui::form::begin_disabled()`: голый `BeginDisabled()` гасит до ImGui'шных 0.6, а не до
    0.4 темы.
13. **Попап, принадлежащий контролу, открывается от контрола** (`popup_menu::open_at`), а не в точке мыши.
    В точке мыши — только контекстное меню по правому клику.
14. **Виджет ведёт себя как обычный контрол.** Если UI обрастает особым поведением только затем, чтобы
    защитить что-то под собой (запись файла, дорогой пересчёт), чинить надо то, что под ним, а баг записывать
    в `Temp/KnownBugs.md`.
15. **На каждом кадре — без аллокаций.** Строки, векторы, форматирование — при изменении данных, а не в
    `update()`. Подписи кэшируются вместе с шириной или значением, для которых сделаны.
16. **Правка `src/ui/` проверяется стендом**: снимки до и после, сравнение, каждый изменившийся снимок —
    вблизи (раздел «Снимочный стенд»).

## Тема (`tw::ui::theme`)

### Цвета

`inline ImVec4` в `theme.hxx`, по группам:

- **Accent** — `accent_primary`, `accent_secondary`, `accent_text`, `accent_selection`, `accent_soft`,
  `accent_hover`, `accent_pressed`, `accent_border`, `accent_selected`, `accent_ghost`;
- **Surfaces** — `surface`, `surface_muted`, `surface_soft`, `surface_hover`, `surface_input`, `surface_row`,
  `surface_row_hover`, `surface_skeleton`, `surface_badge`, `surface_elevated`, `control_track_off`,
  `control_thumb`;
- **Borders** — `border`, `border_subtle`, `border_strong`, `border_divider`, `border_window`;
- **Text** — `text_primary`, `text_secondary`, `text_muted`, `text_subtle`, `text_faint`, `text_glyph_muted`,
  `text_on_accent`; диагностика — `text_error`, `text_warning`.

```cpp
tw::ui::theme::apply_dark();               // дефолты
tw::ui::theme::from_config(config_text);   // key=#AARRGGBB или #RRGGBB построчно, поверх dark
const std::string text = tw::ui::theme::to_config(); // обратно, для сохранения правок редактора
```

Ключ — имя поля (`accent_primary`, `surface`, …), неизвестные ключи игнорируются. Восемь цифр — `#AARRGGBB`,
альфа первой, как в TweakerUI. Виджеты завязаны на эти токены, а не на `ImGuiCol_*`: оверлей обязан совпадать с
хостом.

### Метрики

Константы дизайна, не настройка: редактор темы правит только цвета, в `from_config`/`to_config` метрик нет.

| `theme::space` | px | Где |
|---|---|---|
| `title_h` | 32 | высота заголовка окна (`paint::window_begin`) |
| `window_pad` | 10 | от рамки окна до содержимого |
| `list_pad` | 6 | внутри рамки списка, вокруг карточек |
| `content_pad` | 8 | внутри рамки контролов (страница `tab_view`, тело панели неба) — шире `list_pad`, потому что контролы светятся |
| `nav_pad` | 6 | вокруг кнопок колонки навигации `tab_view` |
| `strip_pad` | 3 | между дорожкой `segmented` и чипами |
| `row_gap` | 6 | между карточками списка |

| `theme::radius` | px | Что |
|---|---|---|
| `row` | 6 | карточка строки (`list_item`, трек, скрипт) |
| `control` | 8 | то, на что нажимают: кнопка, дорожка `segmented` |
| `chip` | 5 = `control − strip_pad` | чип внутри дорожки |
| `tab` | 4 | кнопка вкладки в навигации |
| `field` | 6 | то, во что печатают: `number_input`, поле ползунка, поля ImGui |
| `pill` | 5 | пилюля (`paint::pill`) |
| `scroll` | 12 = `row + list_pad` | рамка списка вокруг карточек |
| `panel` | 10 = `tab + nav_pad` | рамка `tab_view`, `item_group` |
| `window` | 10 = `panel` | окна оверлея и `popup_menu`: отступ окна слишком широк для правила, но окно не бывает менее круглым, чем панель в нём |

`theme::motion` — `timing { duration_ms, easing }`: `hover` 150 мс cubicOut, `press` 90 мс quadOut, `select`
150 мс cubicOut, `slide` 200 мс cubicOut (бегунок переключателя), `transition` 200 мс cubicOut (страницы
вкладок, fade попапа). Тема от tweeny не зависит: `timing` — чистые данные, кривую из них строит `kit::anim`.

`theme::disabled_alpha` = 0.4 — множитель к альфе стиля, поэтому складывается с fade страницы.

### Стиль ImGui из темы

То, что ImGui рисует сам и виджеты не перекрашивают — скроллбары, тултипы, `Separator`, рамки и выделение
полей ввода, курсор, `TextDisabled`, — тоже из темы:

- **`theme::apply_to(ImGuiStyle&)`** — один раз на свежем контексте, вместо `StyleColorsDark()` (DLL —
  `imgui_backend`, стенд — `smoke/shots.cxx`, интерактивное окно — `smoke/main.cxx`). Начинает с
  `StyleColorsDark`, чтобы цвета без токена остались ImGui'шными, и пишет метрики (`FrameBorderSize` 1,
  `FrameRounding`/`GrabRounding` = `radius::field`, `PopupRounding` = `radius::row`, `WindowRounding` =
  `radius::window`, скроллбар 10 px со скруглением 5) и цвета.
- **`theme::sync_colors(ImGuiStyle&)`** — только цвета, в начале **каждого** кадра
  (`imgui_backend::new_frame` и оба цикла стенда). Тему правят пикер редактора, кнопка Default и загрузка
  конфига, и ни одному из них не надо знать, что стиль существует. Метрики каждый кадр не переписываются:
  интерактивное окно стенда масштабирует их под DPI.

Скроллбар — без дорожки, ползунок `border_strong` → `text_faint` под указателем → `accent_primary` при
перетаскивании.

## `kit::anim`

```cpp
#include "ui/kit/anim.hxx"
namespace anim = tw::ui::kit::anim;
```

### `dt_ms()`

Миллисекунды кадра — единица, в которой шагает tweeny. Дробный остаток **переносится** в следующий кадр, а не
округляется: прежняя версия клампила до 1 мс снизу, и выше ~1000 FPS каждый кадр заявлял целую миллисекунду —
окно без vsync проигрывало 150-мс наведение за десятки миллисекунд, а нажатие не было видно вовсе. Значение
считается раз за кадр (кэш по `GetFrameCount()`), иначе весь остаток доставался бы первому спросившему.
`dt_ms()` может вернуть 0 — тогда tween в этом кадре не двигается, и это правильно.

`tw.dt()` скриптов берёт ту же `DeltaTime`, но **без** округления: скрипт сам интегрирует `x += v * dt`, и целые
миллисекунды (6/7 на 144 Гц) давали дрожание.

### `channel` — одно анимированное значение

```cpp
anim::channel hover { tw::ui::theme::motion::hover };

hover.set(pointer.hovered);       // каждый кадр; кривая перезапускается только при смене цели
const float t = hover.step();     // каждый кадр, даже когда стоит на месте (см. ниже)
```

- `set(bool)` / `set(float)` — к цели; новая кривая стартует **от текущего значения**, поэтому смена
  направления посреди хода не прыгает.
- `restart(from, to)` — движение, которое всегда начинается из одной точки: страница, проявляющаяся из нуля;
  тост, въезжающий на место.
- `snap(value)` — значение и цель сразу, без кривой. Для состояния, которое пришло **не от пользователя**:
  контрол, созданный уже включённым; выбор, присланный хостом; другой трек под открытым меню.
- `step()` — читать **каждый кадр**, даже стоя на месте. Перенос остатка в `dt_ms()` видит только кадры, в
  которые его спросили; пропущенный кадр сдвигает цикл 16/17/17 мс, и шаг анимации начинает зависеть от того,
  кто ещё смотрел на часы.
- Значение — источник правды, а не tween. В конце кривой значение не «доводится» до цели (отличие в последнем
  бите, которое стенд честно показал бы как изменение).

### `focus_pair<TKey>` — подсветка списка без состояния в строках

Виртуализированный список не может держать `channel` на строку: значение, привязанное к слоту 12, анимирует
то, что прокрутилось в этот слот. Но в каждый момент ровно одна строка наведена (или выбрана) — анимация
принадлежит ей, плюс предыдущая на время одного перехода.

```cpp
anim::focus_pair<int> g_hover { theme::motion::hover, -1 };   // -1 = никого
anim::focus_pair<int> g_select { theme::motion::select, -1 };

g_hover.step();  g_select.step();         // раз за кадр, до строк
// для строки i:
if(pointer.hovered) { g_hover.focus(i); }
if(pointer.clicked) { g_select.focus(i); }
paint::row_background(draw, bb.Min, bb.Max, g_hover.alpha(i), g_select.alpha(i));
// после строк: никто не навёлся - погасить
if(!any_hovered) { g_hover.focus(-1); }
```

`focus(key)` — с переходом; `jump(key)` — без (программный выбор, смена плейлиста); `reset()`; `current()`.

## `kit::interact`

```cpp
#include "ui/kit/interact.hxx"
```

### `interact(bb, id, placement, enabled)` — то, на что нажимают

`ItemAdd` + `ButtonBehavior`; учитывает окна поверх, `NoInputs` уходящей страницы, элемент, уже держащий мышь.
Возвращает `interaction`:

| Поле | Что |
|---|---|
| `visible` | элемент выложен и не отсечён; если `false`, все остальные поля `false` |
| `disabled` | выключен своим `enabled` или внешним `BeginDisabled()` |
| `hovered` | под указателем |
| `held` | левая кнопка пошла вниз на нём и ещё зажата, где бы ни был указатель |
| `clicked` | полный клик: вниз и вверх на нём (то, что кнопка называет «нажата») |
| `left_down`, `right_down` | кнопка пошла вниз над ним в этом кадре — для действий, которые не ждут отпускания (открыть попап там, где кликнули) |
| `double_clicked` | второй клик двойного |

- `placement::flow` (по умолчанию) — занимает место в раскладке (`ItemSize`).
- `placement::overlay` — только зона нажатия там, где её поставили руками: вкладка в колонке `tab_view`, чип
  внутри дорожки `segmented`, заголовок окна, кружок `color_field`. Место занимают иначе (`Dummy` на строку).
- `enabled = false` ставит флаг `ImGuiItemFlags_Disabled`, а не `BeginDisabled()`: тот ещё и гасит альфу, а
  как выглядит выключенное — решает отрисовка.

### `hovering(bb)` — фон под другими элементами

Строка скрипта несёт свой переключатель и кнопки. Элементом она быть не может: ImGui отдаёт наведение первому
заявившему, и строка отняла бы его у своих же кнопок. `hovering` ничего не заявляет — проверяет, что указатель в
прямоугольнике, в текущем отсечении, и текущее окно — то, что под указателем (с
`AllowWhenBlockedByActiveItem`, чтобы строка не гасла, пока держат её же переключатель). Не для кликабельного.

### `fade_disabled(enabled)`

Гасить ли контрол, выключенный своим `set_enabled(false)`, на `theme::disabled_alpha`: да, если он не внутри
ImGui'шного `BeginDisabled()` — тот уже погасил всё на `Style.DisabledAlpha`.

```cpp
const bool fade = kit::fade_disabled(m_enabled);
if(fade) { ImGui::PushStyleVar(ImGuiStyleVar_Alpha, ImGui::GetStyle().Alpha * theme::disabled_alpha); }
// ... отрисовка ...
if(fade) { ImGui::PopStyleVar(); }
```

`IsMouseHoveringRect` в оверлее остался в одном месте: `popup_menu` проверяет, что клик пришёлся мимо его
собственной рамки, — там нужна именно геометрия.

## `kit::paint` — рецепты

```cpp
#include "ui/kit/paint.hxx"
namespace paint = tw::ui::kit::paint;
```

Рецепты без состояния: принимают уже посчитанные `t` (наведение, выбор), анимацию держит вызывающий. Цвет —
правило 6: `ImVec4` из темы рецепт доводит до готового сам, `ImU32` рисуется как дан.

| Рецепт | Что | Кто рисует |
|---|---|---|
| `lerp`, `to_u32`, `apply_style_alpha`, `resolve_size` | смешение, цвет с альфой стиля, размер «0 = по умолчанию» | все |
| `row_background(draw, min, max, hover_t, select_t)` | карточка строки: `surface_row` → `surface_row_hover` → `accent_selected` с рамкой, `radius::row`; выбранная под указателем не меняется; зазор — раскладка вызывающего | `list_item`, `list_view`, треки, скрипты |
| `scroll_body_begin(id, size, padding, rounding, flags)` / `scroll_body_end()` | область с прокруткой: child на `surface`, рамка `border`, отступ из `space`; `end` — всегда | `list_view`, треки, тело панели неба, контент `tab_view` |
| `window_begin(name, title, closable)` → прямоугольник заголовка | `Begin` окна оверлея и его хром: тело `surface`, рамка `border_window`, `radius::window`, заголовок `title_h` с многоточием; закрывать `ImGui::End()` | меню, панель неба |
| `close_button_rect(title)` / `close_button(draw, slot, hover_t)` | крестик в конце заголовка: где он (для `interact`) и как выглядит | панель неба |
| `resize_grip_rect(window_max)` / `resize_grip(draw, window_max)` | уголок ресайза — две дуги, концентричные углу окна | меню |
| `label_row(label, control)` → прямоугольник текста | подпись по центру строки высотой `max(контрол, строка)`, с многоточием; курсор — у правого края под контрол его настоящего размера | Tweaks, Settings, Skybox, Mods |
| `label_block(label, control)` | то же для подписи-предложения: переносится, контрол — по первой строке, следующее — под подписью | теги в меню трека |
| `paragraph(text, color)` | абзац сам по себе: перенос по оставшейся ширине, цвет темы, занимает свою высоту; пустой — одна строка | текстовый узел `ui/form`, подпись над широким выбором |
| `pill(draw, min, text)` / `pill(…, tint)`, `pill_size`, `pill_height` | пилюля 8 × 3, `radius::pill`; нейтральная (`surface_badge`/`text_muted`) и оттеночная (оттенок ×0.18 / оттенок) | бейджи треков, чипы скриптов |
| `icon(draw, tex, min, px, tint)` | монохромная иконка, позиция привязана к пикселю вниз, альфа один раз | `button`, `segmented`, тосты, пины |
| `add_image_keep_aspect(draw, tex, src, min, max, tint)`, `aspect_fit_size` | картинка с сохранением пропорций | превью скинов, водяной знак |
| `color_swatch(draw, center, d, color, hover_t)` | кружок цвета: свечение своим оттенком, шахматка под неполностью непрозрачным, кольцо | `color_field` |
| `add_text_ellipsis(draw, pos, max_x, col, text)` → обрезан ли | текст с многоточием | везде |
| `fit_text(text, max_w)` → `std::string` | то же строкой — для текста, который рисуют иначе; **аллоцирует**, кэшировать по ширине | подписи `tab_view` |
| `add_text_glow`, `add_rect_glow`, `add_circle_glow`; `glow_reach` | свечения копиями контура; вылет 6.75 px | акценты, бегунки, рамка попапа |
| `add_gradient_polyline(draw, points, colors, n, thickness, flags)` → применён ли | ломаная ImGui, нарисованная белым и перекрашенная по точкам; знает раскладку вершин `AddPolyline` (AA: 2/3/4 на точку, без AA: 4 на сегмент), незнакомая — вся линия цветом первой точки и `false` | `tw.hud.gradient_polyline` |

Рецепт с состоянием не заводится: крестик и уголок — пара «прямоугольник для `interact`» + «рисунок по `t`»,
`channel` держит вызывающий. `paint` от `anim` не зависит.

## Виджеты

Общее для всех:

- **Размер `0` по оси = по умолчанию** (`paint::resolve_size`): ширина — остаток строки
  (`GetContentRegionAvail().x`), высота — значение виджета по умолчанию. `set_size` можно звать каждый кадр.
- **Флаги кадра** (`clicked()`, `changed()`, `committed()`, `selection_changed()`) сбрасываются в начале
  `update`/`begin` того же экземпляра и валидны до следующего.
- **Программная установка** (`set_checked`, `set_selected`, `set_value`, `set_color`) — no-op при том же
  значении и **никогда** не поднимает `changed()`. Владелец может пушить авторитетное значение каждый кадр и не
  зациклиться против клика пользователя. У `slider` и `color_field` она ещё и игнорируется, пока идёт жест;
  `active()` говорит, что сейчас именно так, — владельцу со своей копией значения, чтобы копия не разошлась с тем,
  что держит пользователь (`ui/form`).
- **`set_enabled(false)`** — у всех контролов со значением и у кнопки: `button`, `toggle`, `segmented`,
  `number_input`, `slider`, `color_field`, `list_view` (последние четыре — с 20.10.2026, для `ui/form`). Гасит до
  `theme::disabled_alpha` через `kit::fade_disabled`; `number_input` — стоковые поля ImGui, поэтому у него
  `BeginDisabled` с `DisabledAlpha` из темы. Выключенный `slider` закрывает поле ввода, `color_field` — пикер,
  `list_view` прокручивается, но не наводится и не выбирается.
- **Не рисовать один экземпляр дважды за кадр** — например, на двух страницах `tab_view` во время перехода,
  когда видны обе. По экземпляру на место.

| Виджет | Тик за кадр |
|--------|-------------|
| `button`, `toggle`, `segmented`, `number_input`, `slider`, `list_item`, `list_view`, `color_field`, `color_picker` | `update(...)` |
| `item_group` | `begin()` → содержимое → `end()` |
| `popup_menu` | `if(opened()) { begin();` → содержимое → `end(); }` |
| `tab_view` | `begin()` → ноль+ `begin_view`/`end_view` → `end()` |

### `button`

```cpp
#include "ui/widgets/button.hxx"

static button apply { "menu_skins_apply", { 100.f, 28.f } };   // по умолчанию 120 × 32

apply.set_enabled(can_apply);                // R12: выключена, когда делать нечего
apply.update(pending ? "Applying..." : "Apply");   // метка на этот кадр; или set_label() + update()
if(apply.clicked() && can_apply) { /* ... */ }
```

- `clicked()` — полный клик. `hovered()` — под указателем в этом кадре (сбрасывается, когда кнопка отсечена).
- `size()` — как задан; по нему кнопку раскладывает `label_row` (только фиксированного размера).
- **Иконка** — `set_icon("icons/play.svg")`: слева от метки или одна по центру. Хранится ключом, текстура
  берётся на отрисовке (правило иконок 2). Размер — по высоте кнопки: `>= 36` → 24, иначе 16 (запечённые).
  Тонируется цветом метки, поэтому следует теме и нажатию.
- Скругление `radius::control`, наведение `motion::hover`, нажатие `motion::press` — заливка к
  `accent_pressed` и сжатие на 4 %. Выключенная не наводится, не нажимается и приглушена.
- Тултип — вызывающего: сразу после `update()` кнопка — последний элемент ImGui, поэтому
  `if(btn.hovered() && ImGui::IsItemHovered(ImGuiHoveredFlags_DelayNormal)) ImGui::SetTooltip(...)`
  (транспорт плеера).

### `toggle`

```cpp
#include "ui/widgets/toggle.hxx"

static toggle offline_pin { "menu_offline_pin" };   // по умолчанию 40 × 22

offline_pin.set_checked(config_value);             // каждый кадр; no-op без изменения
paint::label_row("Show \"Offline\" pin", offline_pin.size());
offline_pin.update();
if(offline_pin.changed()) { save(offline_pin.checked()); }
```

- Клик сам переключает `checked` и поднимает `changed()`.
- `set_checked` до первой отрисовки — без анимации: переключатель, появившийся включённым, не «включается» на
  глазах. Не `noexcept` — смена значения строит tween.
- `snap(checked)` — без анимации всегда: состояние сменил не пользователь. Пример — переключатели тегов в меню
  трека помнят, для какого трека их ставили, и на другом треке делают `snap`.
- Отклик: свечение бегунка под указателем, бегунок вытягивается на 5 px к стороне хода при нажатии.
- `set_enabled`, `size()` — как у кнопки.

### `segmented`

Ряд взаимоисключающих чипов — аналог `RadioButton.QPSegmentButton` десктопа: режимы воспроизведения Quick
Player, `Auto`/`Manual`, стороны `Left`/`Right` в Settings.

```cpp
#include "ui/widgets/segmented.hxx"

static segmented side { "menu_feed_side" };          // ctor принимает высоту (28), не ImVec2
static const std::string_view k_labels[] = { "Left", "Right" };
side.set_options(k_labels);                          // раз: пересоздаёт анимации чипов

side.set_selected(current == side::right ? 1 : 0);   // каждый кадр
paint::label_row("Pins side", ImVec2 { side.width(), side.height() });
side.update();
if(side.changed()) { apply(side.selected()); }       // только клик пользователя
```

- **Ширина — по содержимому**: задаётся только высота, чипы не сжимаются под панель — расширяется панель.
  `width()` возвращает ровно то, что посчитает `update()`: транспорт плеера раскладывает свободную ширину между
  группами, ему ширины нужны до отрисовки.
- `set_icons(keys)` — иконочный режим: чипы 34 px с глифом 16 px, подписи уходят вызывающему на тултипы
  (`hovered_index()`). Чип за концом списка иконок рисует подпись в ширину подписи.
- Чипы концентричны дорожке (`radius::control` − `strip_pad`). Наведение — только на невыбранных: на выбранном
  оно спорило бы с акцентом.
- `set_enabled`; выключенная полоса не наводится и не меняется.
- Почему не циклическая кнопка-иконка: у состояний нет однозначных пиктограмм, а «включённое» заливает кнопку
  акцентом до сплошного квадрата. Проверено на десктопе — слова читаются, иконка нет.

### `number_input`

Целое поле с клампом и степперами `-`/`+` — параметризованные теги Quick Player (`[as-msz12]`, `[as-wb50]`, …),
у каждого свой диапазон из каталога.

```cpp
#include "ui/widgets/number_input.hxx"

static number_input match_size { "qp_msz", 96.f };   // ширина
match_size.set_range(0, 24);                         // клампит и текущее значение
match_size.set_value(host_value);
match_size.update();
if(match_size.changed()) { send(match_size.value()); }
```

- `ImGui::InputScalar`, перекрашенный темой: ввод, выделение и клавиатура — слишком много поведения, чтобы
  писать заново ради поля такого размера. Степперы — стоковые кнопки ImGui, поэтому перекрашиваются и
  `ImGuiCol_Button*`, и `FrameRounding` (`radius::field`).
- `changed()` — не на каждую клавишу: клик по степперу или уход из поля после ввода. Каждое изменение у
  вызывающего — сообщение на проводе.

### `slider`

Дробный ползунок: подпись и значение в одну строку, под ними тонкий трек с круглым бегунком. Параметры
шейдерного неба (панель неба).

```cpp
#include "ui/widgets/slider.hxx"

static slider density { "c6x" };    // id из стабильного ключа параметра, не из подписи
density.set_label("Star density");
density.set_range(0.005f, 0.30f);  // клампит и текущее
density.set_value(host_value);     // игнорируется, пока идёт жест или открыто поле
density.update();

if(density.changed())   { push_to_shader(density.value()); }  // каждое движение
if(density.committed()) { save_to_disk(density.value()); }    // конец жеста
```

- **Обычный ползунок.** Нажатие на полосе трека сразу ставит бегунок под указатель (`changed()`), дальше он
  идёт за мышью, `committed()` — на отпускании. Нажатие на подпись ничего не меняет. Двойной клик в любом
  месте строки открывает поле ввода (первый щелчок при этом уже выставил значение — как у любого ползунка).
- **Escape посреди жеста** возвращает значение, которое было до нажатия (с `changed()` — живое превью
  откатывается), и гасит остаток жеста до отпускания.
- **`changed()` и `committed()` — разные вещи.** Перетаскивание — сотни значений; небо получает каждое, файл
  настроек — одно.
- **Shift** — точный режим (0.15 скорости): общая палитра объявляет `Light size` на `0.99..1.0`, весь ход в
  полтора пикселя трека. Якорь перезакладывается на каждом переключении Shift; нажатие с зажатым Shift
  начинает точный режим от текущего значения, без прыжка.
- **Точность вывода — по ширине диапазона:** `>= 100` → `%.0f`, `>= 10` → `%.1f`, `>= 1` → `%.2f`, иначе
  `%.4f`. Место под число резервируется по самому широкому из `min`/`max`, поэтому многоточие подписи не
  ездит под перетаскиванием.
- Поле ввода — `InputFloat`, перекрашенное темой, с нулевым вертикальным `FramePadding`: строка одной высоты в
  обоих режимах, иначе панель прыгает на двойном клике. Enter или уход из поля после ввода — `committed()`;
  Escape — отмена.

### `color_field`

Строка «подпись + кружок цвета», левым кликом по кружку открывающая `color_picker` в своём `popup_menu`.
Пикер большой (квадрат SV, полосы тона и альфы, hex и четыре поля RGBA): палитра неба на четыре цвета inline —
четыре экрана пикера, за кружками — четыре строки. Им же сделан редактор темы в Settings.

```cpp
#include "ui/widgets/color_field.hxx"

static color_field zenith { "c0xyz" };
zenith.set_label("Zenith");
zenith.set_color(host_color);     // игнорируется, пока попап открыт
zenith.update();

if(zenith.changed())   { push_to_shader(zenith.color()); }
if(zenith.committed()) { save_to_disk(zenith.color()); }
```

- **Раскладка.** По умолчанию — обычная строка «подпись + контрол»: подпись слева, кружок у правого края,
  строка во всю ширину. `set_swatch_first(true)` — кружок слева, подпись после, ширина по содержимому: для
  цветов в shrink-to-content рамках (группы редактора темы — строка во всю ширину не оставила бы места второй
  колонке «кладки»).
- **Открытие** — на нажатии (`left_down`), попап — `open_at` под кружком; у края экрана прижимается внутрь.
- `committed()` — на кадре, когда пикер что-то менял, а кнопка мыши отпущена: один коммит на жест.
- Свечение кружка — **его собственным** оттенком: наведение читается как «этот цвет», а не «тут можно
  кликнуть». Неполностью непрозрачный цвет — на шахматке.

### `color_picker`

HSV + альфа: квадрат SV, полосы тона и альфы **во всю ширину**, справа от квадрата — подпись формата, hex и
RGBA, двусторонняя синхронизация. Наружу — `ImVec4` RGBA.

```cpp
#include "ui/widgets/color_picker.hxx"

static color_picker accent { "theme_accent", { 260.f, 0.f } };
accent.update(accent_color);   // привязка к внешнему ImVec4: подхватывает внешнюю запись, пишет обратно
// или внутренний цвет: accent.update(); if(accent.changed()) { use(accent.color()); }
```

- **Hex.** Над полем — постоянная подпись `Hex #AARRGGBB`: порядок цифр — соглашение, и угадать его нельзя
  (CSS пишет `#RRGGBBAA`). Восемь цифр — альфа первой, как в TweakerUI и файле темы. Непрозрачный цвет
  показывается `#RRGGBB`; шесть введённых цифр сохраняют текущую альфу. Применяется на Enter или уходе из поля.
- Поля RGBA — целые 0–255. Пока поле в фокусе, перетаскивание в квадрате не перезаписывает его буфер.
- Квадрат не ниже колонки полей (подпись + пять строк), иначе строки налезают на полосы.
- Внутренняя модель — HSV; тон сохраняется при S ≈ 0. `set_color` — программная установка.

### `list_item`

Одна строка: иконка (необязательно), текст, вторая строка. Карточка (`paint::row_background`), наведение и
выбор анимированы.

```cpp
#include "ui/widgets/list_item.hxx"

static list_item row { "qp_character_0", { 168.f, 26.f } };
row.set_content({ .text = "Mono" });   // раз; не пересобирать строку каждый кадр
row.set_selected(is_current);          // выбор — снаружи: по клику сам не переключается
row.update();
if(row.clicked()) { /* ... */ }
```

- `update(const list_item_content&)` рисует переданное без записи в виджет.
- `subtext` — вторая строка мельче и тише (12 px), со своим многоточием. Основной текст тоже режется
  многоточием, а не краем.
- Иконка вписывается с сохранением пропорций.
- `list_item::draw_content(draw, min, max, content)` — содержимое строки отдельно от карточки, для списка,
  который рисует строки сам (`list_view`).

### `list_view`

Список с прокруткой и одним выбором — плейлисты, скины, персонажи в меню трека.

```cpp
#include "ui/widgets/list_view.hxx"

static list_view skins { "menu_skins" };
if(names_changed) { skins.set_items(items); }   // span<const list_item_content>; копирует

skins.set_size({ 0.f, ImGui::GetContentRegionAvail().y });
skins.update();
if(skins.selection_changed()) { pick(skins.selected_index()); }   // -1 = ничего
```

- **Строки — не объекты.** Каждая — `interact` + `row_background` + `list_item::draw_content`; наведение и выбор
  — две `focus_pair`. Поэтому `set_items` (обновление каталога, переименование) не гасит и не перезапускает
  подсветку; сбрасывается только выбор за концом нового списка.
- `set_selected(index)` — программный выбор (Player подсвечивает плейлист, который реально отдал хост): без
  перехода, `selection_changed()` не поднимает; индекс вне диапазона снимает выбор.
- Строка 36 px, 46 px, если хоть у одной есть `subtext` (все строки одной высоты — иначе список читается как
  сбитый). Рамка — `scroll_body` с `list_pad`, зазор — `row_gap`.
- **Клиппера нет:** каждая строка — элемент ImGui каждый кадр. Для десятков строк нормально; список треков на
  тысячу — свой, на `focus_pair` и префиксной сумме высот (раздел «Самописные места»).

### `tab_view`

Колонка навигации слева, страницы справа, переход — crossfade.

```cpp
#include "ui/widgets/tab_view.hxx"

static tab_view tabs { "menu_tabs" };
static const std::string_view k_labels[] = { "Skins", "Tweaks", "Player", "Settings" };
tabs.set_tabs(k_labels);                      // раз, снаружи begin()/end()
tabs.set_rounding(theme::radius::panel);      // по умолчанию и так panel

tabs.set_size({ content_w, content_h });
tabs.begin();
if(tabs.begin_view(0)) { /* ... */ tabs.end_view(); }
if(tabs.begin_view(1)) { /* ... */ tabs.end_view(); }
tabs.end();                                   // всегда, даже если ни один view не открылся
```

- **Колонка** — дочернее окно `##nav`: ширина по самой широкой подписи, кнопки одной ширины (высота 36, зазор
  2, отступ `nav_pad`). Подписи, которые не помещаются, режутся многоточием (`fit_text`, кэш на вкладку по
  ширине), вкладки, которые не помещаются, прокручиваются колесом над колонкой — без полосы. Вкладки неба
  задаёт автор пакета, поэтому длинные подписи и много вкладок — нормальный случай.
- **Страницы.** Рамка — `scroll_body` на `radius::panel`; страница (`##page`) — своё дочернее окно с отступом
  `content_pad`, вставленное внутрь рамки на её толщину, и сама прокручивается — дочернее окно с прокруткой
  внутри страницы заводить не нужно. Отступ ≥ `glow_reach` (`static_assert`): свечение контролов у края не
  обрезается.
- **`begin_view(i)`:**

  | Условие | Возвращает | Прозрачность страницы |
  |---|---|---|
  | выбранная, переход окончен | `true` | 1 |
  | выбранная, идёт переход | `true` | `t` (0 → 1) |
  | предыдущая, идёт переход | `true` | `1 − t`, и `NoInputs` |
  | иначе / отсечена / неверный индекс | `false` | — |

  Пока идёт переход, **рисуются обе** страницы. Возврат на уходящую посреди перехода меняет их ролями и
  продолжает с текущей прозрачности (без вспышки); третья вкладка оставляет уходящей более видимую из двух.
- `selected_tab()` — целевой индекс. `set_selected_tab(i)` — программное переключение, анимируется как клик и
  так же поднимает `selection_changed()`; только снаружи `begin`/`end` (как `set_tabs`, проверяется `assert`).
- **Вкладки, которые приходят и уходят** (вкладки скриптов, с 20.10.2026):
  - `set_tabs(labels, selected)` — с `selected` ≥ 0 выбирает эту вкладку **без перехода и без
    `selection_changed()`**: колонку пересобрали под пользователем, страниц никто не переключал, а уходящей
    странице может быть уже некому рисоваться. `-1` (по умолчанию) — как раньше, индекс сохраняется с клампом.
  - `set_label(i, text)` — одна подпись, сбрасывается только её кэш многоточия; `set_tab_enabled(i, false)` —
    подпись (и подложка выбранной) гаснет до `disabled_alpha`, вкладка остаётся кликабельной.
  - `set_tab_id(i, key)` — страница ключуется в ID stack по ключу, а не по индексу: иначе вкладка, въехавшая на
    индекс ушедшей, унаследовала бы её прокрутку и состояние виджетов. `set_tabs` ключи сбрасывает.
  - `nav_width()` — ширина колонки на последнем `begin()`, для владельца, который считает окно под страницу.
- Инварианты (`assert` в debug): `begin` не вкладывается; каждому успешному `begin_view` — один `end_view`;
  `end()` — после всех view.

### `popup_menu`

Отдельное окно ImGui поверх всего, по размеру содержимого, со скруглённым хромом, необязательным заголовком и
fade.

```cpp
#include "ui/widgets/popup_menu.hxx"

static popup_menu characters { "qp_character_popup", "Default character" };

character_btn.update(label);
if(character_btn.clicked()) {
    const ImVec2 min = ImGui::GetItemRectMin();
    characters.open_at(min, ImVec2 { min.x + character_btn.size().x, min.y + row_h });   // от кнопки
}
// контекстное меню: if(pointer.right_down) { context.open(); }                          // в точке мыши

if(characters.opened()) {
    characters.begin();
    // ... содержимое; закрыть изнутри - characters.close()
    characters.end();
}
```

- `open()` — левый верхний угол в точке мыши: контекстное меню по правому клику. `open_at(min, max)` — под
  прямоугольником якоря, левые края вровень, зазор 4 px; **над** якорем, если снизу нет места. Попап,
  который принадлежит контролу, открывается так.
- `opened()` остаётся `true` на время fade-out, чтобы `if(opened())` дорисовал исчезновение. С закрытием сразу
  ставится `NoInputs` — полупрозрачный остаток не перехватывает клики.
- **Закрывается:** `close()`; клик (левый или правый) вне рамки; потеря фокуса после того, как фокус был;
  **Escape** — если внутри ничего не активно (поле ввода и перетаскиваемый ползунок забирают Escape себе).
  Кадр открытия и следующий закрытие пропускают, иначе открывающий клик закрыл бы меню.
- **Хром — под содержимым.** Содержимое пишется в канал 1 `ImDrawListSplitter`, хром — в канал 0 в `end()`, по
  размеру **этого** кадра: ни первого кадра с хромом поверх, ни отставания рамки на кадр.
- Тело `surface`, рамка `accent_border` со свечением `accent_primary` (под своим отсечением, расширенным на
  `glow_reach`), `radius::window`, отступ 8. Заголовок — полоса `accent_soft`, текст `accent_text`; длинный
  заголовок расширяет рамку до 320 px, дальше многоточие.
- Имя окна — `##tw_popup_<id>#<n>` по номеру создания: детерминированно и без конфликтов у двух попапов с одним
  `id`. Положение прижимается к экрану после измерения размера.
- Инварианты: `begin` не вкладывается; каждому `begin()` — один `end()`; `begin` на закрытом — no-op.

### `item_group`

Рамка с заголовком на верхней кромке (GroupBox), по размеру содержимого.

```cpp
#include "ui/widgets/item_group.hxx"

static item_group accent { "menu_theme_group_accent", "Accent" };
accent.begin();
// ... любые элементы ...
accent.end();   // обязателен
```

- Рамка = содержимое + `inner_padding` (8, 8), шире — если заголовок шире содержимого; `outer_padding` (0, 4)
  — от окружающей раскладки. Скругление `radius::panel`.
- Разрыв рамки под заголовком — не заплатка фоном (просвечивала при fade и на неоднородном фоне): рамка рисуется
  трижды под тремя отсечениями в обход заголовка.
- Пока группа открыта, доступная ширина урезана на её правый отступ: виджет «на всю ширину» внутри группы не
  выходит за рамку.
- Цвета: рамка `border`, заголовок `text_secondary`. Без заливки и анимаций.
- **`set_fill_width(true)`** — рамка во всю ширину, в которой группу открыли (минус `outer_padding` с обеих
  сторон), а не по содержимому: раздел страницы настроек. Содержимое шире всё равно расширяет рамку. По умолчанию
  выключено — кладке групп редактора темы нужно «по содержимому».

## Форма (`ui/form`)

Страница контролов, описанная данными: владелец добавляет узлы, форма держит по виджету на узел, рисует их и
сообщает, что поменял пользователь. Сделана для вкладок, которые объявляют скрипты (`script-tabs.md`
§3.3), и про Lua не знает: это слой, который делает виджеты со своим состоянием пригодными для владельца, который
не C++ и сам не рисует.

```cpp
#include "ui/form/form.hxx"
using tw::ui::form::kind;

tw::ui::form::form page { "script_7_tab_0" };              // id - ветка ImGui ID, уникальна в окне
const int display = page.add(kind::group, -1, "Display");  // -1 - верхний уровень
const int scale = page.add(kind::slider, display, "Scale");
page.set_range(scale, 0.5, 2.0);
page.set_value(scale, 1.0);

page.draw();                                               // внутри страницы tab_view, каждый кадр
for(const tw::ui::form::event& e : page.events()) {        // что сделал пользователь в этом draw()
    // e.node, e.value, e.committed
}
```

- **Значение — у формы, виджет — его вид.** Значение узла — `double` у всех видов (`bool` 0/1, целое, дробное,
  номер варианта с 0, цвет — упакованный `IM_COL32`, строка списка или −1). Каждый кадр значение уходит в виджет
  программной установкой, после `update()` то, что поменял пользователь, возвращается в значение и в `events()`.
  Так держится контракт виджетов: пушить каждый кадр можно, зацикливания нет.
- **Пользователь главнее — и в значении формы.** Пока `slider` тянут или у `color_field` открыт пикер,
  `set_value` формы игнорируется, а значение повторяет виджет. Без этого запись владельца каждый кадр стояла бы в
  форме под рукой пользователя, и `committed` на отпускании нёс бы число владельца (сцена `form-program-set` это
  поймала).
- **События.** `committed` — конец жеста (отпустили ползунок, закончили тянуть в пикере) или всегда, у контролов
  без жестов. Отпускание, которое ничего не сдвинуло, тоже событие с `committed`: владелец, пишущий на коммите,
  должен его услышать. Escape посреди жеста — событие с прежним значением без `committed`, и коммита после него
  нет. Не больше одного события на узел за кадр.
- **Виды:** `group` (`item_group` во всю ширину, вложенность ≤ `k_max_group_depth` = 2), `toggle` и `number`
  (`label_row`), `slider` и `color` (своя подпись, строка во всю ширину), `choice` (`segmented`: рядом с подписью,
  а если полоса шире половины строки — под подписью, `paint::paragraph`), `button` (ширина по подписи), `text`
  (`paint::paragraph`, `text_secondary`), `separator`, `list` (`list_view` заданной высоты). Нумерация видов —
  ABI для Lua: только дописывать.
- **Выключенный узел** рисуется под `form::begin_disabled()` целиком, подпись `label_row` тоже, — свой
  `set_enabled` виджета при этом ставится ради поведения (закрыть поле, пикер), а дважды не гаснет
  (`kit::fade_disabled`). `begin_disabled()` — `BeginDisabled` с `DisabledAlpha` = `theme::disabled_alpha`: страница
  под ним выглядит ровно как страница, где выключен каждый узел (сцена `form-disabled`). **Скрытый** узел места не
  занимает, скрытая группа прячет содержимое.
- **Подсказка** (`set_tooltip`) — по прямоугольнику строки через `kit::hovering`, после `HoverDelayNormal`; строка
  внутри группы перебивает подсказку группы.
- `min_width()` — самая узкая ширина, в которую форма помещается (полоса чипов не сжимается), с отступами рамок,
  измеренная на прошлом `draw()`; `last_rect(node)` — где была строка узла, для стенда.
- Без аллокаций в кадре: события — в векторе под число узлов, подписи присваиваются только при отличии, ширина
  кнопки — при смене подписи.

## Самописные места

Где виджет целиком не подходит, экран собирается из `kit` без класса. Три образца.

**Список треков плеера** (`player.cxx`) — тысяча строк разной высоты, виртуализированный:

- высоты строк и зазоры `row_gap` — в префиксной сумме `g_row_offsets`, пересчёт при смене списка или ширины,
  не каждый кадр; видимый диапазон — двоичный поиск по сумме, каждая строка ставится `SetCursorPosY` по ней
  (зазор, добавленный мимо суммы, развёл бы отсечение с раскладкой);
- строка — `interact` + `row_background` с `g_hover.alpha(i)` / `g_select.alpha(i)` двух `focus_pair`; левый и
  правый клик двигают выбор одинаково, с переходом;
- бейджи — `paint::pill`, раскладка по строкам считается вместе с высотой строки; маркер «играет» — пилюля
  внутри карточки, а не полоса по краю, которую срезали бы скруглённые углы.

**Строка скрипта** (`lua_ui.cxx`) — карточка с переключателем и кнопками внутри: наведение строки —
`hovering()` (строка не элемент) и свой `anim::channel` на строку; фон — `row_background`; чипы состояния —
оттеночные `pill`; рамка по состоянию (ошибка, приостановка) — поверх карточки, потому что несёт смысл.

**Динамические вкладки меню** (`menu::set_dynamic_tabs`, `script-tabs.md` §3.4) — после встроенных и
`add_extra_tab`, их позиции не двигаются. Список целиком, `{ key, label, draw, token, enabled }`; можно звать из
любого места, в том числе изнутри страницы (Reload из вкладки Scripts): список копируется и применяется в начале
следующего `update()`, снаружи `tab_view`. Те же ключи — только `set_label`/`set_tab_enabled`, колонка не
пересобирается и ни один пиксель не меняется (сцена `menu-dynamic-tabs`, кадры `relabelled-dimmed` и
`same-list-resent` побайтно равны). Другой список — пересборка с выбором по ключу; пропавшая выбранная вкладка
отдаёт выбор предыдущей. `draw(token)` возвращает `form::min_width()` своей страницы — меню держит по ней минимум
окна (колонка навигации, отступы страницы и окна — измеренные) и раздвигает окно при входе, как для Player.
`fixed_tab_labels()` — подписи постоянных вкладок, чтобы владелец мог развести совпадения. Владелец в плагине —
`src/lua/lua_tabs` (вкладки скриптов, `tw.ui`): страницы — формы `ui/form`, по одной на вкладку.

**Окна** — меню и панель неба: `paint::window_begin`, перетаскивание за заголовок — `interact(...,
placement::overlay)` по прямоугольнику заголовка, крестик — `close_button_rect` + `interact` + `channel` +
`close_button`, уголок — `resize_grip_rect` + `interact` + `resize_grip`.

Строки «подпись + контрол» во всех вкладках — `label_row` (Tweaks, Settings, Skybox, Mods в меню трека) или
`label_block` (теги).

## Иконки: `tw::ui::image::svg`

SVG-иконки лежат в `TweakerPlugin/assets/icons/*.svg`, пакуются в PE как ресурсы типа `TW_SVG`
(`resource::type::vector`, см. `src/resource/CMakeLists.txt`) и растеризуются **LunaSVG** — подтягивается
CMake-ом через `FetchContent` (тег `v3.5.0`, см. `cmake/LunaSVG.cmake`; клоны лежат в
`TweakerPlugin/.deps/<генератор>/`, общие для всех build-деревьев на одном генераторе).

В отличие от `ui/texture_cache` (растр, ленивая загрузка, одна текстура на ассет), этот модуль **запекает всё
сразу**: на первом кадре после привязки устройства каждый упакованный SVG растеризуется в набор фиксированных
размеров, так что вызов на отрисовке — поиск по хэшу, а не растеризация.

```cpp
#include "ui/image/svg.hxx"

const auto icon = tw::ui::image::svg::get_resource("icons/skin.svg");
paint::icon(draw, icon.sz16, icon_min, 16.f, theme::text_primary);

// Размер вне k_baked_sizes - растеризуется при первом запросе и дальше живёт в кэше:
const ImTextureID big = icon.at(64);
```

### Правила

1. **Ключ — полный путь ресурса**: `"icons/skin.svg"`, как у `tw::resource`. Промах даёт пустой `image` со
   всеми полями `ImTextureID_Invalid` — `paint::icon` на таком ничего не рисует, отдельная проверка не нужна.
2. **Не кэшировать `image` между кадрами.** Поля `sz16/sz24/sz32` — снимок: при смене D3D9-устройства все
   `ImTextureID` протухают, репозиторий перезапекается. Звать `get_resource()` там, где рисуют (поиск без
   аллокаций). Виджеты хранят **ключ** (`button::set_icon`, `segmented::set_icons`).
3. **Запечённые размеры** — `k_baked_sizes` = `{16, 24, 32}`, единственный источник правды; поля
   `sz16/sz24/sz32` привязаны к нему `static_assert`-ом.
4. **Ассеты монохромные**: белая заливка/обводка + альфа, `viewBox="0 0 24 24"`, только пути, без текста,
   фильтров и внешних ссылок. Цвет даёт тон на отрисовке, поэтому иконка сама следует теме и fade.
5. **Слоты — под запечённые размеры** и на целом пикселе (`paint::icon` привязывает позицию вниз): тогда ImGui
   не пересэмплирует текстуру. `pins` — строка 28 px, слот 16; `notefeed` — слот по высоте строки текста
   (`at(icon_px)`).

### Жизненный цикл

| Вызов | Где | Что делает |
|-------|-----|------------|
| `initialize()` | `tw::ui::initialize()` (поток загрузки) | Индексирует ключи. GPU не нужен. |
| `update()` | первым делом в `ui_main::draw_frame()` | Запекает всё, если есть привязанный рендерер и стоит dirty. Иначе — одна проверка `bool`. |
| `invalidate()` | `imgui_backend::initialize()`, рядом с `texture_cache::clear()` | Устройство сменилось: сбрасывает хэндлы (без `release` — старое устройство уже унесло свои текстуры) и ставит dirty. |
| `shutdown()` | `tw::ui::shutdown()`, **до** `imgui_backend::shutdown()` | `release()` всех текстур, пока устройство ещё живо. |

`smoke_test` проходит ровно ту же последовательность на OpenGL — рендер-специфична только пара функций в
`ui/gpu_texture`. Загрузка текстуры посреди кадра в GL требует плотной распаковки: `smoke/gl_texture.cxx` сам
выставляет `GL_UNPACK_*` и возвращает прежние (вендорный бэкенд после дозагрузки атласа шрифтов оставляет
`ROW_LENGTH` = ширине атласа — сцена `late-icon`).

### Качество на мелких размерах

`k_supersample_factor` в `src/ui/image/svg.cxx` (по умолчанию `1`) переключает «рендерить сразу в целевой
размер» и «рендерить в N раз крупнее + `stbir_resize_uint8_srgb`». LunaSVG делает аналитический AA, поэтому
для простых путевых иконок прямой рендер не хуже, а чаще чётче. Ветка оставлена на случай детальной графики.

### Добавить иконку

1. Положить `.svg` в `assets/icons/` (монохром, правило 4).
2. Пересобрать — `.rc`-генератор подхватит файл через `CONFIGURE_DEPENDS`, ключ = путь относительно
   `assets/`.
3. Если это иконка твика — прописать её в `overlay_state::tweak_icon_key()`, единственном месте маппинга
   `tweak_id` → иконка.

## Вложенность и раскладка

- Абсолютно поставленное (`SetCursorScreenPos`) закрывается `Dummy` на занятый прямоугольник — иначе родитель не
  знает, сколько места занято, а ImGui предупреждает о расширении границ.
- Не занимать место дважды: `Dummy(full)` и потом `BeginChild` той же высоты без `SameLine` — удвоенная высота и
  вечный скроллбар.
- Высота «до низа» — `GetContentRegionAvail().y` **после** заголовка; футер под списком резервируется заранее и
  точно (`player.cxx` `footer_height()`): занижение на пару пикселей даёт постоянный скроллбар, который ещё и
  съедает ширину у строк.
- Внутри страницы `tab_view` своё дочернее окно с прокруткой не нужно: страница прокручивается сама, а
  скроллбар вложенного окна встанет вплотную к контролам у правого края.
- `label_row`/`label_block` используют приём `Dummy(подпись) + SameLine(0, 0) + SetCursorScreenPos(контрол)`:
  высота строки ImGui тогда покрывает и подпись, и контрол, какой бы ни был выше.

## Снимочный стенд

`smoke_test` в режиме снимков — офлайн-проверка всего, что в `tweaker_ui`: каждый виджет во всех состояниях,
рецепты `paint`, меню и плеер целиком, попапы, раскадровки жестов. Аналог `Tools/UiStand` для TweakerUI.

```
cmake --build --preset x86-release --target smoke_test        (из TweakerPlugin/, окружение amd64_x86)

build\x86-release\bin\tweaker_ui_smoke.exe                      интерактивное окно
build\x86-release\bin\tweaker_ui_smoke.exe --list               сцены
build\x86-release\bin\tweaker_ui_smoke.exe --shots <dir> [--filter <часть имени>]
build\x86-release\bin\tweaker_ui_smoke.exe --compare <до> <после> [--diff <dir>]
```

Коды возврата: 0 — успех или полное совпадение; 1 — сцена упала или каталоги различаются; 2 — неверные
аргументы или окружение. Карта различий: совпавшие пиксели — тусклая копия «до», различающиеся — пурпурные.

**Как работать.** Перед правкой — снимки базы на текущем дереве; после — снимки ещё раз и `--compare`. Каждый
изменившийся снимок разбирать **вблизи** (кроп с увеличением), а не довольствоваться «изменение ожидаемое»:
полоса под заголовком попапа была видна на кадре, который сам вошёл в страницу сравнения как показательный.
Два прогона подряд должны совпадать побайтно.

**Устройство** (`TweakerPlugin/smoke/`):

- `shots.{hxx,cxx}` — разбор аргументов, исполнитель сцены (скрытое окно, GL-контекст, FBO, `glReadPixels`),
  PNG через `miniz`, сравнение через `stb_image`. `scene.hxx` — интерфейс сцены, `scenes.cxx` — сцены и их
  реестр. `fake_host` — поддельные данные хоста и Quick Player, `gl_texture` — загрузка текстур.
- **Каждая сцена — отдельный процесс** (`--shots` запускает `--scene <имя>` по процессу): меню и плеер держат
  состояние в глобалах файла, и сцена после другой унаследовала бы её вкладку, анимации и попапы.
- **Детерминизм:** `io.DeltaTime = 1/60` (не делится на целые миллисекунды — перенос остатка в `dt_ms`
  работает как в игре), ввод только от сценария, без `overlay_config::load` (значения по умолчанию, `flush()`
  ничего не пишет), шрифт 18 px, стиль — `theme::apply_to`. Программный курсор меню перед `Render`
  выключается.
- **Сцена** — `{ имя, описание, холст, setup, frame }`. В `frame` сцена рисует своё и по номеру кадра
  управляет вводом через `scene_ctx`: `mouse_move(pos | метка, rel)`, `mouse_button`, `mouse_wheel`, `key`;
  `mark(метка[, rect])` / `rect` / `point` — свои элементы; `window(часть имени)` — окна модулей (меню и плеер
  отметить изнутри нельзя, ориентиры — их окна и дочерние окна: `##qp_tracks`, `##list`, `##tw_popup_…`);
  `capture(имя)` — снимок `<сцена>-<имя>.png`; `finish()`.
- **Ввод, поданный на кадре N, срабатывает на кадре N + 1** — события идут в очередь ImGui, как настоящие между
  кадрами. Отпускание на кадре 15 — клик на кадре 16; снимок «сразу после клика» — на 16.
- Константы раскладки `tab_view` продублированы в `scenes.cxx` (`k_tab_nav_pad`, `k_tab_height`, `k_tab_gap`):
  поменял их в виджете — поправь сцены в той же правке.

**Сцены.** Стендовые — по виджету (`button`, `toggle`, `segmented`, `slider`, `list-view`, `tab-view`,
`popup-menu`, `color-field`, …), рецепты (`paint-*`, `draw-helpers`, `gradient-polyline`, `glow-clip`), поведение
(`slider-escape`, `tab-view-back`, `tab-view-overflow`, `list-view-refresh`, `disabled`, `popup-anchored`,
`interact-covered`, `interact-fading-page`, `late-icon`). Форма — `form-controls`, `form-events`,
`form-program-set`, `form-disabled`, `form-narrow`, `form-tooltip` (страница вкладки с формой, а под ней — журнал
событий формы: то, что картинка иначе не показала бы), и `item-group-fill`. Динамические вкладки меню —
`menu-dynamic-tabs` (раскадровка: добавление под выбранной, удаление выбранной, переименование и приглушение,
повторная отправка того же списка изнутри страницы, рост окна под широкую страницу). Модульные — статика оверлея, вкладки меню, офлайн,
переход вкладок, строки треков, меню трека, попап персонажа. Полный список — `--list`.

**Чего стенд не видит:** вкладки Scripts и Skybox и панель неба живут в DLL. Их строки и хром — рецепты
`paint`, которые стенд снимает напрямую; собранные вкладки проверяются в игре.

Интерактивное окно (без аргументов) — `fake_host` и все модули оверлея плюс окно `Smoke controls` с группами
`Controls`, `Icons`, `Color`; vsync включён (`wglSwapIntervalEXT(1)`), чтобы анимации шли в игровом темпе.

## Новый виджет или рецепт

1. Сначала проверить, не собирается ли нужное из `kit` без класса (раздел «Самописные места»). Новый виджет
   заводится ради состояния, а не ради отрисовки.
2. `widgets/foo.hxx` + `foo.cxx` (или функция в `kit/paint`) в стиле существующих: snake_case, `m_`, namespace
   `tw::ui::widgets` / `tw::ui::kit::paint`, без PCH — системные заголовки явно.
3. Добавить `.cxx` в `tweaker_ui` (`src/ui/CMakeLists.txt`).
4. Ввод — `interact`, анимация — `channel`, отрисовка — рецепты `paint`, числа — `theme::space`/`radius`/`motion`.
5. Флаги кадра сбрасывать в начале `update()`; программная установка — no-op при том же значении и без
   `changed()`; если есть «пользователь закончил» — отдельный `committed()`.
6. Сцена стенда: состояния покоя, наведения, нажатия, выбора, выключенности, середины переходов; для жестов —
   раскадровка.

## Чеклист «ведёт себя странно»

| Симптом | Что проверить |
|---------|----------------|
| ImGui: `Missing EndChild` / `PopID` | Пара `begin`/`end` у `tab_view`, `item_group`, `popup_menu`; `scroll_body_end` при `false` от `begin`; ранний выход из отрисовки мимо `end()` |
| ImGui: `SetCursorPos extend boundaries` | После абсолютного курсора нужен `Dummy` на занятый прямоугольник |
| Вечный скроллбар | Место занято дважды; футер не зарезервирован или зарезервирован неточно |
| Элемент «мигает» или отстаёт при смене вкладки / fade попапа | Цвет мимо `paint` (альфа стиля не применена) или применена дважды |
| Строка подсвечивается под чужим окном или на уходящей странице | Наведение не через `interact`/`hovering` |
| Нет анимации после `set_*` | Значение не изменилось (no-op), `update()` не вызывается, или `step()` не читается каждый кадр |
| Анимация «въезжает» при первом показе / смене данных | Нужен `snap`, а не `set` (изменение не от пользователя) |
| Тема «не применяется» | Закэширован `ImU32`; для стоковых элементов ImGui — не вызывается `sync_colors` |
| Скроллбар вплотную к контролам | Своё дочернее окно с прокруткой внутри страницы `tab_view` |
| Свечение обрезано по прямой | Нет места `glow_reach` внутри отсечения |
| Иконка мыльная | Позиция не на целом пикселе или размер не запечённый |
| Попап сразу закрывается после открытия | Открывающий клик попал в закрытие (пропуск кадра встроен); `close()` в том же кадре |
| Попап ловит клики во время исчезновения | После закрытия должен стоять `NoInputs` |
| Кнопки «мёртвые» / чужой hit-test | Коллизия `id`; забытый `PushID`/`PopID`; выключено через `set_enabled` или `BeginDisabled` |
