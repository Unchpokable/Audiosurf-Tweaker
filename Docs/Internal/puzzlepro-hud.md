# PuzzlePRO HUD 1.8: песня, цветная миникарта, цветные фичи

Руководство по версии 1.8 скрипта `TweakerPlugin/assets/script-projects/puzzlepro_hud` и по тому, что ради неё
сделано в самом плагине. Вырос из плана, выполненного и принятого владельцем 29.10.2026: решения владельца — §8,
несделанное и отложенное — §7, коротко о том, как шли шаги, — §9.

**Почему HUD устроен именно так, записано в `docs/DESIGN.md` проекта** (§11 миникарта, §12 бейдж песни, §13 нижняя
полоса, §14 настройки, плюс строка про `Do_OverheadMap` в §3). DESIGN.md вшит в собранный скрипт и едет с ним, так
что он — источник правды по самому скрипту. Здесь — то, чего в нём нет: что для HUD доделано в плагине, что в каком
файле, откуда данные и как это проверять.

PuzzlePRO HUD — экспериментальный мод: ему можно поднимать `@api` до последнего и пользоваться свежими функциями.
Чего не хватает в API, доделывается в плагине, а не обходится в скрипте. Версия 1.8 требует API 4.

## 2. Что в каком файле

### Скрипт (`src/`)

| Модуль | Что делает |
|---|---|
| `song.lua` | название и исполнитель: чтение раз в 30 кадров и на хуках начала заезда, вырезание тегов `[as-…]`, «Unknown Artist» → нет исполнителя |
| `track.lua` | профиль трассы: 256 точек высоты 0…1 и время, читается по 128 точек за кадр; номер кольца игрока с дробью, «осталось» |
| `scan.lua` | (было) знаменатели таблицы; (новое) счётчики пяти цветных корзин на отрезок по 16 колец (`FINE`), `totals.fine`, `totals.revision` |
| `map_colours.lua` | точки градиента и цвет каждой вершины ломаной; `configure(batch, softness, value)` из настроек |
| `draw/minimap.lua` | две `gradient_polyline` (пройденное с альфой 0.35 и впереди), точка игрока, «осталось» |
| `draw/stats_panel.lua` | панель верх-лево: фон, таблица, карта; уезжает под ленту уведомлений через `roll` |
| `draw/colour_table.lua` | таблица, теперь рисуется в отданную рамку (`height`, `draw(L, x, y, width)`) |
| `draw/song_badge.lua` | бейдж: логотип в кольце, название, волосяная линия, исполнитель; ширина и обход пинов |
| `draw/fitted_text.lua` | строка в рамке: как есть, многоточие или бегущая строка поглифово с мягкими краями |
| `draw/chain_block.lua` | `band_height` (высота полосы), `max_half_width` (предел бейджа), цвета фич (`FEAT_COLOUR`) |
| `draw/rating.lua` | центрирован по высоте полосы |
| `settings.lua` | вкладка, чтение и запись `settings.json`, раздача значений модулям |
| `palette.lua` | `mono()` — цвет единственной цветной колонки, для Stealth и Mono-карты |
| `channels.lua`, `mutes.lua` | каналы `Highway`, `Player`, `StartGroup` (§3); мьют `XX_gui::Do_OverheadMap` |

## 3. Откуда данные

### Песня

`StartGroup` (= `XX_StartHere.cgr`): `CurrentSongTitle` (#3162), `CurrentSongArtist` (#3168). Их же рисует игровой
`Do_ShowSongName` через `Texter_Unicode`. Пишут их загрузчики песни (`VisMusic` #251/#260/#261, `CDBrowser`
#444/#445, `RadioBrowser`, туториал); «Unknown Artist» — `VisMusic` #252.
(`cgrpy query writers StartGroup CurrentSongTitle`)

- **В названии теги.** Игра дописывает свои (`XX_StartHere` #6835…#7147, `" [as-steep]"`, `" [as-portal]"`), автор
  файла — свои (`[as-monoonly]`, читает `Do_ForceCharacterChanges`). Пример из пробы:
  `"Drive my Life [as-steep] [as-prows1] [as-monoonly] [as-allgrey]"`. Вырезаются шаблоном `%s*%[as%-[^%]]*%]`.
- `tw.string_ch` отдаёт UTF-8 (`fam_text.cxx` спрашивает `GetIfUseWChar` и конвертирует), кириллица доходит до Lua
  целой. На экране латиница, кириллица и греческий есть (Roboto, ImGui 1.92 грузит глифы по требованию), CJK нет (§7).

### Трасса

Игровая карта — `XX_gui::Do_OverheadMap` #4147 → `Do_RenderTrackSideView` #4808: боковой профиль трассы, высота
кольца по его номеру. Мы берём то же из `Highway` (`cgrpy query find "^Rings: |NumRings|RingYpos|RingIndex" --group Highway`):

| Канал | Что |
|---|---|
| `NumRings` #65 | число колец |
| `Rings: Pos` #182, курсор `RingIndex` #193 | `tw.array_vec`, `y` — высота профиля |
| `LowestRingYpos` #469, `HighestRingYpos` #505 | нормировка высоты |
| `Rings: SongTime` #320 | время кольца, секунды |
| `Player::OffsetCurrentRing` #695, `OffsetCurrentRingInterpolation` #711 | кольцо игрока и дробь к следующему |

`RingIndex` — общий курсор нескольких групп; `array:get` сохраняет и восстанавливает его, чтение безопасно.

**Цвет живёт на той же оси.** `y` строки `StatCollector::Stats: TrafficPattern` — номер кольца:
`TrafficCommander::Do_BirthCar` пишет `RingToDieAt := y(TrafficPattern)` (#713)
(`cgrpy query writers TrafficCommander RingToDieAt`). Поэтому раскладку блоков по кольцам `scan.lua` получает тем же
проходом по трассе, что и знаменатели таблицы, без лишних чтений.

### Что показала проба (28.10.2026)

| Вопрос | Ответ |
|---|---|
| Когда кольца готовы | на **всех трёх** хуках начала заезда (`Do_ResetStats`, `Do_ReseteWhiteWildBlocks`, `Do_ResetSimpleStats`), включая первый; `rows()` обеих таблиц = `NumRings`. Профиль сканируется по тем же хукам, что и знаменатели |

| Mono по тегу | `[as-monoonly]` даёт `Ninja? = 1` |

## 4. Цвет карты

Как сделано (почему так — DESIGN.md §11):

1. Блоки трассы ложатся в мелкие отрезки по 16 колец, по пять цветных корзин на отрезок. Камень/белый и wild не
   считаются. Мелкая сетка нужна, чтобы смена «колец на отрезок» в настройках пересобирала градиент без нового
   прохода по трассе: отрезок настройки — целое число мелких, значение округляется до кратного 16.
2. Каждому отрезку (`batch` колец, по умолчанию 96) — точка градиента в его центре. Вес цвета — **число блоков ×
   цена блока** (`StatCollector` ChannelSwitch #128: 1, 2, 3, 5, 8 от фиолетового к красному; меняется в настройках).
3. Соседи: окно `±floor(softness·2 + 0.5)` отрезка с убывающим весом. Заострение: вес в степени `8 − 6·softness`
   (8 при мягкости 0, 2 при 1). Отрезок с одной корзиной — её цвет без смешения.
4. Цвета берутся из живой палитры (`palette.lua`), пересчёт — при смене палитры или нейтрального цвета.
5. Цвет вершины ломаной — интерполяция между ближайшими точками градиента по номеру кольца. 256 вершин и сколько
   угодно точек развязаны: размер отрезка не меняет геометрию.
6. **Mono, Ninja, Freeride, песни с тегом** — когда у трассы ровно одна цветная корзина, карта целиком цветом
   `palette.mono()`. Условие выводится из данных, а не из таблицы режимов, так что все эти случаи покрыты разом.

**Первая версия цвета не прошла:** фиолетовый перевешивал, а жёлтое с красным становилось светло-зелёным. Блоки
считались поштучно (фиолетовых на любой трассе больше всех), а смешение было мягким (степень 2.5, окно ±2 отрезка):
точка получалась средним четырёх цветов, а среднее в RGB даёт цвет, которого на трассе нет. Отсюда цены блоков,
крутая степень и узкое окно.

## 5. Что доделано в плагине

### 5.1 `tw.hud.polyline` и `tw.hud.gradient_polyline` (API 4)

```lua
tw.hud.polyline(xs, ys, colour, thickness, closed)
tw.hud.gradient_polyline(xs, ys, colours, thickness, closed)
```

Общие примитивы, не под миникарту. До 4096 точек (`hud_polyline_max_points`).

- **Пролог** копирует таблицы в FFI-буферы, которые только растут, — в установившемся режиме ни одной аллокации за
  кадр. Ошибки аргументов — на строке скрипта (уровень 3).
- **C** собирает путь в `_Path` списка отрисовки, нечисловые координаты отвергает.
- **Перекраска** (`ui::kit::paint::add_gradient_polyline`): `AddPolyline` рисует белым, затем каждая добавленная
  вершина умножается на цвет своей точки; альфа AA-бахромы сохраняется. Опирается на то, как ImGui 1.92 кладёт
  вершины: с AA — 2, 3 или 4 вершины на точку по порядку точек (текстурные линии, тонкие, толстые), без AA — 4 на
  сегмент `[i, i+1, i+1, i]`. Число добавленных вершин сверяется с этими формами; не совпало — вся линия цветом
  первой точки, функция возвращает `false`. Так сохраняется качество AA ImGui без своей тесселяции.
- Учёт места в HUD (`lua_hud_space`) работает сам: он меряет вершины любого вызова.

**Ловушка при обновлении ImGui:** раскладка вершин `AddPolyline` — внутреннее поведение, не API. После обновления
ImGui снять сцену `gradient-polyline` (`smoke_test --shots … --filter gradient`): там все четыре пути, замкнутый
контур и альфа по точкам. Одноцветная линия на снимке — раскладка поменялась.

### 5.2 Живая рамка ленты уведомлений

Раньше лента отдавала скриптам (`widget("notefeed")`, `occupied`, `place`) **фиксированный резерв** на шесть строк,
даже пустая, — панель стояла под пустым местом. Теперь — объединение рамок нарисованных тостов
(`notefeed::last_rect`), `nil`, когда тостов нет. `safe()` остаётся на резерве (`reserved_rect`). Решение владельца —
«живая рамка везде».

Скрипты рисуются **после** ленты, поверх тостов (`ui_main`: водяной знак, пины, лента, меню, затем скрипты), —
поэтому панель уступает ленте, а не игнорирует её.

## 6. Как проверять

- **Скрипт.** Правится проект, не собранный файл: `twllink --project . --out ../../scripts/puzzlepro_hud.lua` из
  папки проекта, бандл и `.lua.map` — в том же коммите (иначе `ShippedProjectsTests`). В игру —
  `twllink --project . --install` с `AUDIOSURF_DIR`.
- **`harness/lua/ljtest`** гоняет бандл на поддельной трассе (64 кольца, высота по косинусу, 0.5 с на кольцо, игрок
  на 32.5) и поддельной песне: карта — две ломаные с разбиением по игроку, пройденное тусклее, «осталось 0:16»;
  бейдж — теги вырезаны, исполнитель есть, логотип нарисован, «Unknown Artist» скрыт, длинное название идёт
  поглифово и после паузы сдвигается; цепочка не наезжает на соседей в узком окне. `harness/` вне истории — заглушки
  только у тех, у кого он есть.
- **`TweakerLuaLinker.Tests`** — `ShippedProjectsTests` (бандл совпадает с проектом), `DocsTests` (ссылки и картинки
  мануалов).
- **Стенд** — `smoke_test --shots`, сцена `gradient-polyline`.
- **Цена** в игре — чип вкладки Scripts: 0.058–0.067 мс на кадр с картой (было 0.04–0.09; Ryzen 7 9800X3D).

## 7. Не сделано и отложено

- **Бегущая строка в игре не проверена**: на 2K-мониторе не нашлось названия, которое не влезло бы. Проверена
  только в `ljtest`.
- **Туториал.** План предполагал не рисовать карту там, где её не рисует игра (`StartGroup::isTutorial?`), —
  отдельной проверки нет. Как HUD выглядит в туториале, не смотрели.
- **Несовпавшая раскладка вершин** в `gradient_polyline` не пишется в лог, как предполагал план, — только
  одноцветная линия и `false` из рецепта (§5.1).
- **Не-латиница вне Roboto (CJK).** Направление: скрипт грузит свой шрифт из своей папки `ScriptData` (ExoSoft,
  Noto) — `tw.hud.load_font(name, file)` в пределах `tw.storage`, имя становится допустимым `font` для
  `tw.hud.text`/`measure`. В ImGui 1.92 шрифт можно добавить после старта, если бэкенд умеет
  `RendererHasTextures` — проверить у нашего DX9. Шрифт кладёт пользователь, пока не ясна лицензия.
- **Заливка под кривой** тем же градиентом — нужен третий примитив (полоса с цветом на вершину).
- **Цветной логотип.** SVG растрируется LunaSVG со своими цветами, `tint` только умножает (`src/ui/image/svg.cxx`):
  цветной вариант — тот же файл с цветами и белый тон, без правок API. Мастер для перерисовки —
  `textures/TweakerIcon-1.png`.
- **Расхождение в документации про кириллицу.** `Docs/scripting/menus.md` («Latin text only… Cyrillic draws as `?`»)
  и скиллы AgentKit (`audiosurf-grill`, `tweaker-lua-api`) пишут, что кириллицы в оверлее нет, а снимок стенда
  `draw-helpers` рисует её нормально. Не правилось: AgentKit — зона своей сессии, решение за владельцем.

## 8. Решения владельца (28.10.2026)

1. Карта — градиентом: каждому отрезку трассы — точка цвета, который на отрезке преобладает. Размер отрезка и
   мягкость — настройки.
2. Смешение — взвешенное с заострением, камень/белый не участвует. Mono/Ninja — карта целиком цветом, которым
   таблица рисует цветные блоки.
3. Логотип — монохромный SVG для начала, цветной — возможно позже.
4. Делаем `tw.hud.polyline` и `tw.hud.gradient_polyline`.
5. Лента уведомлений — подстраиваться под её реальное место (позже: живая рамка везде, §5.2).
6. Бейдж и рейтинг — во всю высоту блока цепочки.
7. Фон-панель у бейджа и у панели «статистика + карта».
8. Бейдж адаптивный; упирается в максимальное место цепочки — многоточие или бегущая строка.
9. Не-латиница — пока Roboto, дальше вплоть до своих шрифтов скрипта.
10. Stealth — цвет Mono (`GlobalMonoColor`), Mono Special — `TEXT`.
11. «Осталось m:ss» — да; вкладка настроек — да, поднимать `@api` можно.
12. Веса цветов карты — в настройки (после первой версии цвета, §4).
