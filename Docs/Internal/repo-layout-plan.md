# Суб-репозитории и релизный канал организации — план

**Статус (15.11.2026):** план согласован владельцем (решения — §2); Ф0–Ф2 выполнены
15.11.2026 и ждут осмотра организации владельцем. Работа идёт фазами §6, каждая заканчивается
приёмкой владельца; итоги фаз записываются в §10. Нормативные правила работы — [AGENTS.md](../../AGENTS.md)
и [Docs/AgentWorkflow](../AgentWorkflow/README.md); этот документ описывает конкретную работу.

**Что это.** Приложение остаётся одним репозиторием (`Unchpokable/Audiosurf-Tweaker`) с одним
`.sln`, одним `Deploy` и одним релизом. Сопроводительные материалы, которые поставляются вместе
с приложением, выносятся в самостоятельные репозитории организации
[Audiosurf-Tweaker](https://github.com/Audiosurf-Tweaker) и подключаются в приложение сабмодулями.
Там же появляется канал экспериментальных сборок приложения (RC, alpha, экспериментальные ветки),
которых не будет в личном репозитории. Приватным остаётся ровно один репозиторий — native harness.

## 3. Целевая раскладка

### 3.1 Репозитории

| Репозиторий | Видимость | Что внутри | Точка монтирования в приложении | Ветка | Релизы |
|---|---|---|---|---|---|
| `Audiosurf-Tweaker/Audiosurf-Tweaker` | public | копия приложения: `Revive` → `main`, экспериментальные ветки, pre-releases | — (это само приложение) | `main` | RC/alpha/experimental (pre-release) |
| `Audiosurf-Tweaker/harness` | **private** | native harness и перенесённые пробы | `TweakerPlugin/harness/` | `main` | нет |
| `Audiosurf-Tweaker/ScriptProjects` | public | контейнер: README, `.gitignore` (`/dev/`), сабмодуль `puzzlepro_hud` | `ScriptProjects/` | `main` | нет |
| `Audiosurf-Tweaker/puzzlepro_hud` | public | исходник скрипта: 17 модулей, `docs/DESIGN.md` | `ScriptProjects/puzzlepro_hud/` | `main` | `vX.Y.Z`: `puzzlepro_hud.lua` + `.lua.map` |
| `Audiosurf-Tweaker/Skyboxes` | public | контейнер: README, `.gitignore` (`/dev/`), сабмодуль `Canvas.sky` | `Skyboxes/` | `main` | нет |
| `Audiosurf-Tweaker/Canvas` | public | пакет неба, **корень репозитория = корень пакета** | `Skyboxes/Canvas.sky/` | `main` | `v1.0.0`: `Canvas.sky` (zip) |

`Canvas.sky` в точке монтирования сохраняет суффикс `.sky`: плагин опознаёт пакет по расширению
записи в `Skyboxes\`. Имя репозитория при этом короткое — `Canvas`; имя пути и имя репозитория
не обязаны совпадать. Путь монтирования вложенного сабмодуля задаётся при `git submodule add`.

Общий вид организации:

```
github.com/Audiosurf-Tweaker
├─ Audiosurf-Tweaker      канал: main = Revive, exp/*, pre-releases
├─ harness                private
├─ ScriptProjects
│  └─ puzzlepro_hud
└─ Skyboxes
   └─ Canvas              монтируется как Canvas.sky
```

Имя `Audiosurf-Tweaker/Audiosurf-Tweaker` — рабочее; его можно поменять до первого пуша без
последствий. Если меняется, меняется и URL в §4.2.

### 3.2 Дерево приложения после перестройки

```
Unchpokable/Audiosurf-Tweaker          (публичный, Revive, «монолит приложения»)
├─ TweakerUI/  TweakerCore/  ASBridge/  AudiosurfInterface/  ...
├─ TweakerPlugin/
│  ├─ src/  assets/  cmake/  probe/  smoke/ ...
│  └─ harness/                 → submodule  harness      (private, update = none)
├─ ScriptProjects/             → submodule  ScriptProjects
│  ├─ dev/                     (gitignored — только локально)
│  └─ puzzlepro_hud/           → submodule  puzzlepro_hud
├─ Skyboxes/                   → submodule  Skyboxes
│  ├─ dev/                     (gitignored)
│  └─ Canvas.sky/              → submodule  Canvas
├─ TweakerPlugin/assets/scripts/puzzlepro_hud.lua + .lua.map   (собранный бандл остаётся здесь)
└─ .gitmodules
```

`.gitmodules` после перестройки:

```
[submodule "ScriptProjects"]
	path = ScriptProjects
	url = https://github.com/Audiosurf-Tweaker/ScriptProjects.git
	branch = main
[submodule "Skyboxes"]
	path = Skyboxes
	url = https://github.com/Audiosurf-Tweaker/Skyboxes.git
	branch = main
[submodule "TweakerPlugin/harness"]
	path = TweakerPlugin/harness
	url = https://github.com/Audiosurf-Tweaker/harness.git
	update = none
```

`update = none` оставляет ссылку в дереве, но не ломает `git clone --recurse-submodules` у того,
у кого нет доступа к приватному репозиторию: подмодуль пропускается и инициализируется только
явной командой. Существующие записи `TweakerPlugin/Detours` и `TweakerPlugin/LuaJIT` не меняются.

### 3.3 Правила владения и источников правды

- **Личный репозиторий** — источник правды для стабильной ветки: код приложения, тулинг,
  документация, собранные бандлы поставки. Здесь живут сабмодули и указатели на их коммиты.
- **Контентные репозитории** — источник правды для своих файлов. Правка начинается там,
  коммитится и пушится; затем в приложении тем же PR бампается указатель сабмодуля.
- **Канал в организации** — источник правды для экспериментальных веток и pre-releases.
  Его `main` — точная копия `Revive`; прямые коммиты в `main` запрещены, эксперименты живут
  в `exp/*`.
- **`dev/`** не коммитится нигде: это локальная папка автора. Пробы, которые нужны проверкам,
  живут в приватном harness (§2.6).
- **Собранные артефакты** остаются в приложении: `assets/scripts/*.lua` и `.map` — поставляемые
  файлы, их пересборка обязательна при изменении проекта (`ShippedProjectsTests` это проверяет).
- **Указатель сабмодуля** фиксирует ровно ту версию, которая тестировалась и поставлялась.
  «Догоняющий» бамп до `main` без проверки не делается.

### 3.4 Что осознанно не переезжает

- Код приложения, `TweakerUI`, `TweakerCore`, `ASBridge`, `AudiosurfInterface`, `QuickPlayerCore`,
  `TweakerLuaLinker`, `LegacyDataConverter`, `Installer`, `Tools/`, `Docs/` — остаются в монолите.
- Ассеты плагина (`TweakerPlugin/assets/{fonts,icons,shaders,skyboxes,textures}`) — встраиваются
  в DLL, к пакетам и проектам отношения не имеют.
- Шаблоны небес (`TweakerCore/Skyboxes/Templates`) — часть приложения, а не поставляемые пакеты.
- Приватным остаётся только harness: он линкуется с внутренностями плагина и содержит локальные
  тестовые данные. Его существование и контракт описаны в публичной документации.

## 4. GitHub Actions

### 4.1 Вынос компонентов (одноразовый bootstrap)

Задача — получить в организации репозиторий с историей папки, а не снапшот. Для каждой папки:

```
git subtree split --prefix=<папка> -b publish/<имя>
git push https://x-access-token:<token>@github.com/Audiosurf-Tweaker/<repo>.git publish/<имя>:main
```

`git subtree split` даёт коммиты, в которых содержимое папки лежит в корне, — правильная форма
и настоящая история. `git filter-repo` делает то же, но требует установки и переписывает все
хеши; здесь это не нужно. Порядок: сначала вложенные (`puzzlepro_hud`, `Canvas`), затем контейнеры
(`ScriptProjects`, `Skyboxes`); приложение перестраивается после этого (Ф3), а канал создаётся ещё
позже (Ф4).

Workflow: `.github/workflows/publish-components.yml`, логика — `Tools/RepoPublish/publish.sh`,
список компонентов — `Tools/RepoPublish/components.json`.

```yaml
name: Publish component repositories
on:
  workflow_dispatch:
    inputs:
      components: { description: "Пусто = все; иначе через запятую", default: "" }
      dry_run:    { description: "Разложить и проверить, ничего не пушить", type: boolean, default: true }

permissions:
  contents: read

concurrency:
  group: publish-components
  cancel-in-progress: false

jobs:
  publish:
    runs-on: ubuntu-latest
    environment: publish-components      # required reviewer
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }          # subtree split без истории не работает
      - name: Split and push
        env:
          GH_TOKEN: ${{ secrets.ORG_PUBLISH_TOKEN }}
          DRY_RUN:  ${{ inputs.dry_run }}
          ONLY:     ${{ inputs.components }}
        run: bash Tools/RepoPublish/publish.sh
```

Существенные свойства:

- запуск только `workflow_dispatch` — токен не достаётся fork-PR;
- `environment` с обязательным ревьюером — случайный диспатч не опубликует;
- `dry_run` по умолчанию: сначала список файлов и коммитов, потом push;
- защита от повторного запуска: папка уже сабмодуль (`git ls-tree` даёт `160000`) — ошибка;
- защита от перезаписи: в организации уже есть `main` — ошибка, а не force;
- токен: classic PAT со scope `repo` и `workflow` (второй нужен синхронизации канала, §4.2)
  в секрете `ORG_PUBLISH_TOKEN`; срок — на время миграции, затем отзыв. При включённом SSO токен
  надо авторизовать в организации;
- одноразовость: после миграции workflow либо удаляется, либо остаётся с защитой `160000`
  и инструкцией «как вынести новую папку» (рекомендуется оставить).

Workflow не выносит harness: harness не в git, а временный коммит в публичный монолит навсегда
опубликовал бы приватный код в истории. Harness создаётся локально (§6, Ф2).

### 4.2 Канал приложения в организации

`Audiosurf-Tweaker/Audiosurf-Tweaker` — не зеркало всех ссылок, а канал:

- `main` — fast-forward копия `Revive`;
- `exp/*` — экспериментальные ветки, создаются в организации от `main`, обратно не сливаются;
- теги: стабильные приходят из личного репозитория, RC/alpha создаются только в организации;
- issues, PR, релизы, секреты и wiki не синхронизируются: релизы создаются в каждом репозитории
  отдельно.

Workflow: `.github/workflows/sync-org.yml` в личном репозитории.

```yaml
name: Sync the organization channel
on:
  push:
    branches: [Revive]
  workflow_dispatch:
    inputs:
      dry_run: { type: boolean, default: true }

permissions:
  contents: read

concurrency:
  group: sync-org
  cancel-in-progress: false

jobs:
  sync:
    if: github.repository == 'Unchpokable/Audiosurf-Tweaker'
    runs-on: ubuntu-latest
    environment: publish-components
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: Fast-forward main and add missing tags
        env:
          GH_TOKEN: ${{ secrets.ORG_PUBLISH_TOKEN }}   # нужен scope workflow: синхронизируются .github/workflows
        run: bash Tools/RepoPublish/sync-org.sh
```

Свойства и ограничения:

- push **только fast-forward**, без `--force`: если в организации кто-то закоммитил в `main`
  напрямую, синхронизация падает и это видно — так и задумано;
- теги добавляются поимённо и только отсутствующие; существующий тег никогда не перезаписывается;
- токен должен иметь scope `workflow`, иначе push изменённых `.github/workflows/*` отклоняется;
- правила ветки `main` в организации: запрет force-push и удаления, bypass у аккаунта-публикатора;
- guard `github.repository` не даёт workflow сработать в копии организации (там нет ветки `Revive`,
  но guard остаётся вторым рубежом);
- push, сделанный PAT, **запускает** workflow в организации — это ожидаемо: `verify.yml` (§4.3)
  проверяет зеркало;
- README в копии идентичен личному и ссылается на личные релизы. Информация о канале живёт
  в описании репозитория, закреплённом обсуждении и release notes, а не в README: иначе каждая
  синхронизация затирала бы его. Правка README в копии запрещена.
- если `Revive` когда-нибудь переименуют в `main` (ветка временная, §2.4), триггер и guard
  обновляются в том же изменении.

### 4.3 Постоянный CI

| Где | Что | Зачем |
|---|---|---|
| приложение | `verify.yml`: checkout без `--recurse-submodules`, затем `git submodule update --init --recursive ScriptProjects Skyboxes`; `setup-dotnet 10.0.x`; `TweakerCore.Tests`, `AudiosurfInterface.Tests`, `QuickPlayerCore.Tests`, `TweakerLuaLinker.Tests` | публичные сабмодули достаются явно, приватный harness не нужен; native/harness/игра в CI не гоняются |
| приложение | удалить `build.yml` (SonarCloud на мёртвом `master`) | устарел, нормой проверки не является |
| `Canvas` | `release.yml` на тег: `zip` содержимого без `.git*` и `.github/` → ассет `Canvas.sky` | «зайти и скачать релиз» |
| `puzzlepro_hud` | `release.yml` на тег: checkout приложения на ref из входа (по умолчанию `Revive`), собрать `twllink`, собрать проект, проверить `version` == тег, приложить `.lua` + `.lua.map` | живой артефакт для авторов |
| `harness` | нет CI | нужны Windows SDK, DirectX-устройство и игровые фикстуры; прогон ручной |

`verify.yml` в организации (после §4.2) запускается на push в `main` — это проверка зеркала.
Нативные проверки и проверка в игре остаются за владельцем.

### 4.4 Экспериментальные сборки

Назначение канала (§2.3): RC, alpha и экспериментальные сборки, которых нет в личном репозитории.

- Ветки `exp/<тема>` создаются в организации от `main`; PR — внутри организации.
- Теги pre-release: `vX.Y.Z-rc.N`, `vX.Y.Z-alpha.N`; тег `vX.Y.Z` без суффикса остаётся
  за стабильным релизом личного репозитория.
- Workflow `release-experimental.yml` лежит в личном дереве (чтобы переживать синхронизацию),
  запускается только `workflow_dispatch` и только в организации:
  `if: github.repository == 'Audiosurf-Tweaker/Audiosurf-Tweaker'`.
  Входы: `ref`, `tag`, `title`, флаг `prerelease`.
- Что собирает hosted-runner: managed-часть, `asbridge`, инжектор, `twllink`, `LegacyDataConverter`.
  Плагин `TweakerPlugin.dll` **не собирается**: нет DirectX SDK (June 2010) и Quest3D SDK,
  а класть их в кэш раннера нельзя — они не распространяются. Сборка честно помечается
  «UI-only: without the in-game plugin».
- Полная сборка с плагином — отдельное решение (§9): self-hosted runner владельца с SDK
  (риск: публичный репозиторий + self-hosted runner; допустимо только с `workflow_dispatch`,
  protected environment и запретом PR-сборок) либо локальная сборка владельцем и ручная
  загрузка ассета в релиз.
- Стабильные релизы по-прежнему выходят из личного репозитория.

### 4.5 Секреты и права (одно место)

| Секрет | Где | Зачем | Срок |
|---|---|---|---|
| `ORG_PUBLISH_TOKEN` | личный репозиторий, environment `publish-components` | создание репозиториев, push компонентов, sync канала | до конца миграции, затем отзыв |
| `GITHUB_TOKEN` | оба репозитория | `verify.yml`; релиз `Canvas` и `puzzlepro_hud` | штатно |

Организация: разрешить создание репозиториев владельцу, отключить Actions там, где workflow нет,
включить branch protection на `main` публичных репозиториев. Приватный `harness` на free-плане
организации защиту ветки не поддерживает: GitHub отвечает `Upgrade to GitHub Pro or make this
repository public`. Это ограничение плана, а не ошибка настройки.

## 6. Фазы

Работа идёт в ветке `repo/components` от `Revive`; `Revive` не меняется до приёмки. Откат на
любом шаге — удалить ветку и, если репозитории уже созданы, удалить их в организации. Коммиты
и push — по команде владельца, как требует [AGENTS.md](../../AGENTS.md); агент не коммитит по ходу.

### Ф0. Подготовка

- Убедиться, что дерево чистое, а работа по вкладке Skyboxes закоммичена (сейчас `b249a58`).
- `git switch -c repo/components Revive`.
- Подтвердить, что аккаунт — Owner организации, создание репозиториев разрешено, SSO не блокирует PAT.
- Сделать резервную копию `TweakerPlugin/harness` (не в git; ~128 МБ).
- Сверить `Tools/RepoPublish/components.json` с §3.1.

**Готово, когда:** ветка создана, бэкап harness есть, список компонентов подтверждён.

### Ф1. Публикация компонентов

1. Добавить `Tools/RepoPublish/{components.json,publish.sh,README.md}` и `.github/workflows/publish-components.yml`; коммит «Add component publish tooling».
2. Локальный dry-run: `DRY_RUN=1 bash Tools/RepoPublish/publish.sh`; сверить число файлов и историю.
3. Запушить ветку в origin (по команде владельца) и диспатчить workflow: сначала `dry_run=true`,
   затем `dry_run=false`.
4. Проверить: в каждом репозитории число файлов `HEAD` совпадает с числом файлов папки в монолите;
   история непустая; первый коммит — не «Initial commit».
5. В организации выставить description, topics, ветку `main`, protection.

**Готово, когда:** владелец открыл организацию и подтвердил имена, видимость и историю.

**Готово, когда:** Code Review владельца пройден, сборка и офлайн-проверки зелёные.

### Ф4. Канал, CI и процессы

**Готово, когда:** push в `Revive` автоматически обновляет `main` организации; CI зелёный

### Ф5. Приёмка

1. Чистый клон без приватного harness: `git clone --recurse-submodules` проходит, harness

## 7. Риски

| Риск | Решение |
|---|---|
| Публичный репозиторий + приватный сабмодуль: ссылка 404, клон без доступа | `update = none`, явная инициализация публичных сабмодулей, документация; ссылка в никуда принята владельцем (§2.2) |
| `.git`/`.github`/`.tweaker` попадают в поставку | исключения в `TweakerPluginSkyboxes` + тест чистоты пакета + проверка payload в приёмке |
| Тесты падают у того, кто не инициализировал сабмодули | `RepositoryLayoutTests` с действием в сообщении; CI инициализирует явно |
| Повторный publish перезапишет организацию | guard «main уже есть» и «папка уже сабмодуль» |
| Sync затрёт экспериментальные ветки | синхронизируется только `main`, FF-only, без force и без `--prune` |
| Прямой коммит в `main` организации ломает sync | branch protection, запрет force/удаления; sync падает видимо |
| PAT без scope `workflow` не пушит `.github/workflows` | scope проверяется при выдаче токена; ошибка видна в логе |
| Пользователи с выбранным `ODC_VolTex`/`OurDraftsCollides` | `PluginInstallation.RemoveDropped` удаляет нетронутые файлы, которых больше нет в бандле; у выбранного старого неба статус `missing`, надо выбрать `Canvas`; отразить в release notes |
| Экспериментальная сборка без плагина | пометка «UI-only» в release notes; полная сборка — отдельное решение (§9) |
| Расхождение указателя сабмодуля и содержимого | правило «бамп тем же PR»; `ShippedProjectsTests` и `ShippedSkiesTests` в CI |
| Потеря локальных артефактов harness | бэкап до `git init`; артефакты пересобираются |
| Line endings в новых репозиториях | `.gitattributes` (`* text=auto`) с первого коммита |
| Секрет в публичном репозитории | `environment` с ревьюером, одноразовый PAT, отзыв после миграции |

## 8. Приёмка

1. В организации шесть репозиториев по §3.1 с описанием, README, лицензией и защищённой `main`;
   приватный только `harness`.
2. У `Canvas` есть релиз `v1.0.0` с ассетом `Canvas.sky`, который ставится в игру как обычный пакет;
   у `puzzlepro_hud` — релиз с `.lua` + `.lua.map`.
3. `Unchpokable/Audiosurf-Tweaker` остаётся монолитом приложения; `ScriptProjects`, `Skyboxes`
   и `TweakerPlugin/harness` — сабмодули на организацию; `main` организации — fast-forward копия `Revive`.
4. `git clone --recurse-submodules` публичной части проходит без доступа к организации; harness
   документирован и подключается явно.
5. Сборка и четыре тест-проекта зелёные; `DeployDebug` даёт payload ровно с `Canvas.sky`
   и без служебных dot-записей.
6. Игра (проверка владельца): `Canvas` рисуется и настраивается, `puzzlepro_hud` работает,
   ошибки указывают в `src/`.
7. `grep` по старым путям не находит ничего, кроме исторических документов.
8. Новый агент, открыв любой репозиторий, понимает, что это, как собрать и куда коммитить.

## 9. Что решается по ходу

- **Полная экспериментальная сборка с плагином** (§4.4): hosted-runner не имеет SDK. Варианты —
  self-hosted runner владельца (с ограничениями), локальная сборка с ручной загрузкой ассета,
  либо выпуск экспериментальных сборок только managed-части. Решение не блокирует миграцию.
- **Судьба `Revive`**: ветка временная (§2.4). Переименование в `main` — отдельная работа;
  до неё sync триггерится на `Revive`.
- **Имя `Audiosurf-Tweaker/Audiosurf-Tweaker`** фиксируется до первого пуша (§3.1).
- **`Docs/Internal` со старыми путями**: живые руководства правятся, журналы и архив — нет (§5).
