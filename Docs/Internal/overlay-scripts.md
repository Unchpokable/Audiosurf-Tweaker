# Протокол скриптов в `TW_OVL` (`SCRIPT_*`)

**Статус (03.10.2026): реализован с обеих сторон, проверен офлайн и принят владельцем на игре.** Плагин —
`src/lua/lua_remote`, `lua_registry::rescan` (С5a); хост — грамматика `TweakerCore/Scripting/ScriptWire`, состояние
и ожидание подтверждений `TweakerUI/Core/ScriptsOverlayBridge`, транспорт `OverlayHelper` (С5b). Зачем и
почему именно так — `script-manager-roadmap.md` §9, итоги — §9.7 и §9.8; здесь только грамматика и смысл
операций. Транспорт (L1/L2, рукопожатие,
сторож) — `overlay-protocol.md`; эти операции ничего в нём не меняют, как и `QP_*`
(`overlay-quickplayer.md`).

## Для чего

TweakerUI включает и выключает скрипты, перезагружает их после установки и просит плагин перечитать папку
`Scripts\` — пока игра запущена. Плагин в ответ сообщает об **изменениях состояния** скриптов. Живого слежения
нет и не будет: стоимость в мс, ожидание загрузки и прочее покадровое — вкладка Scripts оверлея, а не хост
(решение владельца, `script-manager-roadmap.md` §5 п. 4).

Без игры хост, как и раньше, сам пишет `scripts.cfg` (плагина нет, гонки нет). При запущенной игре без связи
переключатели в TweakerUI заблокированы.

## Токены

- **Файл** — имя файла скрипта в `engine\TweakerStuff\Scripts\` (`puzzlepro_hud.lua`), percent-encoded UTF-8
  (общий кодек `ui/wire_text` ↔ `Uri.EscapeDataString`). Это идентичность скрипта для обеих сторон и для
  `scripts.cfg`. Номер скрипта в реестре плагина живёт один сеанс и на провод не выходит. Сравнение — с учётом
  регистра, как в `scripts.cfg`: имя то, которое вернул листинг папки.
- **Логическое** — `true` | `false`.
- **Статус** — одно слово:

  | Статус | Значит |
  |---|---|
  | `off` | выключен |
  | `running` | включён и загрузился (в том числе пока ждёт загрузки игры) |
  | `failed` | при загрузке упал; сообщение — первая строка ошибки, позиции уже в файлах проекта (карта строк). С `true` — включён (упал при старте игры или при `SCRIPT_RELOAD`); с `false` — просили включить, не вышло: переключатель «отпрыгнул», `scripts.cfg` не тронут |
  | `suspended` | приостановлен бюджетом ошибок или времени; сообщение — причина |
  | `missing` | файла больше нет (пропал при пересканировании); запись в реестре плагина остаётся, номера не сдвигаются |

- **Сообщение** — percent-encoded, обрезается до 400 байт до кодирования. Сообщения держатся короткими не
  из-за транспорта (пайп в режиме сообщений склеивает куски, `script-manager-roadmap.md` §9.1), а потому что
  полный текст и трассировка — вкладке оверлея.

## Операции

| OP | Направление | Токены | Смысл |
|---|---|---|---|
| `SCRIPT_SET` | хост → плагин | `<файл> <логическое>` | Включить/выключить (`registry::set_enabled`): выключение — `on_unload` и снятие подписок, включение — запуск файла с диска. `scripts.cfg` пишет плагин. Ответ — `SCRIPT_STATE` по этому файлу **всегда**, даже если состояние не изменилось: это подтверждение. Незнакомый файл — сначала пересканировать; если файла нет и после — `SCRIPT_STATE <файл> false missing`. |
| `SCRIPT_RELOAD` | хост → плагин | `<файл>` | Перечитать с диска. Незнакомый файл — сначала пересканировать (так подхватывается только что установленный). Включённый — перезапуск (`registry::reload`), выключенный — только перечитать шапку, не запускать. `scripts.cfg` не пишет: упавший при перезагрузке (собрался, но упал при запуске — сборка с ошибкой в игру не ставится вовсе) остаётся включённым (`true failed`), чтобы следующая, исправленная, сборка запустилась. Ответ — `SCRIPT_STATE`. Шлётся автоматически после установки из Script Dev, в том числе на пересборке по сохранению с установкой, и после «Восстановить» по затронутым файлам. |
| `SCRIPT_RESCAN` | хост → плагин | — | Перечитать папку: новые файлы — в конец реестра (выключенные в `scripts.cfg` не запускаются, остальные запускаются), пропавшие — выгрузить, статус `missing`; шапки всех — перечитать. Ответ — полный список (`SCRIPT_STATE` по каждому и `SCRIPT_SYNCED`). Шлётся только когда нужно: после установки или удаления скрипта, после «Восстановить», по кнопке. |
| `SCRIPT_STATE` | плагин → хост | `<файл> <включён> <статус> [сообщение]` | Состояние одного скрипта. Шлётся: полным списком — после рукопожатия и после `SCRIPT_RESCAN`; по одному — при каждом **изменении** из любого источника (команда хоста, клик в оверлее, падение при загрузке, приостановка, Resume). |
| `SCRIPT_SYNCED` | плагин → хост | `<число>` | Конец полного списка: сколько скриптов в реестре. Хост по нему понимает, что пересканирование закончилось, а список полон. |

Порядок строк полного списка — порядок реестра (по имени файла, затем дописанные пересканированием).

## Подтверждение и откат на хосте

Как `NOTIFY_TWEAK`/`TWEAK_SET`, только в обратную сторону. Переключатель в TweakerUI сразу показывает новое
положение, строка помечена «ждёт». Подтверждение — первый `SCRIPT_STATE` по этому файлу. Через 5 с без
ответа — откат к последнему известному состоянию и уведомление. Повторный клик по той же строке, пока
предыдущий ждёт, заменяет его: последний клик побеждает.

## Потоки в плагине

- Разбор `SCRIPT_*` идёт на потоке, доставившем `WM_COPYDATA`, и **только кладёт команду в ящик**. Реестр
  скриптов принадлежит потоку движка, а включение скрипта — это запуск его тела. Из `WndProc` посреди чужого
  стека это был бы повторный вход.
- Ящик разбирает `lua_host::draw_frame` раз в кадр до диспетча — там же, где срабатывают клики во вкладке
  оверлея. Пустой ящик — одна атомарная проверка.
- `SCRIPT_STATE` уходит с потока движка. Любой источник изменения (команда хоста, клик в оверлее, падение,
  приостановка в `lua_sched`, Resume) только двигает счётчик `registry::revision()`; `lua_remote::pump()` в
  начале `lua_host::draw_frame` замечает сдвиг и шлёт строки тех скриптов, чьё описание отличается от
  последнего отправленного. Без хоста не шлётся и не запоминается ничего.
- Незнакомый (или `missing`) файл в `SCRIPT_SET`/`SCRIPT_RELOAD` пересканирует папку не больше одного раза за
  кадр. Если VM не поднялась, ящик выбрасывается непрочитанным: хост увидит таймаут.

## Чего в протоколе нет — сознательно

- Живого состояния: ожидания загрузки, стоимости, хуков, списка диагностики. Это вкладка оверлея.
- Операции «удалить скрипт»: удаляет хост (файлы), плагин узнаёт о пропаже по `SCRIPT_RESCAN`.
- Отдельного ACK: подтверждение — `SCRIPT_STATE`.

## Версия

Вводится протоколом **2** (`k_protocol_version` в `overlay_ipc.cxx`, `ExpectedProtocolVersion` в
`OverlayHelper.cs`). Обратной совместимости нет: проект не выпущен. Хост и плагин ставятся вместе, а пара
разных версий показывает «обновите плагин».
