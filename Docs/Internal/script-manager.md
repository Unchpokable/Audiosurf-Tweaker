# Модуль скриптов в TweakerUI — руководство

Как устроена хостовая сторона Lua-скриптов: две вкладки TweakerUI (Scripts и Script Dev), их модель в
`TweakerCore/Scripting`, компоновщик `twllink` с точки зрения UI и связь с плагином в запущенной игре. Что в
каком файле, по каким правилам работает и почему именно так.

Внутренности самого Lua-слоя плагина (движок, каналы, планировщик, пролог) — `lua-engine-fix-roadmap.md` и
`lua-scripting.md`; сюда из них перенесено только то, что нужно хосту. Пользовательская сторона для авторов
скриптов — `Docs/scripting.md` (вкладки TweakerUI — `Docs/scripting/tweaker.md`).

Модуль сделан фазами С1–С5 с 27.09 по 03.10.2026 и принят владельцем целиком (§11). Подробные итоги фаз,
списки проверок и хронология остались в истории git этого файла (до 04.10.2026 он назывался
`script-manager-roadmap.md`).

---

## 1. Что это

Скрипты — `.lua`-файлы в папке игры, которые запускает плагин (`TweakerPlugin/src/lua/`). Хосту про них
нужно две вещи, и это две вкладки:

- **Scripts** — для игрока. Скрипты в папке игры, поставляемые и свои: включить, выключить, вернуть
  поставляемый, увидеть, что он правил или удалил. При запущенной игре — что плагин говорит о каждом скрипте
  (упал, приостановлен).
- **Script Dev** — для автора. Проекты `twllink`: создать по шаблону, открыть папку как проект, поправить
  манифест, собрать, установить в игру, пересобирать по сохранению, открыть в редакторе, в котором
  `twllink` доступен из терминала.

Без игры обе вкладки работают от файлов. С игрой, к которой подключён хост, переключение идёт через плагин,
а установка сразу перезагружает скрипт в игре (§7).

| Кусок | Где |
|---|---|
| модель без UI | `TweakerCore/Scripting/` (§4), тесты — `TweakerCore.Tests/Scripting/` |
| вкладка Scripts | `TweakerUI/ViewModels/ScriptsViewModel`, `Models/ScriptRowViewModel`, `Views/ScriptsView` (§5) |
| вкладка Script Dev | `ViewModels/ScriptDevViewModel`, `Models/ScriptProjectRowViewModel`, `Models/DiagnosticRowViewModel`, `Models/ProjectTemplate`, `Views/ScriptDevView`, `Core/DevTools` (§6) |
| стили обеих | `TweakerUI/Themes/ScriptsStyles.axaml`, префикс `SM`; общие блоки — `SharedStyles` |
| связь с игрой | `TweakerUI/Core/ScriptsOverlayBridge`, `OverlayHelper`; плагин — `src/lua/lua_remote`, `lua_registry` (§7) |
| грамматика протокола | `overlay-scripts.md` |
| `twllink` | `TweakerLuaLinker/` (§3), его README |

Обе вкладки — в меню TweakerUI после Quick Player, перед Settings. `MainWindowViewModel.OnCurrentViewChanged`
зовёт у их вьюмоделей `SetActive`, и пока вкладка не на экране, она ничего не стоит (исключения — §5, §6).

## 2. Скрипты на стороне игры

Всё — от папки `engine\` игры: `PluginService.EngineDirectory` (родитель
`SettingsProvider.GameTexturesPath`, проверка `PluginInstallation.IsValidEngineFolder`).

```
engine\TweakerStuff\
  Scripts\*.lua              скрипты; плагин читает папку НЕРЕКУРСИВНО
  Scripts\*.lua.map          карта строк собранного скрипта (необязательна)
  Scripts\*.lua.old[.N]      версия пользователя, отодвинутая обновлением или «Восстановить»
  Config\scripts.cfg         какие скрипты ВЫКЛЮЧЕНЫ (только исключения) + engine.* — настройки отстоя движка
  .deploy.json               манифест того, что положила установка плагина, с хешами
```

- **Идентичность скрипта — имя файла.** По нему `scripts.cfg` помнит «выключен», по нему же плагин и хост
  говорят о скрипте в протоколе. Сравнение с учётом регистра, как в `scripts.cfg`. Переименованный файл —
  новый скрипт.
- **Шапка** читается без запуска файла: первые строки-комментарии до первой строки кода, `-- @name`,
  `@author`, `@version`, `@description`, `@api`. У собранного скрипта её пишет `twllink` из манифеста, плюс
  `@bundle twllink 1.1, N modules` — признак «собран из проекта». Правила чтения (последнее значение
  повторённого ключа побеждает, неверный `@api` пропускается, BOM прячет шапку) — общие у плагина
  (`lua_script.cxx: read_header`) и хоста (`ScriptHeader`).
- **`@api`**: скрипт, которому нужен API новее, чем у плагина (`tw.api_version`), плагин не запускает и пишет
  об этом в строке скрипта.
- **Реестр плагина** (`src/lua/lua_registry`). Номер скрипта — его индекс, он не меняется весь сеанс: на этом
  держится проверка планировщика «может ли скрипт работать» на каждом вызове перехваченного канала.
  - Папка читается при старте (`load_all`) и по требованию (`rescan`): кнопкой Rescan во вкладке Scripts
    оверлея или командой хоста. Новые файлы дописываются **в конец**, пропавшие выгружаются и остаются записью
    `missing`, вернувшийся файл получает прежний номер. Работающее не перезапускается.
  - Скрипты лежат в куче, в векторе — `unique_ptr`: указатель на скрипт переживает рост списка.
  - Сам плагин за папкой не следит: изменённый файл подхватывается по Reload (кнопка в оверлее или команда
    хоста), новый — по Rescan.
- **Вкладка Scripts оверлея** (`src/lua/lua_ui.cxx`) — живое состояние каждого скрипта: off, running,
  waiting, suspended, failed, missing; стоимость в мс, хуки, сообщения с позициями в модулях; вкл/выкл,
  Reload, Resume, Rescan. Длинное описание или ошибка — «...» и подсказка с полным текстом.
- **Поставляемые скрипты** — `TweakerPlugin/assets/scripts/*.lua` (+ `.lua.map`) →
  `PluginPayload\TweakerStuff\Scripts\` (`CopyTweakerPlugin` в `TweakerUI.csproj`) → игра
  (`PluginInstallation`). Подпапка `dev/` не поставляется. Часть из них собрана из проектов в
  `TweakerPlugin/assets/script-projects/` (`puzzlepro_hud`); проекты не поставляются.
- **`PluginInstallation`** обновляет поставку по манифесту: не менявшийся файл перезаписывает молча,
  изменённый пользователем отодвигает в `.old`, удалённый пользователем не возвращает. Вернуть удалённое —
  «Восстановить» во вкладке Scripts (§5).

## 3. `twllink` — краткое руководство

Консольный `twllink.exe`, лежит в `<TweakerUI>\DevTools\Binaries\`. В поставке — Native AOT, один файл без
рантайма (публикуют все четыре скрипта деплоя); в дев-сборке — обычная сборка компоновщика, которую туда
кладёт `dotnet build` самого `TweakerUI` (target `CopyTwllink`, §8.1).

### Проект

```
my_hud/
  twproject.json        манифест, имя фиксированное
  src/main.lua          точка входа, имя фиксированное
  src/draw/rail.lua     require("draw.rail")
  .luarc.json           настройки Lua Language Server (пишет --new)
  .twllink/             tw.def.lua + схема манифеста для редактора; каждая сборка освежает, если есть
  build/                результат по умолчанию: <id>.lua и <id>.lua.map
```

```jsonc
{
  "$schema": ".twllink/twproject.schema.json",
  "format": 1,
  "id": "my_hud",            // [a-z0-9_]{1,64}; имя файла в Scripts\ — идентичность, не менять
  "name": "My HUD",          // в одну строку
  "author": "you",
  "version": "0.1.0",        // строго MAJOR.MINOR.PATCH
  "description": "One line.",
  "api": 1,
  "build": { "comments": "keep", "embed": ["LICENSE"] },          // необязательно
  "diagnostics": { "warnings_as_errors": false, "suppress": [] }  // необязательно
}
```

Списка исходников нет: в бандл попадает то, до чего дошёл граф `require` от `main`. Манифест не знает
ничего о машине (ни пути к игре, ни к редактору).

### Команды

| Команда | Что делает |
|---|---|
| `twllink` | собрать проект текущего каталога в `build/` |
| `twllink --project <dir\|twproject.json>` | собрать указанный проект |
| `--out <file.lua\|dir\>` | куда писать; `.map` кладётся рядом |
| `--install [--game <dir>]` | собрать и скопировать `.lua` + `.map` в `engine\TweakerStuff\Scripts\`; `--game` — корень Audiosurf **или** его `engine\`; без `--game` — переменная `AUDIOSURF_DIR`. Нет `TweakerStuff\` — отказ «плагин не установлен». **Сборка с ошибками не ставится** — в игре остаётся прежний файл |
| `--json` | результат JSON в stdout вместо текста |
| `--api <api.json>` | проверять по другому описанию API (для разработки самого API) |
| `--new <hud\|hook\|empty> <dir>` | создать проект в новом/пустом каталоге; `id` из имени каталога; с другими флагами — ошибка использования |
| `--version`, `--help` | |

Файлы пишутся только при изменении содержимого (дата не трогается). Следить за папкой проекта — дело
TweakerUI, у `twllink` флага `--watch` нет (§8.8).

### Коды возврата — контракт для UI

| Код | Значит | Где подробности |
|---|---|---|
| 0 | собрано (и установлено, если просили) | stdout |
| 1 | в проекте ошибки (или не удалась установка / запись) | stdout — текст или JSON с диагностикой |
| 2 | ошибка командной строки (нет проекта, неверный флаг, плохой `--api`, `--new` в непустой каталог) | **stderr, только текст** `twllink: ...` — JSON не выдаётся |
| 3 | сбой самого `twllink` | stderr, текст со стеком |

### `--json`

```json
{
  "twllink": "1.1",
  "success": false,
  "project": "C:\\...\\my_hud",
  "id": "my_hud", "name": "My HUD", "version": "0.1.0",
  "output": null, "map": null, "installed": null,
  "modules": [ { "name": "main", "file": "src/main.lua" } ],
  "diagnostics": [
    { "severity": "error", "code": "TW0302", "file": "src/main.lua", "line": 3, "column": 11,
      "message": "'tw.hud.txt' does not exist in API 1 - did you mean 'tw.hud.text'?" }
  ],
  "errors": 1, "warnings": 0
}
```

`file` — от корня проекта, прямыми слэшами; пусто — сообщение о проекте целиком. `line`/`column` с 1,
`0` — неизвестно. `id`/`name`/`version` нет, если манифест не прочитался. Человекочитаемый вывод —
тот же список в виде `file(line,col): error TW0302: ...`; тест сверяет, что они совпадают.

### Коды диагностик

Номера не переиспользуются; полная таблица для авторов — `Docs/scripting/authoring.md` (тест сверяет её
с кодом). Диапазоны: **TW00xx** манифест и вшиваемые файлы, **TW01xx** исходники и граф `require`,
**TW02xx** запись результата и установка (TW0203 — `--install` не смог), **TW03xx** песочница, имена
`tw.*`, глобалы. Предупреждения: TW0010, 0015, 0109, 0303, 0305, 0306, 0307; остальное — ошибки.

### Решено по `twllink` — не переоткрывать без нового аргумента

- Бандл — одна форма (шим `require`, модули как функции); режим «прямого связывания» вычеркнут
  (`lua-engine-fix-roadmap.md` §17.2).
- Имена `twproject.json` и `src/main.lua` фиксированы; `version` — строгий semver; `id` — идентичность.
- Манифест описывает проект, а не машину: путь к игре передаёт тот, кто вызывает (`--game`).
- Разборщик — Loretta; публикация — Native AOT, запасной путь — `PublishSingleFile`, свой парсер не пишем.
- `Nullable=enable` в проектах компоновщика — утверждено; в остальном решении политика не менялась.
- API `tw.*` правится по порядку из CLAUDE.md («Пользовательская документация»).

## 4. Модель — `TweakerCore/Scripting`

Без UI и без связи с игрой, как весь файловый слой. Всё, что читает файлы игры, читает их **ровно как
плагин** — иначе список в TweakerUI разошёлся бы со вкладкой оверлея.

- **`ScriptHeader`** — порт `read_header` плагина со всеми его правилами (§2), плюс `@bundle`.
- **`ScriptsConfig`** — `scripts.cfg`. Читается как в плагине: `script.<файл>=0|false|off` выключает,
  остальное ничего не значит, имена с учётом регистра. Пишется **правкой**, а не перезаписью: меняются только
  строки `script.<файл>` переключаемого скрипта, комментарии и `engine.*` остаются. Писать можно только при
  остановленной игре — это проверяет вызывающий (§8.4). Порядок выполнения — строки `order=` (`Order`,
  `SetOrder`): читаются как в плагине, заменяются на том же месте, первый порядок дописывается в конец с
  комментарием плагина слово в слово.
- **`ScriptOrder`** — порядок выполнения списками имён (`script-coexistence.md` §3). `Arrange` — как
  плагин строит его на старте: перечисленные в `order=` — в их порядке, остальные — по имени, ordinal. `Move` —
  один файл ставится перед другим, все остальные имена, включая те, которых вкладка не показывает, остаются на
  своих местах.
- **`GameScripts.Scan`** — список для вкладки Scripts. Папка читается как в плагине: плоско, расширение
  ровно `.lua`, в порядке выполнения из `scripts.cfg` (`ScriptOrder.Arrange`). Про каждый скрипт: чей он (`User`/`Shipped`/`Modified` — по хешу в
  `.deploy.json`), включён ли, есть ли `.lua.map`, отличается ли от поставки (`Restorable`), его `.old`-копии
  по порядку создания. В конце — поставляемые скрипты, которых нет на диске (`IsMissing`).
  `GameScripts.IsShipped` — для предупреждения о совпадении имён (§8.6): поставка **или** манифест.
- **`PluginInstallation.RestoreScripts`** (`TweakerCore/PluginInstall/`) — «восстановить поставляемые», все
  или по именам; `.lua.map` идёт со своим скриптом. Та же таблица решений, что у установки плагина (`Apply`
  общий), с одной изменённой строкой: удалённый пользователем скрипт **возвращается** (§8.11). DLL и остальное
  дерево не трогает, поэтому безопасно и при запущенной игре.
- **`Twllink`** — клиент CLI. `BuildAsync(project, game?)` (с `game` — ещё и `--install`; всегда `--json`),
  `NewAsync(template, dir)`, `VersionAsync()`. Коды 0/1 → разобранный JSON (`TwllinkBuild`), 2/3 → текст
  stderr (`ToolMessage`), −1 → процесс не запустился. Рабочая папка — ближайшая **существующая** вверх по
  пути: в несуществующей процесс не стартует, а для `--new` это родитель нового проекта.
- **`ScriptProjects`** — список проектов Script Dev: недавние (новые сверху), затем папки из `Sources` по
  имени, без повторов. Недавние — текстом, по пути на строку, не больше 20; файл перечитывается при каждом
  `List`/`Remember`/`Forget`, так что ручная правка видна сразу и не затирается. Папку без `twproject.json` не
  запоминает. Пропавший проект извне остаётся с `IsMissing` до `Forget`; пропавший из `Sources` выпадает
  сам. Сломанный манифест не прячет проект — он в списке с причиной (`ManifestProblem`).
- **`ProjectManifest`** — чтение и **правка** `twproject.json`. `Problem` — правила полей те же, что у
  `twllink`; `IdFrom` — `id` из имени тем же преобразованием, что у `--new`. `Update`/`Edit` меняют ровно
  байты значений (через спаны `Utf8JsonReader`), сохраняя комментарии, порядок, секции, BOM и отступы;
  отсутствующее поле дописывается после последнего с тем же отступом.
- **`ScriptEditors`** — редакторы (§8.3). На каждый одно описание: где искать (стандартные папки, шим в
  `PATH`), аргументы «папка» и «файл на строке», консольный ли, держит ли один процесс, есть ли терминал.
  `StartInfo` кладёт `DevTools\Binaries` в начало `PATH` и `AUDIOSURF_DIR` = корень игры.

  | Редактор | Где ищется | «Файл на строке» |
  |---|---|---|
  | VS Code | `%LOCALAPPDATA%\Programs\Microsoft VS Code\Code.exe`, `Program Files`, шим `code.cmd` | `<папка> -g <файл>:<строка>:<столбец>` |
  | Cursor | `%LOCALAPPDATA%\Programs\cursor\Cursor.exe`, шим `cursor.cmd` | как VS Code |
  | Sublime Text | `Program Files\Sublime Text[ 3]\`, шим `subl.exe` | `<папка> <файл>:<строка>:<столбец>` |
  | Notepad++ | `Program Files[ (x86)]\Notepad++\` | `-n<строка> -c<столбец> <файл>`; папка — `-openFoldersAsWorkspace` |
  | Neovim | `Program Files\Neovim\bin`, `%LOCALAPPDATA%\Programs\Neovim`, scoop, `nvim.exe` в `PATH` | `+call cursor(строка,столбец) <файл>`, рабочая папка — проект |
  | Vim | `Program Files\Vim\vim*` (новейший), `vim.exe` в `PATH` | как Neovim |

  Новый редактор — ещё одно описание. `vim.exe` из `Git\usr\bin` исключён: это MSYS-vim самого Git, а не
  установленный редактор.
- **`ScriptWire`** — грамматика `SCRIPT_*` хоста (§7): `Set`/`Reload`/`Rescan`/`Order` пишут команды,
  `TryParseState`/`TryParseSynced`/`TryParseOrder` читают ответы, `ScriptLiveState`/`ScriptLiveStatus`. Без транспорта и
  состояния — чтобы проверяться юнит-тестами против тех же строк, что требует от плагина его харнесс.

## 5. Вкладка Scripts

**Строки идут в порядке выполнения** (`script-coexistence.md` §3): при связи — в порядке плагина
(`SCRIPT_ORDER`), без неё — в порядке `scripts.cfg`; поставляемые, но не установленные — внизу, без места.
Слева у строки — ручка из шести точек (как в оверлее): за неё строку перетаскивают, линия вставки и затемнение
перетаскиваемой строки — общие `DropLine` и `Dragged` из `SharedStyles` (те же, что в очереди Quick Player),
прокрутка у края — `Core/DragAutoScroll`. Где строка легла и что это значит — `ScriptsViewModel.MoveScript`,
режимы — те же три, что у переключателя (таблица ниже): без игры — строки `order=` в `scripts.cfg`; при связи —
`SCRIPT_ORDER` (весь порядок плагина со сдвинутым файлом), строки сразу в новом порядке до ответа плагина, 5 с
без ответа — возврат и уведомление; без связи — ручка заперта вместе с переключателем.

**Строка скрипта:** имя из шапки, под ним `файл · vверсия · by автор`, описание; значки происхождения
`Bundled`, `Bundled, edited`, `Yours`, `Project build`, `Not installed` (у каждого подсказка, что это значит
для обновлений; у `Project build` — есть ли `.lua.map`); «N saved copies» с именами `.old` в подсказке;
кнопки «восстановить» (только если это что-то изменит) и «показать в Проводнике»; переключатель. При
подключённой игре под описанием — строка того, что говорит плагин, если есть что сказать: «Failed: <ошибка>»
красным, «Suspended: <причина>» жёлтым, «Waiting for the game...» пока переключение ждёт подтверждения,
«The game has not picked this file up yet» для файла, о котором плагин говорит `missing`.

**Шапка карточки:** «N of M enabled» (при связи — «· live from the game»); «восстановить всё», «открыть
папку Scripts», Refresh.

**Переключатель — три режима** (§8.4):

| Игра | Что делает переключатель |
|---|---|
| не запущена | пишет `scripts.cfg` через `ScriptsConfig` |
| запущена и подключена (`ScriptsOverlayBridge.IsLive`) | шлёт `SCRIPT_SET`, сразу показывает новое положение и ждёт `SCRIPT_STATE` до 5 с; без ответа — откат и уведомление; повторный клик заменяет ожидание; `scripts.cfg` пишет плагин |
| запущена, связи нет (синхронизация оверлея выключена или плагин не ответил) | заперт, баннер объясняет почему и куда идти — во вкладку Scripts оверлея |

Положение переключателя: ожидающий клик → слово плагина → `scripts.cfg`. «Игра запущена» — опрос раз в 2 с
и ещё раз в момент клика; при связи решает связь.

**Refresh** перечитывает папку, а при связи ещё и просит игру пересканировать свою (§8.9).

**«Восстановить»** — одного скрипта или всех — спрашивает подтверждение («ваши версии останутся рядом как
.old») и зовёт `PluginInstallation.RestoreScripts`. При связи затем — `SCRIPT_RESCAN` и `SCRIPT_RELOAD`
заменённых `.lua` (не `.lua.map`: карта не скрипт); без связи при запущенной игре текст говорит, что она
подхватит файлы по Reload в оверлее или при следующем старте.

**Пока вкладка на экране:** опрос «запущена ли игра»; наблюдатели за `Scripts\` (установка, правки руками) и
за `Config\scripts.cfg` (переключение в оверлее без связи) с пересканированием после 300 мс тишины; после
выхода из игры — пересканирование. На слова плагина вьюмодель подписана **всегда**: полный список плагин
шлёт один раз, при подключении, и вкладка, открытая позже, должна его показать.

**Пустые состояния и баннеры:** папка игры неизвестна; скриптов нет; плагин не установлен (скрипты не
работают); игра запущена без связи.

## 6. Вкладка Script Dev

### `DevTools\`

Рядом с приложением (`Core/DevTools` — единственное место, знающее раскладку; от `AppPaths`, §8.1):

```
<TweakerUI>\DevTools\
  Binaries\twllink.exe       компоновщик
  Sources\<id>\              проекты, созданные здесь
  recent-projects.txt        проекты, открытые откуда угодно ещё
```

### Проекты — левая колонка

Список `ScriptProjects` (§4): недавние, затем `Sources`. Кнопки «новый», «открыть папку как проект»,
«перечитать». В строке: сломанный манифест — коротко («twproject.json cannot be read»), пропавшая папка —
«Folder not found».

- **Новый проект** — форма справа, на месте подробностей: **Name** (свободный текст в одну строку),
  **Script file (id)** с подписью `.lua` (заполняется из имени через `ProjectManifest.IdFrom`, пока его не
  поправили руками; §8.12), описание, шаблон HUD/Hook/Empty с пояснениями, **Create**/**Cancel** в заголовке
  формы. Создаётся в `Sources\<id>\` через `twllink --new`, затем имя и описание дописываются в манифест.
  Форма закрывается после создания, по Cancel и при выборе другого проекта.
- **Открыть папку как проект** — выбор папки; без `twproject.json` отказ. Файлы остаются, где были, путь
  запоминается в недавних.

### Выбранный проект — правая колонка

- Имя, id, версия, путь, описание. «Открыть папку», «убрать из списка» (только для открытых извне; папку не
  трогает), «удалить проект» (папка — **в Корзину**, с подтверждением; установленный в игру скрипт остаётся —
  его убирают во вкладке Scripts).
- **Правка манифеста** («карандаш»): name, id, author, version, description. Правила — `ProjectManifest.Problem`
  по мере ввода, Save недоступна при ошибке; смена id предупреждает, что это новый скрипт, а старый
  останется в игре. Запись — правкой текста (§4).
- **Описание** — многострочное поле: перенос по ширине, рост до 200 px (~10 строк), дальше прокрутка. Но
  значение — **одна строка** (§8.13): Enter не вставляет абзац, переводы строк и табуляции во вставленном
  тексте становятся пробелами. Шаблон `FlatTextAreaTemplate` и модификатор `TextField.TextArea` — общие
  (`SharedControlTemplates`, `SharedStyles`).
- **Build** и **Build and install** (`--game` — `PluginService.EngineDirectory`). Строка итога: «Built at …»,
  «Built and installed at …», «Built, installed and reloaded at …» (установлено в подключённую игру, §8.10),
  «Built, but not installed», «Build failed … N errors», «twllink could not build it»; под ней путь
  результата и список диагностики — точка важности, `файл:строка:столбец`, код, сообщение. **Двойной клик**
  по записи открывает её место в выбранном редакторе; запись о проекте целиком открывает проект (§8.7).
- **Совпадение id с поставляемым скриптом** — подтверждение перед установкой, один раз на проект за сеанс;
  для автоустановки — в момент включения переключателя (§8.6).
- **Rebuild on save** и **and install into the game** — наблюдатель на папку выбранного проекта, пока включён
  переключатель, **и когда вкладка не на экране**: включил человек, а смотрит он в редактор.
  - Не считаются изменением: `build\`, `.twllink\`, `.git\`, `.vscode\`, `.vs\`, `.idea\` и событие
    «изменилась папка» (его вызывает само чтение файлов при сборке).
  - Пауза — 300 мс тишины; изменения во время сборки дают **одну** сборку после неё. Задержка — `Task.Delay`
    с номером поколения (§8.16).
- **Карточка Editor** — найденные редакторы (`RowList`), выбор запоминается (`ScriptEditor` в
  `ConfigurationManager.Bindings`), поиск повторяется при каждом показе вкладки. Кнопка **Open in
  <редактор>**. Уже запущенный VS Code или Cursor, запущенный не этой сессией Tweaker, — предупреждение с
  «Open anyway / Cancel», за сеанс один раз (§8.3).

## 7. Связь с игрой

Грамматика — `overlay-scripts.md`. Транспорт — `TW_OVL` (`overlay-protocol.md`), протокол **3** (2 — `SCRIPT_*`,
3 — `SCRIPT_ORDER`):
`k_protocol_version` в `overlay_ipc.cxx` и `ExpectedProtocolVersion` в `OverlayHelper.cs` должны совпадать,
иначе хост показывает «обновите плагин».

| Операция | Направление | Смысл |
|---|---|---|
| `SCRIPT_SET <файл> <true\|false>` | хост → плагин | включить/выключить; `scripts.cfg` пишет плагин |
| `SCRIPT_RELOAD <файл>` | хост → плагин | перечитать с диска; незнакомый файл — сначала пересканировать; выключенный только перечитывает шапку |
| `SCRIPT_RESCAN` | хост → плагин | подхватить новые и пропавшие файлы |
| `SCRIPT_STATE <файл> <true\|false> <статус> [сообщение]` | плагин → хост | состояние одного скрипта: при подключении и после пересканирования — по всем, затем при каждом изменении |
| `SCRIPT_SYNCED <число>` | плагин → хост | конец полного списка |
| `SCRIPT_ORDER <файл>…` | хост → плагин | задать порядок выполнения; `scripts.cfg` пишет плагин |
| `SCRIPT_ORDER [файл…]` | плагин → хост | весь порядок: в полном списке перед `SYNCED`, при каждом изменении, всегда в ответ хосту |

Статусы: `off`, `running`, `failed`, `suspended`, `missing`. В хост идут **только изменения состояния**
(§8.5).

### Плагин

- **Разбор** — `overlay_ipc` отдаёт строки с префиксом `SCRIPT_` в `lua_remote::handle_op`, как `QP_*` в
  `ui/qp`. На потоке, доставившем `WM_COPYDATA`, команда только **кладётся в ящик** (мьютекс + вектор +
  атомарный флаг; §8.15).
- **Исполнение** — `lua_remote::pump()`, первое в `lua_host::draw_frame`: меню уже отрисовано (клики оверлея
  применены), скрипты ещё не рисовали. Пустой ящик — одна атомарная загрузка. `SET`/`RELOAD` незнакомого или
  `missing` файла сначала пересканируют папку — не больше раза за кадр.
- **Что уходит хосту.** Всё, что меняет вид скрипта снаружи — переключение, загрузка, падение, `rescan`,
  приостановка и Resume в `lua_sched`, — только двигает счётчик `registry::revision()`. `pump()` замечает
  сдвиг и шлёт `SCRIPT_STATE` тех скриптов, чьё описание отличается от последнего отправленного. На
  `SET`/`RELOAD` ответ уходит всегда — это подтверждение. После рукопожатия (`request_sync`) и на
  `SCRIPT_RESCAN` — полный список и `SCRIPT_SYNCED`. Порядок — тем же путём: строка `SCRIPT_ORDER` уходит, когда
  отличается от последней отправленной, в полном списке и всегда в ответ на `SCRIPT_ORDER` хоста
  (`registry::set_order`; незнакомые имена пропускаются без пересканирования).
- Сообщение — первая строка, не длиннее 400 байт, обрезано по границе символа UTF-8. Полный текст и
  трассировка — во вкладке оверлея.
- Без хоста ничего не шлётся и не запоминается. Если VM не поднялась, ящик выбрасывается: хост увидит
  таймаут.

### Хост

- **`OverlayHelper`** — только транспорт: событие `ScriptsMessageReceived` (строки как есть) и
  `SendScripts`, возвращающий, ушла ли строка.
- **`ScriptsOverlayBridge`** — статический, как `OverlayHelper`, инициализируется рядом с ним в
  `MainWindowViewModel`, потому что нужен обеим вкладкам. Всё — на UI-потоке. Кэш состояний по имени файла,
  ожидающие переключения (`RequestSet`; ответ — **любой** `SCRIPT_STATE` по файлу; таймаут
  `ConfirmTimeout` = 5 с на `Task.Delay`; поколение не даёт часам старого клика сработать на новом),
  `Reload`, `Rescan`, `IsLive`, `IsSynced`, события `Changed` и `RequestTimedOut`. Порядок плагина и
  ожидающее перетаскивание (`Order` — ожидающее или слово плагина, `RequestOrder`, ответ — **любой**
  `SCRIPT_ORDER`, тот же таймаут, событие `OrderTimedOut`). Потеря связи забывает всё,
  что сказала игра. Транспорт подменяется (`UseTransport`), строки подаются `Receive` — так `UiStand` гоняет
  вкладки против поддельного плагина.
- **Кто шлёт:** Scripts — `SET` по переключателю, `ORDER` по перетаскиванию, `RESCAN` по Refresh, `RESCAN` + `RELOAD` после
  «Восстановить»; Script Dev — `RELOAD` установленного файла после успешной установки, в том числе на
  пересборке по сохранению.

### Транспорт: длина сообщений

Пайп `asbridge` в режиме сообщений (`duplex_pipe.cxx`, `PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE`); 4096 байт —
размер **куска чтения**, а не предел: `asbridge` склеивает продолжения по `ERROR_MORE_DATA`, хост — по
`IsMessageComplete`. У `WM_COPYDATA` своего предела нет. Вживую сообщение длиннее 4 КБ не гонялось. Строка
`SCRIPT_STATE` не длиннее ~1.3 КБ, а `SCRIPT_ORDER` растёт с числом скриптов — около 4 КБ это сотня с лишним
скриптов с длинными именами; проверять — длинным `SKIN_LIST`.

## 8. Решения и почему

Решения владельца (большей частью 27.09–01.10.2026) и найденные по ходу. Код ссылается на них по номеру
(`script-manager.md §8.N`).

### 8.1 `twllink` и `DevTools\` — рядом с приложением

`twllink` собирается как часть сборки `TweakerUI`, как все компоненты. Инструменты разработчика — в
`<TweakerUI>\DevTools\`: `Binaries\` (компоновщик), `Sources\` (проекты по умолчанию), `recent-projects.txt`.
В дев-сборке — обычная, не AOT, сборка компоновщика: AOT на каждый `dotnet build` стоил бы десятков секунд и
требовал бы MSVC. В поставке — Native AOT из скриптов деплоя.

`TweakerUI.csproj` ссылается на `TweakerLuaLinker` через `ProjectReference` (`ReferenceOutputAssembly=false`,
выход — в `TwllinkBuildOutput`), target `CopyTwllink` копирует **верхний уровень** выхода (рядом лежат
`native\`/`publish\` от AOT). `_IsPublishing` и свойства публикации сняты (`GlobalPropertiesToRemove`): иначе
публикация TweakerUI делала компоновщик self-contained, и в `DevTools\Binaries\` ложился весь рантайм.

### 8.2 Две вкладки

Игроку — Scripts, автору — Script Dev (§1). Не одна вкладка с режимом: у них разные пользователи и разные
предметы — файлы в игре против проектов.

### 8.3 Редакторы и `PATH`

Список — VS Code, Cursor, Sublime Text, Notepad++, Vim, Neovim (28.09.2026). Atom закрыт в 2022; VSCodium,
Zed и «свой редактор руками» не нужны были на момент работы (§10). Notepad++ без LSP — подсказок по `tw.*` в
нём нет.

**Системный `PATH` пользователя не трогаем.** `twllink` попадает в `PATH` только дочернего процесса
редактора, вместе с `AUDIOSURF_DIR`. Засорять системный `PATH` ради редко нужного инструмента некрасиво, а
уже запущенный редактор его всё равно не увидит: VS Code, Cursor и Sublime держат один процесс, повторный
запуск отдаёт папку уже открытому, и встроенный терминал наследует окружение первого. Поэтому «открыть
проект» замечает уже запущенный редактор и предупреждает (только VS Code и Cursor — у Sublime и Notepad++ нет
терминала, консольные запускаются каждый раз заново). Не предупреждает, если тот экземпляр запущен этой
сессией Tweaker.

Консольные редакторы запускаются напрямую, без оболочки, с `CreateNoWindow = false`, а **не** через `wt.exe`:
новая вкладка Windows Terminal берёт окружение у процесса Terminal, а не у того, кто её позвал. Если Terminal —
консоль по умолчанию, процесс всё равно наш, и окружение наше.

### 8.4 Владелец `scripts.cfg` — плагин

Пока игра запущена, `scripts.cfg` пишет только плагин: он читает файл при старте и переписывает на каждом
переключении. Хост просит его по IPC (§7). Без игры плагина нет и спросить некого — файл пишет хост, тем же
форматом и правкой строк (§4): гонки нет. Игра запущена, связи нет — переключатели заперты с объяснением.

### 8.5 В хост — только изменения состояния

Lua-система — модуль плагина, а не хоста. Хочешь видеть, что скрипт делает прямо сейчас, — открой оверлей.
Хост «сидит на стульчике и смотрит», плагин отчитывается **только об изменении**: включён/выключен, упал при
загрузке, приостановлен, пропал файл. Покадровое — стоимость в мс, ожидание загрузки игры, хуки,
диагностика — в хост не идёт никогда (решение 01.10.2026; задуманная было фаза живого слежения снята).

### 8.6 `id` проекта совпадает с поставляемым скриптом

Подтверждение: «Имя совпадает со скриптом из поставки Tweaker. Установка заменит его, и следующее обновление
плагина отодвинет вашу версию в .old и вернёт поставляемую. Продолжить?» Поставляемое — то, что в поставке
или записано в `.deploy.json`. Спрашивается один раз на проект за сеанс; для автоустановки — при включении
переключателя, а не на первом сохранении: диалог, всплывающий, пока человек печатает в редакторе, — не то
время.

### 8.7 Ошибки сборки — списком, двойной клик открывает место

Из `--json`. Двойной клик — выбранный редактор (с тем же `PATH`) на файле, строке и столбце записи, если
редактор это умеет; не умеет или место неизвестно — проект.

### 8.8 Следить за папкой проекта — дело хоста

`--watch` из `twllink` убран: хост и так запущен — он и открыл редактор, — и второй наблюдатель в компоновщике
только дублировал бы его, держа лишний код и самый хрупкий тест. `--watch` теперь — ошибка командной строки
(код 2).

### 8.9 Пересканирование — только когда нужно; номера не сдвигаются

Плагин перечитывает папку, когда что-то установили, удалили или восстановили, и когда пользователь попросил —
не по каждому изменению папки: при копировании руками наблюдатель увидел бы файл недописанным.

Просить руками можно в двух местах: Rescan во вкладке оверлея и Refresh во вкладке Scripts TweakerUI. Отдельной
кнопки «Rescan in game» в TweakerUI нет: при связи Refresh делает и то и другое, две кнопки «перечитать папку»
рядом путали бы.

Пересканирование **дописывает** новые файлы в конец реестра и помечает пропавшие `missing`, а не
перестраивает список: номер скрипта — индекс, и проверка «может ли скрипт работать» на каждом вызове
перехваченного канала держится на том, что он не меняется (§2, §8.14).

### 8.10 После установки — перезагрузка в игре; перезагрузка не пишет `scripts.cfg`

Установка из Script Dev в подключённую игру сразу шлёт `SCRIPT_RELOAD`, в том числе на пересборке по
сохранению. Скрипты выгружаются и обрабатывают ошибки без фейерверков, а тот, кто сидит в Script Dev посреди
заезда, пишет моды — скачки времени кадра его не волнуют.

Перезагрузка (`registry::reload`, кнопка Reload в оверлее и `SCRIPT_RELOAD`) — выгрузить и запустить **без
записи** в `scripts.cfg`. Упавший при перезагрузке остаётся включённым и `failed`, как при старте игры, — иначе
следующая, исправленная, версия не запустилась бы: перезагрузка выключенного только перечитывает шапку.
Падает при перезагрузке скрипт, который собрался, но падает при запуске (ошибка в теле, `@api` новее
плагина): сборка с ошибками в игру не ставится вовсе (§3).

Неудачное включение **переключателем** (оверлей или `SCRIPT_SET`) — другое: переключатель «отпрыгивает»,
`scripts.cfg` не меняется, на проводе это `false failed <ошибка>`.

### 8.11 «Восстановить поставляемые» возвращает удалённое, правки — в `.old`

Ради кнопки правило установки «изменённый пользователем файл не перезаписывается без копии» не нарушается:
правка уходит в `.old`, и подтверждение говорит «ваши версии останутся рядом», а не «будут потеряны».
Отличие от установки плагина одно — удалённый пользователем скрипт возвращается: для этого кнопка и нужна.

### 8.12 `name` свободный, `id` строгий

У проекта два имени. **name** — отображаемое, любой текст в одну строку. **id** — имя файла скрипта в игре и
его идентичность, `[a-z0-9_]{1,64}`. Строгость `id` — правило `twllink`, и у неё есть причина: плагин и
`scripts.cfg` различают скрипты по имени файла с учётом регистра, а файловая система — без. Только строчные
буквы, цифры и `_` не оставляют двух написаний одного имени. Форма спрашивает оба и выводит id из имени.

### 8.13 Описание — одна строка; в оверлее — «...» и подсказка

Плагин читает шапку построчно, `twllink` отвергает перевод строки в манифесте, поэтому описание — одна
строка, а поле в Script Dev только выглядит многострочным (§6). Настоящие абзацы потребовали бы расширить
формат шапки (например, повторяющиеся `@description`) в плагине, `twllink` и `ScriptHeader` разом (§10).

В оверлее длинное описание, ошибка или причина приостановки — «...» и подсказка с полным текстом, перенесённым
по ширине (`lua_ui.cxx`; `detail::add_text_ellipsis` возвращает, обрезал ли). Плашки в пол-экрана некрасивы.
Окно описания сбоку от меню — возможное продолжение (§10).

### 8.14 Реестр плагина — на `unique_ptr`

Скрипт в куче, в векторе — владеющий указатель: дописывание при пересканировании двигает указатели, а не
скрипты, и `script*` у вызывающих остаётся живым. `unique_ptr`, а не `shared_ptr`: владелец один (реестр),
записи не удаляются (пропавший файл — состояние), счётчику ссылок нечего считать, а атомарные инкременты на
копиях стоили бы денег. На доступе через `->` машинный код у умного и сырого указателя один. Аллокация —
только при пересканировании, не каждый кадр.

### 8.15 Команды хоста — через ящик на потоке движка

Реестр принадлежит потоку движка, а включение скрипта — это запуск его тела. `WM_COPYDATA` доставляется на
потоке окна; скорее всего это тот же поток (Quest3D качает сообщения внутри `EngineLoop`), но не доказано, и
даже на одном потоке `WndProc` приходит посреди чужого стека — получился бы повторный вход в середине кадра.
Поэтому разбор только кладёт команду в ящик, а исполняет её `draw_frame` — там же, где клики оверлея.
Приостановка рождается в горячем пути (`lua_sched`), поэтому только двигает счётчик, а отправка — из кадра.

### 8.16 Мелкие технические решения

- **Таймеры UI — `Task.Delay` с номером поколения, не `DispatcherTimer`**: часы `DispatcherTimer` не идут в
  headless-стенде, и пересборку по сохранению и таймаут подтверждения там было бы нечем проверить. Опрос
  «игра запущена» во вкладке Scripts остался на `DispatcherTimer` — его стенд не проверяет, на игре он проверен.
- **Удаление проекта — в Корзину** (`Microsoft.VisualBasic.FileIO`, `RecycleOption.SendToRecycleBin`): кнопка
  «удалить» в одном клике от «собрать».
- **Общие блоки в `SharedStyles`**, а не копия в модуле: `ActionButton`, `TextField`, `TextField.TextArea`,
  `RowList` переехали туда из Settings и Skin Changer, когда понадобились Script Dev.

## 9. Как проверять

| Что | Чем |
|---|---|
| модель (`TweakerCore/Scripting`, `RestoreScripts`) | `TweakerCore.Tests/Scripting/`: `ScratchGame` — поддельная папка игры; тесты `Twllink` гоняют **настоящий** `twllink` (проект тестов ссылается на компоновщик, как TweakerUI, и копирует его в `twllink\`); `ScriptWireTests` — те же строки, что `remotetest` |
| вкладка Scripts | `Tools/UiStand scripts`: настоящая вьюмодель над поддельной игрой (все виды строк, баннеры, пустые состояния, обе темы и ширины), переключатель без игры (запись `scripts.cfg`; если Audiosurf на машине реально запущена — отказ), живой режим против поддельного плагина (`ScriptsOverlayBridge.UseTransport`/`Receive`) |
| вкладка Script Dev | `Tools/UiStand scriptdev`: настоящий `twllink`; создание, правка манифеста, сборка, ошибка с местом, установка, `SCRIPT_RELOAD` после установки, пересборка по сохранению, высоты поля описания, Neovim без окна — видит ли `twllink` и `AUDIOSURF_DIR` |
| утечки и снимки | `Tools/UiStand tabs` (живые вьюшки после GC), `shoot` + `compare` (попиксельно до/после правки общих стилей) |
| реестр плагина и ящик | `TweakerPlugin/harness/remote/remotetest` (настоящие `lua_registry`, `lua_remote`, `lua_script`, `wire_text` над временной папкой); `harness/sched/schedtest` — приостановка и Resume двигают ревизию |

**Стенд берёт `TweakerUI.dll` из сборки самого TweakerUI** — после правки TweakerUI собрать его, затем стенд,
иначе проверяется старый код.

Только на игре и руками: IPC целиком, вкладка оверлея, окна VS Code и Cursor, модальные диалоги (совпадение с
поставкой, удаление, подтверждение «Восстановить»), системный выбор папки.

## 10. Не сделано и возможное продолжение

- **Окно описания скрипта в оверлее** — клик по карточке (не по её кнопкам) открывает окно сбоку от меню, как
  панель параметров неба (`skybox/sky_panel`), с макетом, похожим на описание в TweakerUI. Можно совместить с
  «...» и подсказкой. Только если владелец решит (§8.13).
- **Свой редактор руками** (программа, шаблон аргументов `{project}`/`{file}`/`{line}`/`{column}`, признак
  «консольный») — задумывался, не сделан: шесть пресетов покрыли названный список.
- **Многострочное описание** — изменение формата шапки в плагине, `twllink` и `ScriptHeader` разом (§8.13).
- **Сообщение > 4 КБ через мост** вживую не проверено (§7).
- **Открытые хвосты Lua-слоя** (не про модуль; подробно — `lua-engine-fix-roadmap.md`, «Не закрытые
  проверки»): хук на канал пула `Renderer` с новым заездом, `tw.matrix_ch` из живой игры, стоимость колбэков на
  слабом железе (замер только с Ryzen 7 9800X3D). Отложено: обобщение `engine/channel_vtable` в `framework/`,
  объекты и текстуры как семейства каналов.
