# Skybox в `TW_OVL`

Протокол **4**. Плагин реализован в Н2; хостовый мост и вкладка TweakerUI остаются Н3/Н4
([план](sky-manager-roadmap.md)). Транспорт — [overlay-protocol.md](overlay-protocol.md).

| Операция | Направление | Аргументы |
|---|---|---|
| `SKY_ENABLE` | хост → плагин | `true` или `false` |
| `SKY_SELECT` | хост → плагин | `<kind> <id>` |
| `SKY_RESCAN` | хост → плагин | нет |
| `SKY_ENTRY` | плагин → хост | `<kind> <id> <display_name> [face_size]` |
| `SKY_SYNCED` | плагин → хост | `<count>` |
| `SKY_STATE` | плагин → хост | `<enabled> <kind> <id> <status> [message]` |

`kind` совпадает с `skybox_config::kind_key`; `id`, название и сообщение кодируются UTF-8 percent-encoding
общим `ui/wire_text`. Сообщение содержит первую строку ошибки, не более 400 байт до кодирования,
без разрыва символа UTF-8. Параметры шейдеров, свет и качество рендера через протокол не передаются.

После рукопожатия и `SKY_RESCAN`: `SKY_ENTRY` для каждого элемента, затем `SKY_SYNCED`, затем `SKY_STATE`.
Изменение поколения каталога в оверлее также отправляет полный список. Каждая корректная команда
`SKY_ENABLE`/`SKY_SELECT` получает `SKY_STATE`, даже если значение не изменилось. Самопроизвольные изменения
отправляются по `skybox::revision()`; одинаковые состояния повторно не отправляются. Без хоста сообщения
не накапливаются; при подключении передаётся актуальный снимок.

Состояние относится к **выбору в конфиге**, даже если продолжает рисоваться прежнее небо:

| Статус | Значение |
|---|---|
| `off` | реплейсер выключен |
| `missing` | выбранного элемента нет в каталоге или отсутствует источник пакета |
| `compiling` | первоначальное чтение пакета либо компиляция его слоя |
| `failed` | ошибка загрузки, компиляции слоя, создания шейдеров/текстур или генератора |
| `waiting` | небо ещё не было встречено в отрисовке либо нет готового источника |
| `ready` | источник готов, небо уже встречалось, известных ошибок нет |

`ready` не является подтверждением визуальной корректности результата на GPU.

`WndProc` синхронно разбирает команду и кладёт её в ящик `sky_remote`. `pump()` вызывается в начале
`skybox::ui::update()` при закрытом меню тоже, на том же игровом потоке. Ящик переносит изменение
ресурсов к границе кадра и допускает повторный вход оконных сообщений; фонового обработчика `WM_COPYDATA` нет.
Фоновый watchdog IPC лишь проверяет существование окна моста (ранее согласованный R-14).

Незнакомый дисковый `id` вызывает пересканирование, максимум одно на пакет команд за кадр. Выбор
сохраняется и при отсутствии файла. Повторный выбор активного пакета запрашивает проверку источника
тем же модулем `skybox::reload`, который обслуживает наблюдение при открытом меню. Снимок содержит
существование, время записи и размер каждого файла; одинаковая версия не загружается повторно.
Чтение пакета и исходников компиляции идёт через `bg_work`; результат устаревшего выбора отбрасывается.
Изменение содержимого с сохранением и размера, и времени записи не обнаруживается этим наблюдением.
