# Вкладки скриптов в меню оверлея, файлы скрипта и пролог в `.lua` — руководство

Руководство к трём связанным частям скриптового слоя: **вкладкам, которые объявляют скрипты** (`tw.ui`: форма
`ui/form` над виджетами, динамические вкладки меню, `lua_tabs`), **личным файлам скрипта** (`tw.storage`,
`lua_storage`) и **прологу в отдельных `.lua`** (`src/lua/prelude/`). Как устроено, что в каком файле, решения и
почему, как проверять.

Сделано по плану Т0–Т5 и закрыто 20.10.2026; API 3. Т6 плана — вкладка настроек поставляемого `puzzlepro_hud` — не
делалась: владелец оставил её себе (§7). Номера §2.N и §3.N — те, на которые ссылается код. Публичная сторона, для
авторов скриптов, — `Docs/scripting/menus.md`, `Docs/scripting/storage.md`, разделы «Menu tabs» и «Storage» в
`api-reference.md`, разбор `dev/ui_probe.lua` в `examples.md`.

---

## §1. Что это и зачем

До API 3 у скрипта было две поверхности: то, что он рисует в HUD (`tw.hud.*`, только вывод), и его строка во
вкладке Scripts. Настроить скрипт пользователь не мог ничем, а сохранить что-либо между сеансами не мог сам скрипт:
`io` и `os` убраны песочницей.

Теперь:

1. **Вкладка скрипта.** Скрипт объявляет вкладку в меню оверлея и контролы на ней — переключатели, ползунки,
   числа, выбор, цвета, кнопки, списки, текст, группы — и **видит, что ввёл пользователь**: читает значения,
   получает уведомления, сам выставляет значения. Что на вкладке — решает скрипт; плагин даёт инструменты.
2. **Файлы скрипта.** Личная папка, текст и JSON. Настройки вкладки скрипт сохраняет сам, этими же функциями:
   отдельного механизма «запомнить значения контролов» нет.
3. **Пролог в `.lua`.** Lua-половина слоя лежит файлами `src/lua/prelude/*.lua` и вшивается в DLL сборкой, а не
   строковыми литералами в `.cxx`.

Главный вопрос дизайна — как виджеты со своим состоянием, живущие между кадрами (`tweaker-plugin-widgets.md`,
правила 1, 2, 15), соединить со скриптом, который живёт в другом слое, умеет падать и может быть перезагружен в
любой момент. Ответ — §3.1.

## §2. Решения владельца (19–20.10.2026)

1. **Вкладок у скрипта — сколько попросит.** В идеале одна, разделы — группами (`item_group`), страница
   прокручивается сама; но API — просто `tw.ui.tab{...}`, без лимита. `item_group` для этого умеет растягиваться
   **во всю ширину** (`set_fill_width`); прежние вызовы (кладка групп редактора темы) остались по содержимому.
2. **Вкладки — после встроенных, в порядке выполнения скриптов** (`script-coexistence.md` §3), внутри скрипта — в
   порядке объявления. **Reload и переключение место не меняют**; перетащили скрипт — вкладка переехала с ним.
3. **Совпадающие подписи — через имя скрипта.** Когда подпись совпала — со встроенной вкладкой или с вкладкой
   другого скрипта, без учёта регистра, — **все** совпавшие скриптовые вкладки показываются как
   `<имя скрипта> - <подпись>`; имя — `@name`, без него — файл без `.lua`. Все, а не «вторая и дальше»: иначе
   какая останется без приставки, решал бы порядок загрузки. Сокращений имени нет — однозначно их не вывести.
4. **Настройки сохраняются между сеансами** — основной случай; механизм — п. 9.
5. **Вкладка приостановленного скрипта — выключена целиком**: страница под `BeginDisabled`, подпись приглушена, но
   её можно открыть и посмотреть значения; Resume — во вкладке Scripts. **Выключенный** скрипт (и упавший при
   загрузке) — вкладки нет вовсе.
6. **Плагин ничего не навязывает содержимому вкладки.** Ни встроенного сброса, ни «значения по умолчанию» как
   понятия плагина: у контрола есть начальное значение, и только.
7. **Выбор из вариантов** — `choice:get()` отдаёт `{ text, index }`; таблицы — по одной на вариант, одни и те же на
   каждом вызове (`get()` в `on_frame` не плодит мусор). Менять их нельзя (в доке).
8. **TweakerUI ничего не знает** о вкладках и файлах скриптов: всё внутри плагина, хост не участвует ни
   протоколом, ни файлами.
9. **Сохранение — не механизм вкладок, а файлы скрипта** (`tw.storage`): `read_text`/`write_text`,
   `read_json`/`write_json` через `libyyjson`. `read_binary` не нужен — строки Lua двоичны.
10. **Пролог — в отдельные `.lua`**, вшиваются сборкой.
11. В модели событий поле `committed`, не `final` (контекстно-зарезервирован в C++, и `committed()` — словарь виджетов).
12. **Т5 — без `Tools/AgentKit`** (20.10): набор и скиллы ведёт своя сессия; ей отдана короткая сводка того, что
    изменилось в API 3.

Общий принцип, который за этим стоит, — скриптам даются примитивы (вкладка из контролов, файлы, JSON), а не
готовые под конкретную задачу помощники, и плагин не диктует, что на вкладке.

## §3. Устройство

### 3.1 Главное решение: модель в C, скрипт её описывает и читает

Скрипт **не рисует** свою вкладку. Он один раз (при загрузке или в `tw.on_ready`) **объявляет**, что на ней лежит,
и получает хэндлы контролов. Рисует вкладку C++ — каждый кадр, пока она видна, из модели, которой владеет плагин.
Значение контрола живёт в модели; виджет — его вид; скрипт читает модель (`ctl:get()`), пишет в неё (`ctl:set(v)`)
и подписывается на изменения (`ctl:on_change(fn)`).

```
скрипт (Lua)          tw.ui.tab{...}:toggle{...}      ctl:get() / ctl:set(v)      ctl:on_change(fn)
   │ объявление (раз)        │ FFI                        │ FFI, когда угодно         ▲ guarded, kind = ui
   ▼                         ▼                            ▼                           │
lua_tabs (DLL)     формы скриптов: хэндлы и поколения, порядок, подписи, очередь событий, связь с меню
   │                                                                                  ▲
   ▼                                                                                  │ события кадра
ui/form (tweaker_ui) узлы → виджеты: значение ⇄ set_*/value(), changed/committed → события
   │
   ▼
ui/widgets         toggle, slider, number_input, segmented, color_field, button, list_view, item_group
```

Тот же приём, что у панели неба (`sky_panel.cxx`): параметры объявлены, виджеты — по одному на параметр, значение
— у владельца. Здесь объявляет скрипт, а не шейдер.

### 3.2 Почему не биндинг виджетов один-к-одному (immediate mode из Lua)

Альтернатива — колбэк отрисовки вкладки и функции вида `tw.ui.slider(id, v, min, max) → v, changed`, зовущие
`slider::update()` прямо из Lua. Отвергнуто:

1. **ImGui-стек.** Колбэк шёл бы изнутри `menu::update`, посреди `tab_view::begin_view`/`end_view`. Группа и любой
   контейнер — пара вызовов, и ошибка Lua между ними оставляет стек несбалансированным. Планировщик **сознательно**
   обходится без снимка `ErrorRecovery` на скрипт (`lua_sched.hxx`, шапка): каждый `tw.hud.*` добавляет в draw list
   и возвращается. Immediate mode этот инвариант ломает.
2. **Флаги кадра.** `changed()`/`committed()` валидны до следующего `update()`. Скрипт, не дошедший до своего
   `update()` (ошибка выше, приостановка, ворота `ready`), теряет нажатие; до `ready` вкладка была бы пустой.
3. **Бюджет времени.** Отрисовка ушла бы в бюджет скрипта: открытое меню на тяжёлой вкладке приостанавливало бы
   скрипт, пока пользователь двигает его ползунок.
4. **Правила виджетов** — объект с временем жизни, стабильный `id`, без аллокаций в кадре — пришлось бы обеспечивать
   пулом по `(скрипт, id)` с вытеснением: тот же retained-слой, только спрятанный.

Цена — меньше свободы раскладки: вкладка — вертикальная стопка строк и групп, а не холст (§7).

### 3.3 `ui/form` — модель формы над виджетами (`tweaker_ui`)

`src/ui/form/form.{hxx,cxx}`, в `tweaker_ui` (без PCH, как `kit` и `widgets`), **ничего не знает про Lua**: его
снимает стенд, и он пригоден для `sky_panel`. Источник правды по API — `form.hxx`; в руководстве по виджетам —
раздел «Форма».

- `enum class kind` — `group`=0 … `list`=9; **нумерация — ABI** (Lua передаёт вид числом), только дописывать.
  `k_max_group_depth` = 2.
- `form(id)` — `id` области ImGui-идентификаторов формы; `add(kind, parent, label)` → номер узла или -1; `size`,
  `valid`, `kind_of`; `set_range`, `set_options`, `set_items`, `set_height` (список); `set_value`/`value`;
  `set_label` (подпись контрола, текст абзаца, заголовок группы); `set_tooltip`; `set_enabled`/`set_visible`;
  `draw()`; `events()` — что пользователь изменил за последний `draw()`, не больше одного на узел; `min_width()` —
  самая узкая страница, на которой форма помещается; `last_rect(node)` — для стенда.
- **Узел владеет своим виджетом** (`unique_ptr`, виджет в `std::variant`): рост вектора не двигает виджеты (у
  `color_field` внутри `popup_menu` с именем окна по номеру создания).
- **Значение — `double`** у всех: `bool` 0/1, целое, дробное, номер варианта, цвет как `u32` (`IM_COL32`).
  `set_value` нормализует по виду и игнорирует NaN.
- **Синхронизация** каждый кадр, по контракту виджетов (программная установка — no-op при том же значении и никогда
  не поднимает `changed()`): значение модели → `widget.set_*`; `update()`; `changed()`/`committed()` → модель и
  событие `{ node, value, committed }`. У контролов без жеста `committed` всегда `true`.
- **Пользователь главнее — и в модели, не только на экране.** Пока ползунок или цвет тянут (`active()` у `slider` и
  `color_field`), `set_value` формы игнорируется, а модель повторяет виджет. Иначе владелец, пишущий каждый кадр,
  оставлял бы в модели своё число под рукой пользователя, и `committed` на отпускании ушёл бы с числом владельца.
- **Выключенный узел рисуется под одним `begin_disabled()`** целиком — подпись `label_row` вместе с контролом.
  `form::begin_disabled()` — это `BeginDisabled` с `DisabledAlpha` темы (`theme::disabled_alpha`, 0.4; голый ImGui
  гасит до 0.6); им же `lua_tabs` выключает страницу приостановленного скрипта.
- **Раскладка**: группа — `item_group` во всю ширину; переключатель и число — `paint::label_row`; ползунок и цвет —
  своей строкой с подписью; выбор — `label_row`, а шире половины страницы — `paint::paragraph` подписи над ним;
  кнопка — ширина по подписи (меряется на `draw`, не при `set_label`); текст — `paint::paragraph`; разделитель —
  `ImGui::Separator`; список — `list_view` заданной высоты.
- **Подсказка** — `kit::hovering` по строке с `HoverDelayNormal`; строку под указателем забирает самая внутренняя.
- **`min_width()`**: полоса чипов `segmented` не сжимается, и в узкой странице не помещается даже под подписью.
  Форма меряет нужную ширину по факту раскладки (с отступами рамок), меню держит по ней минимум окна (§3.4).
- **Без аллокаций в кадре**: события — в векторе, зарезервированном под число узлов; подписи присваиваются только
  при отличии.

Что для этого появилось в самих виджетах: `set_enabled` у `slider`, `number_input`, `color_field`, `list_view`;
`active()` у `slider` и `color_field`; `item_group::set_fill_width`; рецепт `paint::paragraph`.

### 3.4 Динамические вкладки меню (`tweaker_ui`)

Колонка навигации раньше строилась один раз, на первом кадре. Скрипты приходят и уходят в любой момент — rescan,
Reload, переключение, падение. Источник правды — `ui/plugins/interactive/menu.hxx`:

```cpp
using dynamic_tab_draw_fn = float (*)(int token);   // рисует страницу, возвращает form::min_width()

struct dynamic_tab {
    std::string_view key;   // стабильная личность: "<файл скрипта>#<номер вкладки в скрипте>"
    std::string_view label; // окончательная - с приставкой при совпадении (§2.3), её считает lua_tabs
    dynamic_tab_draw_fn draw = nullptr;
    int token = 0;          // что вернуть в draw
    bool enabled = true;    // false - подпись приглушена (§2.5); страницу гасит сам владелец
};

void set_dynamic_tabs(std::span<const dynamic_tab> tabs) noexcept;   // весь список, применяется в начале update()
std::vector<std::string> fixed_tab_labels();                          // встроенные + add_extra_tab, по порядку
```

- Вкладки идут **после** встроенных и `add_extra_tab` (Skybox, Scripts): те не сдвигаются никогда, и
  `extra_tab_selected(handle)` остаётся верным.
- `set_dynamic_tabs` можно звать когда угодно, в том числе изнутри `menu::update` (Reload из вкладки Scripts):
  список копируется и применяется в начале следующего `update()`, снаружи `tab_view` — и когда меню скрыто.
- **Список с теми же ключами** (Reload: выгрузка и запуск синхронны) — колонка не пересобирается: только
  `tab_view::set_label`/`set_tab_enabled`, токены и функции отрисовки берутся из нового списка. Стенд: кадры
  `relabelled-dimmed` и `same-list-resent` сцены `menu-dynamic-tabs` побайтно равны.
- **Иначе — пересборка с выбором по ключу**, без перехода; пропала выбранная — выбрана предыдущая, тоже без
  перехода (страницы, с которой гасить, уже нет).
- **Страница ключуется ключом вкладки** (`tab_view::set_tab_id`), а не индексом: прокрутка и состояние виджетов не
  переезжают к соседу, когда вкладки перед ней приходят и уходят.
- **Ширина окна**: возвращённое `draw` — минимум окна, пока вкладка открыта (по `tab_view::nav_width()` и
  измеренным отступам); при входе на вкладку окно раздвигается, как для Player.
- `tab_view` для этого получил `set_tabs(labels, selected)` (выбор без перехода), `set_label`, `set_tab_enabled`
  (приглушает, кликабельна), `set_tab_id`, `nav_width`.

### 3.5 Скриптовая сторона: `lua_tabs` (DLL)

`src/lua/lua_tabs.{hxx,cxx}` — формы скриптов и связь с меню. Шапка `lua_tabs.hxx` — источник правды.

- **Хэндлы** — номер слота в младших 20 битах и поколение (11 бит) выше: одно `int`, которое держит пролог. Слот
  указывает на (вкладку, узел формы); вкладка — тоже слот (узел -1). Освобождённый слот переиспользуется только с
  новым поколением, так что старый хэндл не дотягивается до чужого узла. Проверка — по поколению, не по владельцу:
  `get()` зовут каждый кадр, а `caller_owner()` стоит `getfenv`.
- **Формы**: у вкладки — своя `ui::form` с id `s<скрипт>t<n>`; ключ вкладки — `"<файл>#<n>"`, где `n` — номер в
  порядке объявления за этот запуск. Перезагруженный скрипт, объявивший те же вкладки, получает те же ключи.
- **Время жизни.** `sched::unload(owner)` (выключение, Reload, падение при загрузке, пропажа файла) зовёт
  `drop_owner(owner)`: хэндлы инертны **сразу** (чтение — NaN, пролог отвечает начальным значением; запись —
  ничего), вкладки уходят из списка меню. **Формы освобождаются только в `end_frame()`**, в конце
  `lua_host::draw_frame`: Reload из вкладки Scripts происходит **внутри** `menu::update`, и страница того же
  скрипта может отрисоваться позже в том же кадре по старому токену — `draw` проверяет токен как хэндл и ничего не
  рисует.
- **Когда список уходит в меню.** `begin_frame()` в начале `lua_host::draw_frame` (после команд хоста, которые
  могут перезагрузить скрипт): если что-то объявили, выгрузили, переименовали — или сдвинулся
  `registry::revision()`. Перестановка, приостановка, Resume, переключение, перезагрузка — всё это уже двигает
  счётчик, поэтому отдельных крючков в `sched::reorder` и в приостановку нет. Вкладка появляется на кадр позже
  объявления. Сессия, где ни один скрипт вкладку не объявил, меню не трогает вовсе.
- **Порядок и подписи** считаются в `publish()`: `registry::order()`, внутри скрипта — по номеру объявления;
  совпадения (§2.3) — с `menu::fixed_tab_labels()` и между скриптами, без учёта регистра; пустая подпись — имя
  скрипта. У приостановленного `enabled = false`.
- **Отрисовка** (`draw_tab`): у приостановленного — `form::begin_disabled()` на всю страницу (§2.5), `form::draw()`,
  события формы — в очередь, `return form.min_width()`. Ни одного входа в Lua.
- **Очередь событий**: флаг «ожидает» на слоте + индекс слота в векторе; одно событие на контрол, последнее
  значение побеждает, `committed` копится через ИЛИ (отпускание, за которым начался новый жест, не теряется);
  порядок — по первому изменению. Вектор резервируется под число слотов при их создании, так что кадр не
  аллоцирует. `next_event` пропускает мёртвые слоты и **выбрасывает события приостановленного скрипта**: его
  страница выключена, и событие — разве что из кадра приостановки. Очередь живёт, пока игра не `ready`.
- **Пределы** — от честных ошибок, не граница безопасности: подпись, подсказка, вариант, строка списка ≤ 96 байт
  (обрезка без разреза UTF-8), абзац ≤ 1024, вариантов ≤ 16, строк ≤ 512, узлов на скрипт (с вкладками) ≤ 1024.
  Нарушение — диагностика `lua_diag` с местом `tw.ui` и обрезка либо инертный хэндл, не ошибка Lua: скрипт с
  одной кривой строкой настроек работает дальше. Места в скрипте C не знает, а спрашивать его у Lua на каждом
  `set` дорого. Число вкладок не ограничено (§2.1).

### 3.6 `tw.ui`: пролог и C ABI

Секция `prelude/ui.lua` (`tw.ui`, между `tw.callbacks` и `tw.storage`), ABI — `api/api_ui.{hxx,cxx}`, каждая
функция — тонкий проход в `lua_tabs`.

- **Типы хэндлов**: `TabHandle`, `GroupHandle`, `ControlHandle` (переключатель, ползунок, число, цвет),
  `ChoiceHandle`, `ListHandle`, `ButtonHandle`, `ParagraphHandle` (абзац), `SeparatorHandle` — в
  `S.handle_types`. Методы скопированы в каждый тип (`handle_type(...)`), а не цепочкой метатаблиц: поиск — один
  шаг, и типы в описании API — плоские списки. **Имя, занятое дважды, останавливает пролог**: абзац назывался
  `TextHandle`, пока сверка `api.json` не показала, что так уже зовут строковый канал и запись его перезаписала.
- **Объявление** (`tw.ui.tab`, конструкторы на вкладке и группе, `on_change`, `on_click`) — только в окне
  регистрации: `S.window_open` и `S.may_register` из `tw.callbacks` — те же, а не копии. Отказ — диагностика и
  инертный хэндл (`id = -1`). Аргументы конструкторов — таблица (голая строка — подпись); поле не того типа —
  ошибка Lua на строке скрипта.
- **Чтение и запись** — откуда угодно. `get()`: переключатель — boolean, выбор — таблица варианта (индексы с 1),
  список — строка с 1 или `nil`, остальное — число; NaN от C (инертный или мёртвый хэндл) → начальное значение,
  посчитанное C при объявлении (зажатое, округлённое). `set()` событий не поднимает. Вариант, которого нет
  (`choice:set("Up")`, `value = "Up"` из старого файла), — предупреждение в диагностику и без изменений, не ошибка:
  настройки читаются из файла, а его мог написать прошлый выпуск скрипта.
- **`on_change(fn)` / `on_click(fn)`** — колбэк вида `callback::ui` = 8 (`K_UI`, имя `on_change`):
  `fn(value, committed)` под `guarded` (передаёт до двух аргументов), в бюджете скрипта. Обработчики — по номеру
  узла; номер несёт поколение, так что узел перезагруженного скрипта старых обработчиков не находит.
- **`exports.dispatch_ui`** — в `sched::draw_frame` **после** диспетчеров жизненного цикла и **до**
  `dispatch_frame`, только в `ready` и только когда `tabs::has_events()` — без входа в VM на пустой очереди. Меню
  рисуется раньше `lua_host::draw_frame` в том же кадре, поэтому задержка — ноль кадров.
- **Выгрузка**: `ui.lua` оборачивает `exports.unload_owner` — сначала `on_unload` скрипта (он ещё может прочитать
  свои контролы), потом снимаются его обработчики; C-половину делает `tabs::drop_owner`.
- **`S.method_returns`** — что возвращают методы (конструкторы — новый узел, остальное — свой хэндл, для цепочек);
  `ljtest` пишет это в `api.json` полем `returns` у типов, и `tw.def.lua` даёт LuaLS дополнять методы контрола после
  `tab:toggle{...}`.

```
int    tw_ui_tab(int owner, const char* label)                         -> хэндл или -1
int    tw_ui_add(int parent, int kind, const char* label)              -- владелец - у родителя
void   tw_ui_range(int node, double min, double max)
void   tw_ui_options(int node, const char* const* labels, int count)
void   tw_ui_items(int node, const char* const* text, const char* const* sub, int count)
void   tw_ui_height(int node, float height)                            -- список
double tw_ui_get(int node)                                             -- NaN у неживого
void   tw_ui_set(int node, double value)
void   tw_ui_text(int node, int which, const char* text)              -- 0 подпись / текст, 1 подсказка
void   tw_ui_flags(int node, int enabled, int visible)                -- 1, 0, -1 = не трогать
int    tw_ui_tab_visible(int node)                                     -- этот кадр или прошлый
int    tw_ui_next_event(int* node, double* value, int* committed)      -- для dispatch_ui; 0 - пусто
```

### 3.7 Цена

- Меню закрыто: **ноль** — вкладки не рисуются, событий нет, `dispatch_ui` даже не зовётся.
- Открыта вкладка скрипта: только C++ — те же виджеты, что во вкладке Tweaks. Lua не входит.
- `ctl:get()` в `on_frame`/`on_tick` — один FFI-вызов, в трассе — прямой вызов (`lua-scripting.md` §2.2).

### 3.8 Файлы скрипта: `tw.storage`

`src/lua/lua_storage.{hxx,cxx}`, ABI — `api/api_storage.{hxx,cxx}`, секция `prelude/storage.lua` (`tw.storage`,
перед `tw.sandbox`). Шапка `lua_storage.hxx` — источник правды.

- **Где**: `engine\TweakerStuff\ScriptData\<файл скрипта без .lua>\` (`paths::script_data_dir()`) — по имени файла,
  как `scripts.cfg`: Reload, переключение, пересборка `twllink` видят ту же папку; переименованный скрипт — новый.
  Папка создаётся при первой записи.
- **Имена** — плоские, `[A-Za-z0-9_.-]{1,64}`, не с точки: `..`, разделители и диски невыразимы. Проверка — в одном
  месте, `storage::valid_name`. Квоты: 1 МиБ на файл, 64 файла, 8 МиБ на папку; перезапись вычитает старый
  размер. **Файлы, уже лежащие на диске, считаются** — список папки читается при первом обращении к хранилищу после
  загрузки скрипта (один системный вызов); имена, которых скрипт не смог бы написать, — не его.
- **Запись** кладёт байты в память (последняя версия на имя побеждает) и сразу возвращает `true`; свой поток пишет
  на диск раз в 100 мс через `<имя>~tmp` (тильда в имени скрипта невозможна) и `MoveFileEx(REPLACE_EXISTING)`.
  Без `FlushFileBuffers`: от падения игры защищает и так (данные уже у ОС), от пропадания питания — нет, а цена
  была бы десять сбросов в секунду у скрипта, пишущего каждый кадр. Два замка: `g_lock` — состояние (поток
  копирует грязное под ним и пишет без него), `g_io_lock` — один проход записи за раз.
- **Чтение** — из той же памяти; первое чтение файла с диска читает его (системный вызов — поэтому «читать при
  загрузке»). Своя ещё не записанная запись читается сразу.
- **Выгрузка скрипта** (`sched::unload` → `storage::drop_owner`) пишет его файлы синхронно и забывает его:
  перезагруженный скрипт читает диск заново, с правкой руками. `shutdown()` дописывает всё — но **при закрытии
  игры `lua_host::shutdown` не вызывается вовсе** (§6), и записанное за последние ≤ 100 мс до выхода может
  пропасть.
- **Что поток не смог записать** — в список под замком; `pump()` каждый кадр (одна атомарная проверка) отдаёт это в
  диагностику скрипта: `lua_diag` не потокобезопасен.
- **Ошибки — результатом `nil, причина`**, не исключением: `read_json(...) or {}` — весь первый запуск. Ошибка Lua
  — только неверный аргумент (имя не строка, `write_text` не строкой, `write_json` не таблицей).
- **JSON ↔ Lua — лентой.** FFI-функция не может класть значения на стек Lua, а `lua_CFunction` слой не использует,
  поэтому C отдаёт **ленту**: значения в прямом порядке, по `json_node { type, count, number, str, len }` (раскладка
  — ABI, пролог объявляет ту же структуру), из которой пролог строит таблицы; запись — та же лента обратно, C
  строит `yyjson_mut_doc`. Чтение прощает BOM, комментарии и хвостовые запятые. Запись — два пробела, перевод
  строки в конце, целые без дроби; ключи сортирует пролог. Отказ записи: NaN/inf, смешанные ключи, дырка в
  массиве, ключ не строка и не `1..n`, функция/userdata, цикл, глубина > 64; не UTF-8 ловит `yyjson`. `null` при
  чтении — ключа нет; файл, где только `null`, — `nil, "<имя> holds null"`.

| JSON | Lua | Обратно |
|---|---|---|
| объект | таблица со строковыми ключами | таблица, где все ключи — строки |
| массив | последовательность `1..n` | таблица, где ключи — ровно `1..n`, `n ≥ 1` |
| `{}` / `[]` | пустая таблица | пустая таблица → `{}` |
| строка, `true`/`false` | строка, boolean | — |
| число | number (целые за 2^53 теряют точность) | `NaN`/`inf` — отказ |
| `null` | `nil` (ключ пропадает; в массиве — дырка) | — |

```
int         tw_storage_read(int owner, const char* name, const char** data, int* size)
int         tw_storage_write(int owner, const char* name, const char* data, int size)
int         tw_storage_read_json(int owner, const char* name, const void** tape, int* count)
int         tw_storage_write_json(int owner, const char* name, const void* tape, int count)
int         tw_storage_exists(int owner, const char* name)
int         tw_storage_remove(int owner, const char* name)
const char* tw_storage_list(int owner)                    -- по имени на строку
const char* tw_storage_error(void)                        -- почему последний вызов вернул 0
```

`io` и `os` по-прежнему убраны песочницей, `twllink` по-прежнему отвергает `io.open` (TW0301). `tw.storage` — не
дыра в песочнице, а её законная замена.

### 3.9 Пролог в отдельных файлах

- `src/lua/prelude/abi.lua`, `core.lua`, `channels.lua`, `hud.lua`, `callbacks.lua`, `ui.lua`, `storage.lua`,
  `sandbox.lua` — код рядом с кодом: это половина слоя, а не ассет.
- **Порядок и имена чанков — только таблица `k_sections` в `lua_prelude.cxx`** (`{ "=tw.core", text::core }`):
  порядок значим (каждая секция берёт нужное у предыдущих через `S`, песочница — последней), и задаёт его код, а
  не сортировка имён файлов. Чанк — `"=tw.<имя файла>"`.
- **Вшивание — сгенерированным заголовком.** `cmake/EmbedText.cmake` (режим скрипта) по `GLOB CONFIGURE_DEPENDS
  prelude/*.lua` пишет `<дерево>/src/lua/generated/lua/lua_prelude_text.hxx`: `tw::lua::prelude::text::<имя файла>`
  — `constexpr std::string_view` над массивом `'\xHH'` (ни разделителя, который встретится в тексте, ни предела
  длины литерала). Отдельная цель `tweaker_prelude_text` + `add_dependencies`, а не источник `TweakerPlugin`:
  цель плагина создана в корневом каталоге, и выход `add_custom_command` из `src/lua` её сборку не цепляет.
  *Отвергнуто:* ресурс `TW_TEXT` через `src/resource/` — тот путь для ассетов, которые ищутся во время работы,
  а прологу нужна гарантия «есть с момента загрузки DLL».
- **`ljtest` читает те же файлы по той же таблице** (разбирает строки `k_sections`) и грузит их под теми же
  именами чанков.
- **Новая секция** — файл в `prelude/` плюс строка в `k_sections` (перед `tw.sandbox`), и в `ljtest` поправить
  проверку числа секций (сейчас восемь) и пробу `k_section_probe`. Каждое новое имя в `k_entry_points`
  (`lua_vm.cxx`) — сигнатура в `abi.lua` и заглушка в `ljtest` в той же правке: пролог сверяет имена в обе стороны
  и без них не стартует.
- `S.unpublished` — имена, которые описание API пропускает, пока секция строится раньше своей документации
  (так жили `tw.ui` и `tw.storage` до API 3; сейчас пусто).

## §6. Ловушки и находки

- **ImGui до контекста.** При ранней загрузке тела скриптов исполняются до того, как оверлей создал контекст
  ImGui. `tw_theme_color` упаковывал цвет через `paint::to_u32` — рецепт *рисования*, который подмешивает
  `Style.Alpha` и читает `GImGui` без проверки, — и `tw.theme(...)` в теле скрипта роняло игру на старте
  (`0xc0000005` в `TweakerPlugin.dll`; нашла проба в первом же запуске). Ошибка жила с появления `tw.theme`, но
  все поставляемые скрипты звали его только из `on_frame`. Теперь — `ImGui::ColorConvertFloat4ToU32`, чистая
  функция. **Правило — в шапке `api_hud.hxx`**: всё, что скрипт может позвать, допустимо и из тела; рисование
  охраняет `inside_frame`, замеры — `imgui_ready`. Объявление вкладки (`lua_tabs`, `form::add`/`set_*`, сеттеры
  виджетов) ImGui вне `draw` не трогает. Офлайн это не ловится: харнессы гоняют пролог против заглушек.
- **`lua_host::shutdown` при закрытии игры не вызывается** — плагин его не зовёт, игра просто завершает процесс.
  Для `tw.storage` это значит: при выходе из игры теряется записанное за последние ≤ 100 мс (при выгрузке скрипта
  всё пишется сразу). Для настроек, сохраняемых на отпускании контрола, на практике недостижимо; если понадобится —
  подписка на закрытие окна через `wndproc_hub` (§7). Тот же факт касается лога скриптов.
- **Reload изнутри кадра меню.** Выключатель и Reload во вкладке Scripts срабатывают внутри `menu::update`; отсюда
  отложенное освобождение форм и токен, который проверяется как хэндл (§3.5), и `set_dynamic_tabs`, который
  только откладывает список (§3.4).
- **Имена типов хэндлов — общее пространство** с `tw.channels`: `TextHandle` уже был; теперь повтор останавливает
  пролог.
- **`x86-release` месяц собирался как Debug** (кэш `CMAKE_BUILD_TYPE=Debug` с 22.09; сторож в корневом
  `CMakeLists.txt` ловит только пустой тип). Найдено при Т0; лечится `cmake --preset x86-release` из шелла с
  `vcvarsall amd64_x86`.
- **CMake**: склейка текста `string(CONCAT)` без кавычек съедает `;` как разделители списка; `REGEX REPLACE` с
