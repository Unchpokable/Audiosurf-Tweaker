**Developer Bundle** — так называется вариант поставки с полным набором инструментов разработки скриптов и
реверса. Это не отдельный архив: всё лежит в `<TweakerUI>\DevTools\` той же поставки.

## 1. Что есть сейчас и что найдено при разборе

- **В поставке** из инструментов только `DevTools\Binaries\twllink.exe` (`Scripts/Deploy*.{ps1,sh}`).
  Документации нет никакой; в проекте у автора — `.twllink/tw.def.lua` и схема манифеста. Шапка шаблона
  `--new` (`TweakerLuaLinker/Project/Scaffold.cs`) ссылается на «api-reference.md in the Tweaker's repository»
  без ссылки.
- **Публичный мануал ведёт во внутренние журналы**: `Docs/scripting/game-model.md` («How to find the thing you
  want», шаг 2), `hooks.md`, `Docs/scripting.md` («Getting help»).
- **CgrPy к поставке не готов**:
  - `cgr/paths.py` ищет игру от корня репозитория (`parents[3]/Audiosurf_Steam`) — из `DevTools\CgrPy\` это
    `<TweakerUI>\Audiosurf_Steam`; Steam-библиотеки на других дисках не находятся; `AUDIOSURF_DIR` принимается
    только корнем игры (`twllink` принимает и `engine\`);
  - запуск — только `uvrun.bat`, пары `.sh` нет, а имя `uvrun` в `PATH` редактора ничего не говорит;
  - 54 ссылки на `Docs/Internal` и журналы в docstring-ах девяти `.py` и в README; раздел README «Why it lives
    here» — история репозитория;
  - локально есть `__pycache__/` и `.cache/` (gitignore) — в поставку не должны попасть.
- **Расхождения в документации** (чинятся в Ф2):
  - `game-model.md` дважды называет Group Inspector скриптом, который «ships with the Tweaker»; на деле это
    `assets/scripts/dev/_groups.lua`, а `dev/` не поставляется. Владелец: этот скрипт мусорный и не
    поставляется вовсе; нормальный Group Inspector — эталонная задача приёмки (Ф6);
  - `Scripts/Deploy.ps1` (и, вероятно, пара) ссылается на `script-manager-roadmap.md` — давно `script-manager.md`;
  - `authoring.md` («What the built script looks like») показывает `@api 1`, `script-manager.md` §3 — `"api": 1`
    и JSON с «API 1»; текущий API — 2.
- **Точка встраивания** — `ScriptDevViewModel.Create`: `twllink --new`, затем правка манифеста. Обвязка для
  агентов — третий шаг там же, `twllink` о ней не знает. Образец обновления управляемых файлов уже есть:
  `PluginInstallation` по `.deploy.json` (нетронутое — заменить молча, правленое — не терять).

## 2. Решения владельца (18.10.2026)

Номера — номера вопросов из обсуждения; код и документы ссылаются на них как `dev-bundle-roadmap.md §2.N`.

**Поставка и CgrPy**

1. Developer Bundle — всё в `DevTools\` той же поставки, отдельного архива нет.
2. `uv.exe` **не поставляется**. Ищется в `PATH`; не нашёлся — запускалка CgrPy (и Script Dev) с лёгким укором
   «это было в README» предлагает `winget install --id=astral-sh.uv -e`.
3. Python и пакеты при первом запуске качаются из сети — приемлемо: тащить с собой гигабайты незачем.
4. Запускалка переименовывается в `cgrpy` (`cgrpy.cmd` + `cgrpy` для Git Bash) и кладётся в `PATH` редактора
   вместе с `Binaries\`. `uvrun` в репозитории убирается, ссылки на него в журналах правятся.
5. `examples/` поставляются: это рабочие образцы разовых запросов.
6. **Все кэши — только внутри папки установки Tweaker** (там руки развязаны). В `%LOCALAPPDATA%` и прочие
   пользовательские папки кэши не пишутся.
7. `meshes` с записью (`splice`) — предупреждение и эвристика «это живая игра»: в пути есть `steam`,
   `steamapps`, `12900` (AppID Audiosurf), или рядом/выше лежат `.vdf`. Живая игра — отказ с объяснением,
   что можно испортить себе установку; локальная копия — молча делать. Инструмент нужен и тем, кто моддит
   игру без скриптов: внутренности и CgrPy полезны шире скриптового слоя.

**Документация**

8. Публичные мануалы о внутренностях — без рендера и аудио: ими пока пользуется только плагин. Отложено.
9. Правило в CLAUDE.md: журналы — источник правды, публичный мануал производный; находка, меняющая публичное
   утверждение, правит мануал в том же коммите.
10. Ссылки — на публичный репозиторий https://github.com/Unchpokable/Audiosurf-Tweaker, на ветку по умолчанию
    (`blob/HEAD/...`, GitHub разворачивает `HEAD` в ветку по умолчанию; проверить в Ф0). Тегов релизов нет.
11. Публичная документация (`scripting`, `skyboxes`, новые `internals`) поставляется в `DevTools\Docs\`.
12. `_groups.lua` не поставляется. Нормальный Group Inspector пишется как проверка обвязки (Ф6).

**AI-обвязка**

13. Поддерживаются три системы: **Claude Code, Codex, Cursor**. Остальные малопопулярны или читают чью-то из
    этих нотаций.
14. Канонический скилл — один; у каждого агента своя минимальная обвязка в его нотации, которая содержит
    описание скилла (для срабатывания) и «полное описание — в X, читай там».
15. Владение файлами: скиллы и копия документации — **управляемые**: нетронутые молча обновляются с новой
    версией Tweaker, правленые пользователем остаются, обновление предлагается. `AGENTS.md` — **пользователя**:
    пишется один раз, управляемая часть — между маркерами.
16. Предлагается галочкой в форме нового проекта и кнопкой у любого проекта, включая открытые извне. Выбор
    агентов запоминается.
17. В коммитимых файлах обвязки абсолютных путей нет. Машинное — в игнорируемом `.tweaker/local.json` (путь к
    игре, к `DevTools`), Tweaker переписывает его при каждом открытии проекта. Нет файла — скилл велит агенту
    спросить пользователя.
18. **Tweaker не пишет конфигов агентов и MCP.** Скилл декомпиляции сам просит агента поискать в своём окружении
    MCP-серверы известных декомпиляторов и скиллы пользователя; не нашёл — объяснить пользователю, что
    поставить, с приоритетами (IDA Pro MCP — самое мощное, но IDA платная; Ghidra — хуже, но бесплатная, ставится
    так-то; и т.д.).
19. CLI агентов и их отдельные приложения — позже (скорее всего придётся). Пока в публичной доке: «для работы с
    агентами, вероятно, понадобится расширение Claude Code или Codex для VS Code; CLI и standalone-приложения —
    позже».
20. `.gitignore`-строки обвязки дописывает Tweaker; `twllink --new` не меняется.

**Скиллы**

21. Нужен скилл **цикла проверки в игре**. Он прямо говорит: у агента сейчас нет надёжного способа самому
    заглянуть в игру и достоверно увидеть, что сделал скрипт, — это ответственность пользователя. Пользователь
    может дать агенту отмашку «лепи как хочешь», но сломанная после этого игра — тоже его ответственность.
22. **Логи скриптов в файл** нужны — и без агентов: их отсутствие — архитектурное упущение плагина.
23. Скилл бинарников — ориентация и рецепты со ссылками на публичный мануал по ABI, плюс явное правило: при
    любой сомнительной находке перестать верить бумажкам и вскрыть игру декомпилятором.
24. Мы сами ничего не устанавливаем. Агент может объяснить, где взять и как настроить, и помочь подготовить, но
    не ставит софт втихаря.
25. В скиллах явно: только своя копия игры, ничего из неё не публиковать, базы декомпилятора — на копии.

**Приёмка и порядок**

26. Проверка (§5): тест, что каждое `tw.*`-имя в скиллах и мануалах есть в `api.json`, а каждая упомянутая
    команда CgrPy существует; прогон субагента на эталонных задачах в сгенерированном проекте; владелец — на игре.
27. Фазы по одной, с приёмкой владельца каждой; объединять — только по его явному слову.

**Дополнение (18.10.2026)**

28. Нужен скилл **допроса** (`audiosurf-grill`, §3.5 п. 6). У агента будет огромный арсенал инструментов и
    документации, но ни малейшего понятия, что с ним делать, когда первый запрос — «хочу красивый HUD, и чтоб
    фейерверки». Так пишет человек, который без AI к программированию не притрагивался, и таких сейчас много.
    Агент обязан допросить с пристрастием и выяснить, что надо сделать в итоге. Пишем сами, а не берём готовый
    из интернета, потому что специфику игры можно заложить заранее. Тогда агент задаёт **конкретные вопросы
    про Audiosurf**, а от запроса вида «сделай, чтобы Undo у Eraser Elite не обрезало сохранённые блоки по
    свободным ячейкам доски, а пушило с переполнением и сразу сжигало получившиеся совпадения» у него не сводит
    мозг.
29. Для этого скилла нужно знание игры глазами игрока, а в журналах его нет: они описывают граф каналов, а не
    то, что человек видит на экране и как в это играют. Его даёт владелец в отдельной фазе-интервью (Ф4a).
30. **Лог скриптов — свой файл на каждый сеанс, `scripts-<дата_время>.log`**, а не пара «основной» `scripts.log` +
    «вчерашний» `scripts.1.log` (18.10, по итогам проверки Ф3). Пользователь с проблемным скриптом должен
    приложить лог к GitHub Issue как есть, ничего не переименовывая в папке игры, — а при вращении файл сеанса
    меняет имя или пропадает со следующим же запуском.
31. **Запрос, который нынешний Lua API не поддерживает** (вычитка Ф4b, 18.10; пример — «сделай старый Undo у
    Eraser»): правильный ответ агента — прямо «текущая версия Lua API TweakerPlugin этого не поддерживает» и
    предложение помочь написать issue разработчикам на GitHub. Только при настойчивом «всё равно делай» — пытаться
    собрать, что позволяет нынешний API, заранее сказав, чего не будет. API сырой и умеет мало — это ожидаемо, и
    «нужна правка Tweaker» — нормальный вердикт, а не провал.
32. **Тонкость допроса — по собеседнику.** Набор рассчитан на игрока-не-программиста; со сложными задачами придёт
    скорее моддер с инженерной квалификацией, с которым агент говорит на равных и уточняет задачу по месту, без
    допроса «как ребёнка».
33. **Направление на будущее, не решение** (владелец, 18.10): либо постоянное расширение безопасного API в Tweaker,
    либо, временно, **Unsafe API** — `os`, сырой FFI, `loadlibrary`, `tw::set_channel_shim(vtable_ptr)`,
    `tw::make_vtable(chtype)` и прочая низкоуровневая работа с чужой памятью: дыра в безопасности и стабильности, но
    «нереализуемо» превращается в «можно, залезши в кишки игры». В скиллах сейчас не упоминается; при появлении —
    свой скилл и правка вердиктов `audiosurf-grill`.

### 3.2 CgrPy как продукт

- **Поиск игры** (`cgr/paths.py`): `AUDIOSURF_DIR` — корень игры **или** `engine\`, как у `twllink`; затем
  Steam: путь из реестра (`HKCU\Software\Valve\Steam\SteamPath`) и все библиотеки из
  `steamapps\libraryfolders.vdf`, в каждой `steamapps\common\Audiosurf`; кандидат «репозиторий» — только если

- **Запускалки** `cgrpy.cmd` и `cgrpy` (Git Bash) с одинаковым поведением; нет `uv` — сообщение из §2.2.
- **`meshes`** — защита живой игры (§2.7) на всех записывающих подкомандах.
- **README** по-английски, для пользователя Tweaker: что это, установка (`uv`), две семьи инструментов,
  каждая команда с примером, ловушки, `examples/`. Ссылки на находки — на публичные мануалы `Docs/internals/`

  Russian». То же — в docstring-ах и в выводе «where it was used».
- **Сверка с действительностью** — каждая команда прогоняется (Ф0), цифры (`161 groups, 131356 channels`,
  `meshes verify` 893/930) перепроверяются, расхождения правятся в README или в коде.

### 3.4 Логи скриптов в файл (плагин)

`engine\TweakerStuff\Logs\scripts-<дата_время>.log` (§2.30; было `scripts.log`) — то, что сейчас видно только в ленте и во вкладке Scripts оверлея:
ошибки загрузки и выполнения (с позициями в модулях после `.lua.map` и трассировкой), `tw.warn`,
приостановки и Resume, смены состояния скрипта (включён, выключен, перезагружен), смены `engine_state`.
Требования:

- **В кадре — без системных вызовов** (правило рендер-потока): запись в кадре — в кольцевой буфер без
  аллокаций, на диск — с другого потока или с холодного пути.
- Источник — `lua_diag` (там уже дедупликация); в файл идёт то же, что в ленту, плюс трассировка.
- Сеанс игры — свой файл, имя по времени старта, ни переименований, ни переиспользования (§2.30); старые
  сеансы не копятся без конца; предел размера.
- Строка с меткой времени и номером кадра движка — чтобы агент мог сопоставить «сохранил → перезагрузилось →
  упало».
- Харнесс — расширение `schedtest`/`remotetest`.

### 3.5 AgentKit — содержимое

Исходник — `Tools/AgentKit/` в репозитории, в поставке — `DevTools\AgentKit\`. Всё по-английски.

В проекте после настройки:

```
my_hud/
  AGENTS.md                      пользователя; управляемый блок между <!-- tweaker:begin --> и <!-- tweaker:end -->;
                                 его читают все три агента (Claude Code — через CLAUDE.md, см. ниже)
  .agents/skills/<имя>/          канонические скиллы: SKILL.md (+ references/); Codex и Cursor читают отсюда сами
  .tweaker/
    manifest.json                управляемые файлы и их хеши (коммитится)
    local.json                   путь к игре и к DevTools (gitignore, переписывается при открытии)
    docs/                        копия DevTools\Docs (управляемая)
  CLAUDE.md                      только если выбран Claude Code: @AGENTS.md (Ф0: старые версии и ловушка вложенности)
  .claude/skills/<имя>/SKILL.md  только если выбран Claude Code: name + description + «читай .agents/skills/<имя>/»
```

Для Codex и Cursor отдельных файлов нет (Ф0): им хватает `AGENTS.md` и `.agents/skills/`. Выбор агентов в форме
(§3.6) решает только, писать ли две строки Claude Code.

**`AGENTS.md`, управляемый блок** — что это за проект (скрипт для плагина Audiosurf Tweaker, `twllink`), команды
(`twllink`, `twllink --install`, `twllink --json`, `cgrpy`), где документация (`.tweaker/docs/`), список скиллов
и когда какой, жёсткие правила (§2.24, §2.25, что в игре трогать нельзя), правило «агент не видит игру» (§2.21).

**Скиллы:**

1. **`tweaker-lua-api`** — жизненный цикл скрипта, `tw.*` по разделам со ссылками на `.tweaker/docs/`,
   песочница, бюджеты (5 ошибок/300 кадров, 4 мс), порядок выполнения и место в HUD, цикл `twllink` (`--json`,
   коды TWxxxx), установка и перезагрузка, типовые ошибки.
2. **`audiosurf-game-files`** — как найти игру (`.tweaker/local.json` → `AUDIOSURF_DIR` → Steam; иначе спросить),
   раскладка `engine\` и `engine\TweakerStuff\`; белый список: писать в игру только через `twllink --install`;
   `scripts.cfg` при запущенной игре принадлежит плагину; не трогать `.cgr`, `channels\`, DLL плагина, файл
   `DISABLE`; ничего из игры не распространять и не коммитить.
3. **`cgrpy`** — две семьи команд, `build_proj` и проверка `unparsed bytes`, `render find/chain/callers`, разовые
   запросы на `cgr.project` по образцу `examples/`, индекс против имени, «находка не проверена, пока пробный
   скрипт не показал её в игре».
4. **`audiosurf-in-game-loop`** (§2.21) — пробный скрипт (`tw.notify`, `tw.warn`, хук на `Do_`-обработчик), сборка
   и установка, что сказать пользователю проверить, лог скриптов (§3.4; последний по имени `Logs\scripts-*.log`)
   как единственный канал обратной связи,
   «отмашка» и ответственность.
5. **`audiosurf-binaries`** (галочка, по умолчанию выключена) — модули игры и где что; рецепты
   (vtable канального типа, `SetVector`-подобный вопрос об ABI, поиск класса по импортам); инструменты по
   приоритету: найти у себя MCP декомпилятора или скилл пользователя → иначе объяснить пользователю (IDA Pro MCP,
   Ghidra, …) → план C: CgrPy `disasm`/`vtdump`/`symbols`/`findvt`; работа на копии игры (базы IDA пишутся рядом с
   бинарём); «бумажки против дизассемблера» (§2.23); ловушка ICF.

6. **`audiosurf-grill`** (§2.28) — допрос перед работой. Срабатывает на первом запросе в проекте и на любом
   расплывчатом, «эстетическом» или написанном игровым жаргоном («красивый HUD», «чтоб Eraser…»). Что делает:
   - **пересказывает запрос в терминах игрока** и проверяет, что понял: режим и персонаж, сложность, когда
     (заезд, пауза, экран итогов, меню), где на экране, заменить элемент игры или добавить рядом, что при рестарте
     и паузе, как это должно ощущаться;
   - **спрашивает пачками и с вариантами по умолчанию**, не бесконечно: за раунд несколько вопросов, у каждого
     предложенный ответ. Уровень вопросов подстраивается под человека — новичку не говорят «канал» и «vtable»;
   - **переводит ответы в технический план**: какие группы и каналы искать (сначала карта и мануалы, затем
     CgrPy), что здесь чтение, что хук, что `tw.mute`, что запись в таблицу; что из `tw.hud` нужно; как ужиться с
     хромом оверлея, лентой уведомлений и другими скриптами (`tw.hud.occupied`/`place`);
   - **выносит вердикт осуществимости** по известным пределам: «можно», «можно с оговорками», «нужна правка
     плагина» (список недостающего в Lua API — публичный пересказ `reversing-journal-render.md` §8), «сейчас
     нельзя». Проверяется по документам и, при сомнении, по игре, а не по догадке;
   - **пишет короткое ТЗ** (что видит игрок, когда, что делаем, чего не делаем, что проверит пользователь в игре)
     и **ждёт подтверждения** до первой строки кода.

   Опора — справочник «Audiosurf глазами игрока» из интервью Ф4a. По умолчанию это публичный мануал
   `Docs/internals/playing-audiosurf.md`: он нужен и людям, не только агенту. Скилл ссылается на него и держит в
   себе только процесс и чек-лист вопросов. Справочник — глоссарий игрока (режимы и персонажи, способности,
   доска, совпадения, цепочка, медали и т.д.) **с привязкой каждого термина к группам и каналам**, карта экрана
   (что где нарисовано в заезде и вне его, чем это нарисовано) и то, как в это играют.

Управляемый блок `AGENTS.md` прямо велит начинать с `audiosurf-grill`, если запрос расплывчатый.

Публичная пометка (§2.19) — в `Docs/scripting/tweaker.md` и `authoring.md`.

### Ф0 — итоги разведки (18.10.2026)

**GitHub.** Ветка по умолчанию — `Revive`, репозиторий публичный (`gh repo view`). Ссылки вида
`https://github.com/Unchpokable/Audiosurf-Tweaker/blob/HEAD/<путь>` отвечают 200 и ведут на ветку по умолчанию —
ими и пользуемся (§2.10). Ссылка на файл, которого ещё нет в запушенной ветке (тот же `Docs/internals/`), до пуша
отдаёт 404: проверка ссылок — после пуша, а не по рабочей копии.

**CgrPy против README** — все восемь команд запускаются через `.\uvrun.bat`; примеры из README воспроизводятся
дословно:

| Утверждение | Итог |
|---|---|
| `vtdump --type "Array Vector"`: `SetVector` в слоте 18 | ✓ |
| `findvt --type "Array Unique" --min 23 --ret 20:4 --ret 22:0xc` — ровно один кандидат, `ArrayConnectItem` | ✓ (серия 61 слот — README честно предупреждает, что это не длина таблицы) |
| `symbols --imports`: `??0Aco_VectorChannel@@QAE@XZ` | ✓ |
| `disasm` `SetVector`: три dword с `[esp+4]`, `ret 0xc` | ✓ |
| `render find` `GridColor` — три канала; `callers` #202 → Material `ro_01` под Surface `ro_01 1` | ✓, но README не называет группу (`Render/RenderCommon.cgr`) |
| `meshes verify`: 893 побайтно, 930 через OBJ, 0 проблем | ✓ |
| `build_proj`: 161 группа, 131 356 каналов | ✓, 5,5 с («under a minute» с запасом) |
| `qchic.py`: 400 из 431 `Array Value` с `CHIC=1` | ✓ |

Что неверно или мешает поставке — всё в работу Ф1:

1. **`build_proj` предупреждает на каждом запуске.** Он сравнивает *сумму* неразобранных байтов с нулём, а у
   замеренного базового уровня их 3 141 960 в 17 группах (ровно те, что описаны в его docstring: `Squid_*`,
   `SetPieces*`, `XX_StartHere` и мелочь). Пример вывода в README и docstring показывает `0 unparsed bytes` —
   так не бывает. Нужно: базовый уровень **поимённо**, предупреждение — только на регрессии против него.
2. **Число групп зависит от установки.** Две из 161 — `Cache/Web/…/asradio/*.cgr`, скачанные песни Audiosurf Radio;
   у каждого игрока их свой набор. Базовый уровень и README не должны опираться на «161»; `Cache/` — исключить из
   разбора по умолчанию (это не логика игры).
3. **«Every tool prints its own usage when run with no arguments» — неправда** для `build_proj` (пересобирает кэш),
   `chtypes` (печатает всю таблицу) и `meshes` (делает инвентаризацию и **пишет `out\meshes.csv` в текущую папку**).
4. **`examples/writers.py` и `examples/genall.py` не запускаются**: открывают `proj.pkl` из текущей папки, а не
   через `cgr.paths`, и пишут `out/` туда же. Раз примеры поставляются как образец (§2.5), они обязаны работать.
   В docstring `qchic.py` — устаревшая ссылка на `lua_channels::read_array`.
5. **Короткое имя группы роняет `render`** голым `KeyError` с трейсбеком (`render find RenderCommon GridColor`).
   Принимать короткие имена так же, как `tw.*` и помощник из Ф4a.
6. **`§` в справке выводится как `�`** под кодовой страницей консоли cmd — запускалке `PYTHONIOENCODING=utf-8`.
7. **`.\` перед `uvrun`** и **Windows-пути в `PYTHONPATH` из Git Bash** — см. «первый настоящий прогон» ниже.
8. Из Git Bash `cmd //c '…"Array Vector"…'` ломает кавычки — это не баг инструмента, но довод за настоящую
   `.sh`-запускалку вместо «вызови `.bat` через cmd».

learn.chatgpt.com `build-skills`, developers.openai.com `guides/agents-md`; Cursor: cursor.com/docs `context/skills`,

**Как устроено и почему:**

- **В кадре ни одного системного вызова.** `write()` форматирует строку в буфер на стеке (≤ 8 КиБ, длиннее —
  обрезка с `...`), берёт спин-лок и копирует в кольцо 64 КиБ. Время — только `QueryPerformanceCounter` (его и так
  зовёт `lua_sched` на каждый колбэк); часы дня считает писатель из базы, снятой при открытии. Не влезло — строка
  выброшена и посчитана, на её месте в файле — `dropped … N line(s) lost`. Кадр не ждёт никогда.
- **Файл пишет свой поток**, раз в 100 мс просыпаясь по таймауту, а не по событию: `SetEvent` из кадра был бы тем
  самым системным вызовом. Спин-лок, а не lock-free кольцо: писателей двое (поток запуска при первой загрузке,
  потом поток движка), а держат его ровно на одну копию памяти.
- **`flush()` — синхронно, только с холодного пути** — отступление от «на диск с другого потока»: загрузка,
  переключение, перезагрузка, Rescan и смена порядка зовут его сами. Причина: перезагрузка — это то, что запускает
  сохранение автора, и если новый код уронит игру на первом же кадре, строка `reloaded` (и ошибка загрузки) должна
  уже быть на диске, а не в кольце. Эти пути и так читают файл с диска, правило рендер-потока их не касается.
  Остальное (ошибки кадра) может отстать от падения игры не больше чем на 100 мс: `lua_host::shutdown` в игре не
  зовётся, процесс просто кончается.
- **Сеанс — файл** (§2.30). `open()` создаёт `scripts-YYYY-MM-DD_hh-mm-ss.log` по местному времени старта, с
  `CREATE_NEW`: имя занято (второй запуск в ту же секунду) — `_2`, `_3`…, в чужой лог не пишет никогда. Имена
  сортируются по времени, последний по имени — свежий. Хранятся 20 новейших, вместе с текущим; старейшие
  удаляются при открытии, и только файлы **ровно** такого вида — переименованный, скопированный или старый
  `scripts.log` не трогается; не удалилось (открыт без `FILE_SHARE_DELETE`) — попробует в следующий раз. Файл открыт
  с `FILE_SHARE_READ|WRITE|DELETE` — его можно читать, пока игра идёт. `log::path()` — файл этого сеанса. Предел
  4 МиБ на сеанс, последняя строка говорит, что он исчерпан. Открывается только если есть папка `Scripts\`.
- **Отступления от постановки §3.4.** (1) В файл идёт не «то же, что в ленту», а всё, что слой говорит о скрипте:
  лента не показывает `tw.warn`, а §3.4 требует его в файле; и ошибки до `ready` в файл не придерживаются — ошибка
  загрузки как раз то, что будут искать. (2) Вехи повтора 10/100/1000 — не было в постановке: без них файл не
  говорит, что ошибка всё ещё идёт. (3) `flush()` с холодного пути — выше.

**Находка по §6 «`tw.log`?»** — вопрос стоял неверно. `tw.log` **уже есть** в API (с версии 1), `print` — его
псевдоним, но оба идут в `TW_LOG_INFO`, который Release вырезает: в поставке они молчат. Значит, «писать в
лог скриптов без шума в ленте» — не новая функция и не подъём `tw.api_version`, а перенаправление существующей.
Риск один: `print` в каждом кадре — это 4 МиБ за минуты, после чего настоящие ошибки в файл уже не попадут; если

### Ф4a — материал для скиллов, собранный в интервью

Справочник — `Docs/internals/playing-audiosurf.md`. Сюда — то, что идёт не в него, а в сами скиллы.

- **Имена в графе — не доказательство** (владелец, раунд 3). Добрая половина игровой логики и сущностей названа
  случайной абракадаброй или осталась от вырезанного (`FindJollyRoger`, «candy cane / sword / hook / skull»;
  `Do_TripDisplay` и прочие мёртвые ветки из `reversing-journal-gameplay.md` §11.2). В `cgrpy` и
  `audiosurf-binaries`: имя — зацепка; правда — в том, кто канал зовёт и что из него читает, и в пробе в игре.
- **Игровые имена ≠ имена веток**: «Pointman Pro» — `Do_Pointman`, «Eraser» — `Do_EraserMedium`, Mono — «Ninja».
  В `audiosurf-grill`: переводить по таблице персонажей справочника, не по созвучию.
- **Слова графа ≠ слова игрока** (сверка по графу, 18.10.2026): доска — **buffer** (`NumBufferRows`), стирание
  Eraser — **shatter** (`ShatterStorming?`), Clean Match — **Butler** (`RunButler?`), паверап на дороге — блок,
  «превращённый» в него (`Do_TurnCarIntoPainter`). AutoAdvance у Freeride — не руление, а «следующая песня сама»;
  руление — автопилот на SPACE. В `cgrpy`: искать по смыслу через таблицу справочника, а не по слову игрока.
- **Игрок помнит неточно, граф — точно**: стек Pointman 1/3/4 (помнилось 2/3/4), Double Vision Casual 4×6 и множитель
  по лигам 1.5/1.75/2.4 (помнилось 4×7 и ×1.5), Multiplier у Vegas до ×7 (помнилось ×12). В `audiosurf-grill`: числа
  от пользователя — гипотеза, которую сверяют с графом, и расхождение показывают ему, а не тихо выбирают одно.
- **Разобранный пример для `audiosurf-grill`** — «сделай, чтобы Undo у Eraser Elite не обрезало сохранённые блоки
  по свободным ячейкам, а пушило с переполнением и сразу сжигало совпадения». Расшифровка: вернуть поведение
  старых версий игры (Undo выкладывает, что влезает, → сжигает совпадения → выкладывает остаток → повторяет, пока
  память не опустеет) вместо нынешней обрезки по свободным ячейкам до выкладки. Что искать: обработчик Undo в
  `SpecialPurpose`/`Puzzle`, где считается обрезка, как вызвать проход сбора совпадений (`FindMatches`, ожидание
  `MatchCollectionTicks`) посреди выкладки. Вопросы пользователю: только Eraser Elite или и Eraser? Сжигать сразу
  или с обычным таймером? Учитывать каскад и счёт как обычные совпадения? Понимает ли он, что это меняет счёт,
  который игра отправит в таблицу лидеров? Вердикт осуществимости — после разведки, а не до неё.
- **Читерство — мягкое правило** (владелец, раунд 4). Скрипт, меняющий логику игры, меняет и счёт, который игра
  сама отправляет в таблицу, а обнаружить такой скрипт сейчас нечем. Живой онлайн мал, турниры судят по видео.
  Поэтому: моды, делающие игру **сложнее**, — без вопросов. Для явно облегчающих счёт (множитель каскада, таймер
  сгорания, генератор «только красные», правка отправляемой статистики, «всегда 99 999 999 очков») агент
  говорит, что это чит, переспрашивает, точно ли это цель, и при «да» продолжает. В `audiosurf-grill` — отдельный
  пункт допроса; в справочнике — раздел «Mods and the leaderboards».
- **Ф2: исправить `Docs/scripting.md`** («What this is not»): утверждение «nothing it does affects online
  leaderboards — the game reports its own score, not yours» верно только для скриптов, которые читают и рисуют.
  Скрипт, меняющий логику, меняет собственный счёт игры. Ссылаться на раздел справочника.
- **Незнакомый термин — переспросить.** Твёрдого сленга нет, кроме таблицы в справочнике («стакан», «райд», «чейн»).
  Запросы будут и на русском.
- **Чего хотят от модов**: визуальное (больше всего), живая статистика для опытных паззлеров (`puzzlepro_hud`),
  исправление багов и вылетов в графе самой игры. **Replay mod** просили в Discord, но сейчас он невозможен: у
  скриптов нет файловой системы. Если позже понадобится, это ещё один кандидат в недостающее API, рядом со списком
  `reversing-journal-render.md` §8.

### Ф4a — что показал первый настоящий прогон CgrPy (вход для Ф0 и Ф1)

Пометки справочника закрывались CgrPy (18.10.2026): шесть разовых запросов по образцу `examples/`, каждый — секунды.

- **`uvrun.bat` по голому имени не находится** там, где задан `NoDefaultCurrentDirectoryInExePath` (так у агентов):
  cmd не ищет программы в текущей папке, нужен `.\uvrun`. README должен это сказать; `cgrpy.cmd` в `PATH`
  редактора проблему снимает.
- **Из Git Bash `PYTHONPATH` должен быть в виде Windows** (`C:/...`, `pwd -W`), иначе `import cgr` падает: Python под
  Windows не понимает `/c/...`. Это требование к `.sh`-запускалке Ф1.
- **Каждый раз понадобились одни и те же четыре помощника**, которых в `rdy2use/` нет: поиск по regex имени по всем
  группам (с типом и значением), «кто пишет в канал» (Set Value в своей группе **и** через import-заглушки в чужих),
  дамп `ChannelSwitch` (селектор и значения веток) и родители узла. Без них каждый вопрос начинался с пятнадцати строк
  кода. Кандидат в Ф1 — готовая команда (`cgrpy query find|writers|switch|parents|dec`) и упоминание в скилле `cgrpy`.
- **`render.py callers` по индексу** работает, но имя группы надо давать полным путём (`Render/Render_IndustrialTunnel.cgr`);
  помощник выше принимает и короткое имя — так же, как `tw.*`.

## 5. Как проверяем

- **Имена API в тексте.** Каждое `tw.*` в `Tools/AgentKit/**` и `Docs/internals/**` есть в `api.json` —
  `TweakerLuaLinker.Tests` → `DocsTests` (с Ф4b).
- **Команды CgrPy в тексте.** Каждое `cgrpy <команда>` в скиллах, мануалах и README — есть `rdy2use/<команда>.py`, а
  подкоманда — в его `COMMANDS` (`DocsTests`).
- **Ссылки публичной документации** (появилось в Ф2). Каждая относительная ссылка в `Docs/**/*.md` без `Internal/` и
  `readme/` ведёт на существующий файл, каждый `#якорь` — на заголовок; правило слага — в блоке «Где мы сейчас».
  Тем же тестом — `Tools/AgentKit/**` (`DocsTests`); пути `.tweaker/docs/…` набора — `AgentKitTests`. Ссылки за
  пределы `Docs/` — только GitHub-адресами (CLAUDE.md).
- **Раскладка.** `dotnet build TweakerUI` даёт `bin\…\DevTools\{Binaries,CgrPy,Docs,AgentKit}`; в поставке нет
  `__pycache__`/`.cache`.
- **AgentSetup.** Развёртывание, повторное развёртывание, правленый файл, удалённый файл, `AGENTS.md` с
  текстом пользователя вокруг блока — юнит-тестами.
- **Логи.** Харнесс; на игре — владелец.
- **Скиллы целиком** — Ф6.

## 6. Открытые вопросы (решаются по ходу; по умолчанию — как написано)
