# Публикация компонентов в организации

Одноразовый вынос папки этого репозитория в отдельный репозиторий организации с сохранением
истории. План и контекст — [repo-layout-plan.md](../../Docs/Internal/repo-layout-plan.md) §4.1.
Скрипт не является частью приложения, AgentKit или поставки.

## Что делает

Для каждой записи [components.json](components.json):

1. `git subtree split --prefix=<папка>` — коммиты, в которых содержимое папки лежит в корне.
2. Если `main` в целевом репозитории ещё нет — создаёт репозиторий и пушит туда сплит.
3. Если `main` уже есть — **отказывается** работать: после публикации источник правды живёт
   в организации, а этот скрипт больше не перезаписывает её.

Запуск по умолчанию — `DRY_RUN=true`: сплит и отчёт, без сети, кроме `gh`-проверок.
Не трогает `Revive`, не удаляет папки из приложения и не создаёт `.gitmodules` — это следующий шаг
плана (Ф3), отдельными коммитами.

## Запуск локально

Нужны `git` с `git-subtree` (Git for Windows подходит) и `gh`, авторизованный в организации.
`python3`/`python` читает манифест; `jq` не нужен.

```bash
export GH_TOKEN="$(gh auth token)"   # не печатать токен в лог
DRY_RUN=true  bash Tools/RepoPublish/publish.sh          # отчёт
DRY_RUN=false bash Tools/RepoPublish/publish.sh          # создать и запушить
ONLY=Canvas   DRY_RUN=false bash Tools/RepoPublish/publish.sh
REUSE=true    DRY_RUN=false bash Tools/RepoPublish/publish.sh   # повторно использовать publish/*
```

Сплит начинается с коммита, который впервые затронул папку: раньше её не существовало, и обход
всей истории только тратил бы время. Перед push скрипт сверяет дерево сплита с `HEAD:<папка>`,
поэтому `REUSE=true` не может опубликовать устаревшую ветку.

Скрипт использует `git-subtree` из состава Git, поэтому на Windows запускается из Git Bash.
Если рабочая копия грязная — отказ: сплит идёт от коммита, а не от незакоммиченных файлов.

## Запуск в Actions

Workflow — `.github/workflows/publish-components.yml`, только `workflow_dispatch`, среда
`publish-components` (обязательный ревьюер). Нужен секрет `ORG_PUBLISH_TOKEN`: classic PAT со
scope `repo` и `workflow`, авторизованный в организации при включённом SSO. Пока секрет
и среда не настроены, локальный запуск — основной путь.

## Ограничения

- Harness этим скриптом не выносится: он не в git, а временный коммит в публичный монолит
  навсегда опубликовал бы приватный код в истории. Harness создаётся локально.
- Повторный запуск после перестройки приложения ожидаемо упадёт на проверке «папка уже
  сабмодуль» — это и есть защита от второго сплита.
