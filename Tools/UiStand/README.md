# UiStand — headless-стенд для TweakerUI

Запускает **настоящие** стили и вьюшки из собранной `TweakerUI.dll` в Avalonia.Headless со Skia (реальная
отрисовка текста, не заглушки) и проверяет то, что иначе проверяется только глазами у владельца. Им проверены
баги 2–8 из `Temp/KnownBugs.md`; механизмы, которые он помог найти, — в `Docs/Internal/avalonia-pitfalls.md`.

Не входит в `.sln`: зависит от **выхода** сборки `TweakerUI`, а не от проекта (подключать проект `WinExe`
ссылкой — значит тащить нативные pre-build хуки в каждую сборку стенда).

```
dotnet build TweakerUI/TweakerUI.csproj           # сначала — стенд читает её bin/x64/Debug
dotnet build Tools/UiStand/UiStand.csproj
Tools/UiStand/bin/x64/Debug/net10.0-windows10.0.19041.0/UiStand.exe <режим>
```

Запускать **`UiStand.exe`, а не `dotnet UiStand.dll`**: вьюмодели пишут свои файлы рядом с
`Environment.ProcessPath` (`TweakerUI/Core/AppPaths.cs`), а под `dotnet …dll` это `dotnet.exe`.

## Режимы

| режим | что делает |
|---|---|
| `shoot <dir>` | PNG-снимки: пять вкладок (с пустым `DataContext` — вёрстка и стили, не данные) и галерея общих блоков (`Card*`, `Switch`, `ToggleRow`, `IconButton*`, списки) во всех состояниях, обе темы |
| `compare <dirA> <dirB>` | попиксельное сравнение двух наборов снимков: сколько пикселей и насколько отличаются |
| `diffmap <a.png> <b.png> <out.png>` | копия `b` с отличающимися пикселями красным + рамка изменения |
| `transitions` | все анимируемые смены цвета всех интерактивных классов, обе темы: насколько **видимый** кадр уходит от прямого перехода — для встроенного `BrushTransition` и для `CrossfadeBrushTransition` |
| `colors <dir>` | вкладка Colors Configurator с **настоящей** вьюмоделью при ширине модуля минимального (1000 px) и 1920-пиксельного окна |
| `mem [fast] [rounds=N] [cycles=N]` | память Skin Changer с **настоящей** `SkinChangerViewModel` и её вьюшкой: после загрузки списка, после каждого выбора скина (`rounds` проходов по списку), после каждого вкл/выкл Fast Previews на лету (`cycles`); `fast` — режим включён с запуска. Каждая точка — до и после полной сборки мусора: разница между ними — чей-то забытый `Dispose`. Плюс проверки владения картинками (быстрое A→B→A, открытое окно увеличения) и кадр после каждого шага — ловит освобождённый `Bitmap`, который ещё на экране (`avalonia-pitfalls.md` §6). `UISTAND_PAUSE=<часть метки>` останавливает на этой точке на 40 с — снять дамп `dotnet-gcdump collect -p <pid>` |
| `tabs` | переключение вкладок так, как это делает `MainWindow` (`ContentControl` + `ViewLocator` — новая вьюшка на каждое переключение), 20 кругов: сколько вьюшек живо после сборки мусора |

Для `mem` нужны скины в `Skins\` рядом с `UiStand.exe` (`bin\` — вне git, туда же вьюмодель положит свои
файлы): скопировать папку `Skins\` из рабочей установки. Цифры headless — без окна и GPU; в приложении
всё выше примерно на ту же величину, что и базовая память пустого окна.

Рабочий порядок для правки стилей/разметки: `shoot` до → правка → сборка `TweakerUI` → `shoot` после →
`compare`; каждое отличие должно быть объяснено (`diffmap` показывает где).

## Что узнали о headless-режиме (не повторять)

- **Часы анимаций в headless ненадёжны**: переход может навсегда застрять на первом кадре (свойство
  контрола уже новое, у части шаблона — старое), причём не у всех контролов. Подменить часы нельзя —
  `IClock`/`ClockBase` в Avalonia 12 внутренние. Поэтому: снимки делаются с **снятыми** `Transitions`
  (конечное значение сразу), а сами переходы считаются математикой по **базовым** значениям кистей
  (`GetBaseValue` — без анимационного слоя) через `InterpolatingTransitionBase.Interpolate` / внутренний
  `ColorAnimator.InterpolateCore` (отражением).
- **Время в headless не идёт само**: два `MouseDown` подряд в одной точке считаются двойным/тройным
  кликом. Отдельное окно на каждый случай.
- `UseHeadlessDrawing = false` + `UseSkia()` обязательны, иначе метрики текста фиктивные и замеры
  раскладки врут.
- `CaptureRenderedFrame()` детерминирован: два прогона `shoot` подряд совпадают до пикселя.
- Вьюшки без вьюмодели: команды с неразрешённой привязкой делают кнопку **неактивной** — на снимках
  такие кнопки в состоянии `disabled`.
- Стенд повторяет `App.axaml` вручную (`class App` в `Program.cs`) — при изменении порядка или состава
  словарей/стилей в `App.axaml` поправить и здесь.
