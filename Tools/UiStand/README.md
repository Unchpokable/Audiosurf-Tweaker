# UiStand — headless-стенд для TweakerUI

Запускает **настоящие** стили и вьюшки из собранной `TweakerUI.dll` в Avalonia.Headless со Skia (реальная
отрисовка текста, не заглушки) и проверяет то, что иначе проверяется только глазами у владельца. Им проверены
баги 2–8 из `Temp/KnownBugs.md`; механизмы, которые он помог найти, — в `Docs/Internal/avalonia-pitfalls.md`.

Не входит в `.sln`: зависит от **выхода** сборки `TweakerUI`, а не от проекта (подключать проект `WinExe`
ссылкой — значит тащить нативные pre-build хуки в каждую сборку стенда).

```
dotnet build TweakerUI/TweakerUI.csproj           # сначала — стенд читает её bin/x64/Debug
dotnet build Tools/UiStand/UiStand.csproj
Tools/UiStand/bin/x64/Debug/net10.0-windows10.0.19041.0/UiStand.exe <режим>
```

Запускать **`UiStand.exe`, а не `dotnet UiStand.dll`**: вьюмодели пишут свои файлы рядом с
`Environment.ProcessPath` (`TweakerUI/Core/AppPaths.cs`), а под `dotnet …dll` это `dotnet.exe`.

## Режимы

| режим | что делает |
|---|---|
| `shoot <dir>` | PNG-снимки: семь вкладок (с пустым `DataContext` — вёрстка и стили, не данные) и галерея общих блоков (`Card*`, `Switch`, `ToggleRow`, `IconButton*`, списки) во всех состояниях, обе темы |
| `compare <dirA> <dirB>` | попиксельное сравнение двух наборов снимков: сколько пикселей и насколько отличаются |
| `diffmap <a.png> <b.png> <out.png>` | копия `b` с отличающимися пикселями красным + рамка изменения |
| `transitions` | все анимируемые смены цвета всех интерактивных классов, обе темы: насколько **видимый** кадр уходит от прямого перехода — для встроенного `BrushTransition` и для `CrossfadeBrushTransition` |
| `colors <dir>` | вкладка Colors Configurator с **настоящей** вьюмоделью при ширине модуля минимального (1000 px) и 1920-пиксельного окна |
| `mem [fast] [rounds=N] [cycles=N]` | память Skin Changer с **настоящей** `SkinChangerViewModel` и её вьюшкой: после загрузки списка, после каждого выбора скина (`rounds` проходов по списку), после каждого вкл/выкл Fast Previews на лету (`cycles`); `fast` — режим включён с запуска. Каждая точка — до и после полной сборки мусора: разница между ними — чей-то забытый `Dispose`. Плюс проверки владения картинками (быстрое A→B→A, открытое окно увеличения) и кадр после каждого шага — ловит освобождённый `Bitmap`, который ещё на экране (`avalonia-pitfalls.md` §6). `UISTAND_PAUSE=<часть метки>` останавливает на этой точке на 40 с — снять дамп `dotnet-gcdump collect -p <pid>` |
| `scripts <dir>` | вкладка Scripts с **настоящей** `ScriptsViewModel` над поддельной папкой игры (все виды строк: поставляемый, изменённый, свой, сборка проекта с картой и без, «не установлен», с `.old`-копиями; выключенный в `scripts.cfg`), обе темы, обе ширины, плюс состояния «игра запущена», «плагин не установлен», «папка игры неизвестна». Затем переключатель: выключение и включение должны править `scripts.cfg`, не трогая `engine.*`. Если на машине **на самом деле** запущена Audiosurf, проверяется отказ вместо записи. Поставка — `PluginPayload\` рядом с `UiStand.exe`, создаётся на прогон и удаляется. **С5b:** игра «подключена» — поддельный плагин за `ScriptsOverlayBridge.UseTransport` записывает каждую строку, ответы подаются `Receive`: полный список со статусами (упал, приостановлен, «игра не видела файл»), переключатель шлёт `SCRIPT_SET` и ждёт, `scripts.cfg` хост не трогает, ответ плагина закрывает ожидание, `false failed` возвращает переключатель с ошибкой, без ответа — откат и уведомление по таймауту, второй клик перезапускает ожидание (мутационно проверено), Refresh шлёт `SCRIPT_RESCAN`, потеря связи забывает слова игры и запирает переключатели; снимки `*-scripts-live` в обеих темах. **П2 (порядок, `script-coexistence.md` §3):** без игры строки идут по `order=` из `scripts.cfg` (без них — по имени, «не установленный» внизу без места), `MoveScript` переставляет строку и пишет в `scripts.cfg` весь порядок строками `order=`, не трогая остального; новая вьюмодель читает тот же порядок. С «подключённой» игрой строки идут в порядке `SCRIPT_ORDER` плагина, перетаскивание шлёт порядок плагина целиком со сдвинутым файлом (имя без строки остаётся на месте), строки сразу в новом порядке, ответ закрывает ожидание, без ответа — возврат и `OrderTimedOut`, порядок из оверлея двигает строки, потеря связи возвращает порядок `scripts.cfg` и запирает ручки (мутационно проверено: порядок из строк вместо порядка плагина, ответ, не снимающий ожидание). Само перетаскивание мышью (`DoDragDropAsync`) headless не гоняется |
| `scriptdev <dir>` | вкладка Script Dev с **настоящей** `ScriptDevViewModel` и **настоящим** `twllink` (копируется из `TweakerUI\bin\...\DevTools\Binaries\` в `DevTools\` рядом с `UiStand.exe`, на прогон): неверное имя, создание из шаблонов, сборка, сборка с ошибкой (место в диагностике), установка в поддельную игру, пропавший и сломанный проекты; пересборка по сохранению — одна на изменение, собственный вывод `twllink` не в счёт. Если установлен Neovim — окружение редактора: ровно `StartInfo` кнопки «Open in Neovim», запущенный `--headless`, должен найти `twllink` в `DevTools\Binaries` (`exepath`, `:!twllink --version`) и видеть `AUDIOSURF_DIR`; `SHELL` снимается, как у TweakerUI из Проводника. Снимки каждого состояния, обе темы; в карточке Editor — редакторы, **реально** установленные на машине. **С5b:** установка в «подключённую» игру (поддельный транспорт `ScriptsOverlayBridge`) шлёт ровно `SCRIPT_RELOAD <файл>` и пишет «Built, installed and reloaded»; сборка без установки не шлёт ничего |
| `readme <dir>` | скриншоты для публичного `README.md` (кладутся в `Docs/readme/`): **настоящий** `MainWindow` с **настоящими** вьюмоделями всех семи вкладок, обе темы, 1200×720. Сцена поставлена: поддельная папка игры, в которую плагин **установлен** `PluginInstallation.Install` из настоящего `PluginPayload\` сборки `TweakerUI`; скины из `Skins\` рядом с `UiStand.exe` (без них режим отказывается); демо-плейлисты из выдуманных треков со сгенерированными обложками — аудио это килобайтные MP3 с Xing-заголовком и FLAC с одним STREAMINFO, чтобы TagLib показал длительность и формат; пять палитр; настоящий проект `puzzlepro_hud`, собранный настоящим `twllink`, и проект из шаблона, установленный в игру; игра «подключена» (статусы скриптов через поддельный транспорт `ScriptsOverlayBridge`, `OverlayHelper` в `Connected`). `MainWindowViewModel` собирается **без конструктора**, а обработчик `Opened` окна снят: оба трогают настоящую игру (поиск установки, синхронизация плагина). Временные пути и имя учётной записи в тексте заменяются нейтральными перед снимком. `QuickPlayer\` и `palettes.pltc` рядом с exe отодвигаются на прогон и возвращаются |
| `tabs` | переключение вкладок так, как это делает `MainWindow` (`ContentControl` + `ViewLocator` — новая вьюшка на каждое переключение), 20 кругов: сколько вьюшек живо после сборки мусора |

Для `mem` нужны скины в `Skins\` рядом с `UiStand.exe` (`bin\` — вне git, туда же вьюмодель положит свои
файлы): скопировать папку `Skins\` из рабочей установки. Цифры headless — без окна и GPU; в приложении
всё выше примерно на ту же величину, что и базовая память пустого окна.

Рабочий порядок для правки стилей/разметки: `shoot` до → правка → сборка `TweakerUI` → `shoot` после →
`compare`; каждое отличие должно быть объяснено (`diffmap` показывает где).

## Что узнали о headless-режиме (не повторять)

- **Часы анимаций в headless ненадёжны**: переход может навсегда застрять на первом кадре (свойство
  контрола уже новое, у части шаблона — старое), причём не у всех контролов. Подменить часы нельзя —
  `IClock`/`ClockBase` в Avalonia 12 внутренние. Поэтому: снимки делаются с **снятыми** `Transitions`
  (конечное значение сразу), а сами переходы считаются математикой по **базовым** значениям кистей
  (`GetBaseValue` — без анимационного слоя) через `InterpolatingTransitionBase.Interpolate` / внутренний
  `ColorAnimator.InterpolateCore` (отражением).
- **Время в headless не идёт само**: два `MouseDown` подряд в одной точке считаются двойным/тройным
  кликом. Отдельное окно на каждый случай.
- `UseHeadlessDrawing = false` + `UseSkia()` обязательны, иначе метрики текста фиктивные и замеры
  раскладки врут.
- `CaptureRenderedFrame()` детерминирован: два прогона `shoot` подряд совпадают до пикселя.
- Вьюшки без вьюмодели: команды с неразрешённой привязкой делают кнопку **неактивной** — на снимках
  такие кнопки в состоянии `disabled`.
- Стенд повторяет `App.axaml` вручную (`class App` в `Program.cs`) — при изменении порядка или состава
  словарей/стилей в `App.axaml` поправить и здесь.
- **`DispatcherTimer` в headless не срабатывает**: ему нужны часы платформы, а `RunJobs()` их не двигает.
  Отложенное действие во вьюмодели, которое стенд должен проверить, — через `Task.Delay` и
  `Dispatcher.UIThread.Post` (так сделана пересборка по сохранению в `ScriptDevViewModel`), а не таймером.
- **Стенд берёт `TweakerUI.dll` из своей папки** (копия при сборке стенда). После правки TweakerUI
  пересобрать **и** стенд, иначе проверяется старый код — так однажды «не поймалась» мутация.
