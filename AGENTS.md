# Работа с Audiosurf Tweaker

Эти правила действуют для всего репозитория. Руководства агентов находятся в
`Docs/AgentWorkflow/`; начни с [карты документации](Docs/AgentWorkflow/README.md).
Читай материалы по теме задачи, а не весь архив проекта.

## Проект

Три исполняемые части: внешний .NET/AvaloniaUI клиент **TweakerUI**, 32-битный
IPC-мост **asbridge** и внутриигровой x86-модуль **TweakerPlugin**. Плагин управляет
игрой, содержит LuaJIT и работает без хоста; он не тонкий клиент.
Архитектура и границы слоёв — [architecture.md](Docs/AgentWorkflow/architecture.md).

## Подход к изменениям

- Изучи место внедрения, зависимости и похожие реализации. Встраивай фичу в
  существующую систему. Перестройка допустима как цель задачи либо после
  выявления накопленных частных переделок; её необходимость согласуй.
- До правок, включая точечные, исследуй последствия, предложи план и вопросы,
  получи ответы владельца. Уже согласованные действия повторно не согласовывай.
  Реализуй небольшими проверяемыми шагами; расширение объёма сначала обсуди.
- Предпочитай общее решение частному исключению. Условие «для X иначе» требует
  обоснования; исключение или рефакторинг выноси на обсуждение до реализации.
- Не копируй похожую логику между модулями: ищи общий механизм. Сохраняй
  намеренную изоляцию, например отдельных Lua-движков скриптов игры и генерации
  геометрии Skybox Replacer; сходство само по себе не требует объединения.
- Избегай оверинжинирга

## Работа и Git

- Сначала проверь `git status`, текущую ветку и относящийся к задаче план. Чужие
  изменения сохраняй; не откатывай и не добавляй их в свой коммит. Если изменения
  пересеклись в одном файле, согласуй разделение с владельцем.
- Базовая ветка — **Revive**. Новая фича всегда начинается в отдельной ветке от
  неё. Работы, уже начатые в Revive, продолжаются там. Старые ветки не трогай.
- Агент коммитит **после подтверждения владельцем, что фича реализована и
  работает, и после его Code Review**. Не делай автокоммиты по ходу реализации.
  Git CLI — основной инструмент, GitHub CLI (`gh`) — по необходимости.
- В индекс добавляй свои файлы поимённо. Один коммит — одно осмысленное изменение;
  генерация и описывающие изменение документы идут вместе с исходником.
  Механический шум отделяй. Сообщения — на английском, imperative, заголовок до
  примерно 72 символов, без Conventional Commits и ссылок на внутренние фазы.
- Push, релизы и переписывание опубликованной истории — только по команде
  владельца. Не выводи разрешение на amend/rebase чужих коммитов из старой памяти.
- Работай в пределах текущего поручения. При фазовой работе выполни проверки,
  сообщи, что проверить в игре, и запиши результат владельца в документ этой
  работы. Следующая фаза, ожидающая его команды, сама не начинается.
- Личный `Temp/KnownBugs.md` не является планом агента; не веди его автоматически.
  Решения и процесс — [agent-workflow.md](Docs/AgentWorkflow/agent-workflow.md).

## Данные и совместимость

- `Audiosurf_Steam/` — исследовательская копия игры. **Существующие базы IDA
  содержат результаты исследований: сохраняй их и аннотации, не пересоздавай
  базы как якобы пустые или мусорные.**
- В Steam-установку можно устанавливать новые скрипты/скайбоксы, которых там ещё
  нет, либо материалы по явному разрешению или прямой просьбе владельца.
  Сначала проверь существование назначения. Перезапись существующего требует
  такого разрешения. Развёртывание DLL плагина остаётся за владельцем.
- **LegacyDataConverter обязателен.** Изменения формата скинов должны сохранять
  перенос из legacy-формата, который он читает. Скрипты и скайбоксы не выпущены:
  их breaking changes не требуют обратной совместимости.
- Правь исходный Lua-проект, а не собранный `.lua`. После изменения пересобери
  bundle и `.lua.map`; изменения публичного `tw.*` требуют синхронного обновления
  API-описания, справочника, LuaLS definitions и twllink.
  Порядок — [development.md](Docs/AgentWorkflow/development.md).

## Субмодули

`ScriptProjects/`, `Skyboxes/` и `TweakerPlugin/harness/` — сабмодули организации
[Audiosurf-Tweaker](https://github.com/Audiosurf-Tweaker); план и решения —
[repo-layout-plan](Docs/Internal/repo-layout-plan.md).

- Правка начинается в репозитории компонента: ветка, коммит, push — и только потом
  указатель сабмодуля в приложении бампается **тем же PR**. Указатель фиксирует
  проверенную версию, а не «последний main».
- `ScriptProjects/puzzlepro_hud` и `Skyboxes/Canvas.sky` — вложенные сабмодули:
  после клона `git submodule update --init --recursive`.
- После изменения проекта скрипта пересобери бандл в `TweakerPlugin/assets/scripts/`
  (`ShippedProjectsTests` проверяет совпадение).
- `dev/` в контентных репозиториях не коммитится. Пробы живут в приватном harness
  (`scripts/dev/`, `projects/dev/`); в `TweakerPlugin/assets/scripts/dev/` их больше нет.
- Harness — приватный сабмодуль с `update = none`: у внешнего клона он пропускается.
  Не делай его публичным и не инициализируй принудительно у чужих клонов.

## Реализация и проверки

- Полный билд — `Scripts/Deploy.ps1` / `Scripts/Deploy.sh`, отладочная поставка —
  парные `DeployDebug`. Они пересоздают `distr`; проверь, что там нет нужных
  локальных материалов. Для локальной managed-проверки:
  `dotnet build TweakerUI/TweakerUI.csproj`;
  `dotnet run --project TweakerUI/TweakerUI.csproj` запускает приложение и нужен
  только когда запуск входит в проверку. Всю `.sln` не считай dotnet-only целью.
- Правишь deploy-скрипт — правь парный `.ps1`/`.sh`. Состав поставки задают
  `CopyTweakerPlugin` и `CopyDevTools`, а не ручное копирование набора файлов.
- Перед правками кода прочитай [стиль и организацию](Docs/AgentWorkflow/code-style.md).
  C++ — **C++23**, `.hxx`/`.cxx`, CRLF; layout — `.clang-format`, naming —
  `.clang-tidy`. Vendored-зависимости не меняй; runtime-правила — в `development.md`.
- В TweakerPlugin **не создавай покадровую тяжёлую системную или I/O-нагрузку**.
  Файлы и тяжёлые задачи, включая компиляцию шейдеров, — `plugin::bg_work` с
  покадровой проверкой готовности без блокирующего ожидания. Игровой WndProc/IPC
  синхронен: `EngineLoop` сначала делает `pump()` сообщений, потом считает граф.
  Обработчик сообщения не считай независимым фоновым IPC-потоком.
- Под loader lock не жди, не вызывай оконные функции и не приостанавливай потоки.
  Предпочитай перехваты каналов Quest3D общим D3D/Win32-хукам, когда задача
  решается каналом. Исключения/RTTI в горячем пути запрещены.
- Для UI проверяй снимки до/после и просматривай изменённые области. Запускай
  относящиеся к изменению тесты; skipped, недоступный harness и ручная проверка
  игры не означают passed. Игра проверяется владельцем.
- Native harness живёт в **приватном** сабмодуле `TweakerPlugin/harness` по плану
  владельца; подключение и адреса сабмодулей меняет владелец. GitHub workflow
  устарел и не задаёт норму проверки.
